## 1. 专项目标

用户打开页面，应能直接判断：现在在做什么、能做哪些事、主要操作是什么、操作后会得到什么，以及怎样回到原任务。

逐项审查每个标题、数字、标签、卡片、面板、提示、按钮、导航与默认展开内容。每项可见内容必须支持具体的用户操作、判断、定位或必要纠错；无法说明用途的内容默认删除。说明设计理由的材料保存在设计文档，不把这些理由写回产品 UI。

删减不能只靠缩字、折叠全部内容或移走按钮。需要同时简化导航层级、重复容器和任务切换，保留关键功能的可发现性。界面不承担展示工程工作量、架构完整性或功能数量的任务。

## 2. 范围、所有权与完成边界

| 本专项负责 | 直接产物 | 相关业务模块负责 |
|---|---|---|
| 信息取舍与默认显隐 | 元素清单、保留理由、删除/合并/延后决定 | 数据事实及访问权限真实有效 |
| 信息架构与功能边界 | 页面任务、导航、归属、跨页入口与返回规则 | 跳转引用、对象身份和版本连续 |
| UI 布局与视觉 | 页面/组件方案、字号/间距/颜色/状态和响应布局 | 原有命令、合法动作和查询语义 |
| 文字呈现 | 按钮、标题、术语、空/错/等待/完成状态文案 | 失败原因、完成条件、评分资格 |
| 前端落地与体验验收 | 组件/样式/文案变更、前后对照和关键旅程 | Solver、规则、持久化、部署独立验收 |

当前批次只准备任务，不修改应用。后续 UI 落地尽量复用现有服务与合同；若必须增加字段/投影，登记最小消费者需求，交由对应业务任务实现，不在 UI 中虚构数据或重算业务结论。状态文字不能改变取消、保存、评分或暴露的语义。

## 3. 信息取舍规则

| 决定 | 使用条件 | 示例 |
|---|---|---|
| 默认保留 | 当前操作/判断直接需要，或决定能否继续 | 轮到谁、待跟注金额、选中节点、当前结果是否过期 |
| 合并 | 多处内容回答同一个问题 | 页面名与大号工作台标题、重复牌面、上下同时出现的状态 |
| 按需出现 | 仅在选择对象、失败、修改或比较时有用 | 组合明细、保存冲突、两版差异、模型不匹配的补救 |
| 进入详情 | 有复现/审计价值，但不影响眼前操作 | 引擎提交、哈希、协议名、完整诊断、历史执行配置 |
| 删除 | 装饰性、重复、空泛、自我介绍或与当前任务无关 | “专业研究工作台”、重复“当前任务”卡、无后续操作的功能口号 |

只有影响信任与决策的事实才保持当前上下文可见：例如示例数据身份、不可评分、输入已变更、实际失败、即将揭示答案、不可逆操作。用最短准确表述，避免每个控件重复同一警告。完整来源留在可找到的详情中；不能为了清爽把必要限制只藏在帮助中心。

默认不用“新增一个说明卡/再加一个标签”解决不清楚。先检查名称、归属、空间位置、主次和操作反馈。Tooltip 补充术语，不能承载找到主要功能所必需的信息。

## 4. 可见内容审计合同

UI01 对每个首要页面及其核心状态建立清单。重复标准组件可以审计其模板与例外，不机械登记每个相同单元格。每项记录：

| 字段 | 要回答的问题 |
|---|---|
| 页面 / 模式 / 状态 / 元素 | 用户在什么情境看到它？ |
| 用户问题 | 它帮助用户判断或完成哪件具体事情？ |
| 显示时机 | 为什么现在显示？什么条件下可以不显示？ |
| 操作或判断后果 | 读完/点击后会发生什么？纯信息如何影响判断？ |
| 归属与重复 | 应属于哪个功能？已有哪里表达了同样信息？ |
| 处理决定 | 保留、合并、按需、详情或删除，并写理由 |
| 落点与验证 | 新位置/文案、对应任务和验证方式 |

保留理由不能仅写“完整”“专业”“后端有字段”“以后可能有用”或“让页面丰富”。审计表是开发材料，不进入用户页面。

初始审查候选如下，依据已读源码/历史截图与上轮草图，不代表已完成全产品盘点：

| 候选 | 预期处理与理由 |
|---|---|
| 导航、页标题、面板中反复说“研究/分析工作台” | 合并为足以定位的一个标题，主区让给任务 |
| 同一牌面/位置在上下文条、牌桌和旁栏重复 | 同一可视范围内保留必要一处；滚动/独立浮层等例外另验 |
| 持续可见的“第几手→决策→研究版本→训练”说明 | 改为有作用的面包屑/返回入口，非交互路径说明删除 |
| “参考策略暂不显示”与“提交后显示”等重复卡片 | 题干/提交动作表达一次，隐藏区不占位；提示入口仍可找到 |
| 字段前的内部对象名、合同比例、hash 与 jobId | 常态移入详情或故障诊断；不影响用户定位的技术内容不常驻 |
| 研究页长段功能介绍、模型边界与教程混排 | 保留当前影响判断的条件，其余按需帮助/详情 |
| 视图已有明确选中态，又单列“模式：研究” | 删除冗余；若模式影响答案可见/作答身份，用必要状态直接表达 |
| 无待办时仍展开的质量、警告、任务卡 | 空态不占长期面板；真异常在关联操作附近出现 |
| 与选中对象无关的旁栏 | 选择后显示相应详情；无详情不以默认说明填满 |

## 5. 模块与功能边界

先按用户任务确定入口，再决定 UI 模块。不能直接把后台服务、每类制品或每个已有页面映射成一级菜单。

| 用户活动 | 应负责什么 | 向下一活动交接什么 |
|---|---|---|
| 连续练习 | 完整一手的连续行动、疑问记录、合法终局和手后反馈 | 整手记录、各节点原始选择与具体问题 |
| 专项训练 | 优先设定整手条件与目标，连续作答/复测；单点题另行标明 | 整手/节点作答、提示时序、题目来源和待研究问题 |
| 复盘 | 找到值得研究的具体决策，回到当时信息 | 所选决策与已确认事实 |
| 研究 | 深入整条行动线与逐街、双方范围/组合、树/混频、实验和后续牌比较 | 固定基准/变体/结论与条件，生成整手训练或明确专项题 |

“连续练习”和“专项训练”是否合并在一级“练习”下，在 UI02 中优先验证。它们共享作答/行动组件，但会话目标、抽样和反馈时机明确。上轮草图的四个平级页签是讨论方案，不是固定产品架构；本次不为沿用页签而保留重复入口。

研究不永久重复显示复盘历史和训练面板，训练不默认展示研究配置。知识解释与 Agent 在需要的上下文提供，避免变成并列工具墙。跨模块入口用“研究此决策”“练习这个局面”“返回原手牌”等结果明确的动作，交接上下文只在需要确认时简要显示。

功能拥有一个主要归属。其他位置允许带上下文的快捷入口，不能生成另一份独立数据、另一套保存行为或不同叫法。进入、离开、恢复当前任务的规则必须可解释，并保护未保存内容。

## 6. UI 与文案要求

先用任务顺序和布局表达关系，再补必要文字。首屏明确一个当前主任务；主操作在主任务附近，关联控制聚在一起。专业研究可以保持高信息密度，每项密度都要服务当前分析，不以全页面统一减字作为目标。

文案采用用户动作和结果：按钮说明做什么，必要时带对象和金额；名称稳定，单位靠近数值；卡牌、尺寸、范围权重与行动频率不混称。状态只说明当前事实、影响和下一步，避免“温馨提示”、自夸、空泛引导和重复“当前/已验证/真实”。

以下仅为改写方向，具体文案要随真实状态核对：

| 原表达/表达类型 | 改写方向 |
|---|---|
| “配置并保存范围，固定规格后运行真实分析……” | 表单命名清楚，主要按钮“开始计算”；未保存时就地说明实际前置条件 |
| “真实作业已保存：运行中。刷新页面不会取消计算。” | 常态“计算中”＋取消；离开页面相关时再说明计算继续 |
| “执行完成 · 已覆盖当前受限模型……” | 有可读结果即呈现结果；不足以评分时保留具体限制与原因 |
| “INVALID / unsupported / artifact_miss…” | 给出具体用户原因及能做的操作；错误码进入可复制诊断 |
| “查看完整分析 / 继续 / 确认” | 根据上下文改为“研究此决策 / 提交答案 / 保存范围”等明确结果 |
| “保存成功”弹条与常驻已保存重复 | 根据编辑风险保留一个准确保存反馈，失败/冲突必须可见 |

Typography、间距、对比度、卡牌、矩阵、表单和错误视觉仍按体验规格实施。业务主信息不能靠小字/低对比隐藏。不要用大面积空白、装饰卡、反复徽章、全大写英文把删掉的说明重新填回。

| 编号 | 工作 | 交付与出口 |
|---|---|---|
| UI01 页面/状态盘点与删减 | 练习、复盘、研究、专项训练及跨页旅程；记录实际可达与概念状态 | 元素审计表、原始截图/来源、删减清单；每项保留有用途，未审页面明确列出 |
| UI02 信息架构与功能归属 | 一级导航、页面边界、整手流程/手后反馈、深度研究入口、进入/返回/保存 | 任务地图、入口归属表、关键路径线框；练习/训练层级作出有依据的决定 |
| UI03 UI 布局与视觉体系 | 整手连续行动、逐街/树/双方范围/组合/实验视图，首屏/详情/响应/焦点 | 可交互方案、组件状态/布局规范、前后对照；专业深度可找到，不以说明填空 |
| UI04 文字与状态专项编辑 | 术语、标题/按钮、空/错/等待/保存/结果/未覆盖 | 上下文文案表、统一命名、技术词去向；每句话有用途且状态准确 |
| UI05 分旅程落地 | 用现有真实合同替换页面 UI/文案，逐条闭环 | 先现有研究/作答可达路径，再接新增牌局；保护原功能、固定引用与答案权限 |
| UI06 独立体验验收 | 信息理解、找功能、切换返回、异常恢复、读写/键盘/窄屏 | 真实截图/旅程、审计回查、未解决项；与数值/部署验收分别报告 |

顺序 UI01→UI02→UI03/UI04→UI05→UI06，UI03/UI04 在同一方案内迭代，不意味着安排代理并行。可先在一个完整旅程中落实，再推广到其他页面。新模块未有可达实现时先验证概念方案，不能据草图通过宣布真实旅程完成。

本专项拥有独立变更范围、交付报告和验收结论，不夹在 Solver 功能中按“顺便调整样式”完成。UI01–04 可立即开展而无需等待 U00；UI05 逐页依据实际合同接入，U 系列新增功能必须消费本专项的页面/文案规则，不另造一套导航和视觉。

## 8. 验收标准

1. 每项默认可见内容有合格审计理由；无法解释的重复信息已删除或合并，详情内容有合理可发现入口。
2. 用户能说清所在任务、主要操作和预计结果；关键操作不能依赖读长说明或 hover 后才发现。沿用 5 秒定位/30 秒跨页的候选可用性目标，记录实测、样本和困难，不伪造通过。
3. 用户能区分连续练习、专项训练、复盘、研究，跨活动保留同一决策上下文；切换后能返回原任务。
4. 标题、按钮和术语一致；金额、范围/策略、版本、可评分与否语义准确。源码术语、哈希、协议和调试字段不侵占常态主界面。
5. 必要风险和边界在影响决策时可见，示例不伪装真解；取消/保存/质量/旧结果不因简化而误导；答案/未来隔离保持业务合同。
6. 删除前后以相同旅程和状态对照，核心功能可达且无隐藏退化。审计信息量变化，但不设无依据的“删掉百分之多少”为完成标准。
7. 实际验证桌面/窄屏、键盘、焦点、文本缩放、动态效果和对比度；截图无溢出只是其中一项，不等于整体 UI 达标。
8. 设计审查、设计者自测、真实应用测试与用户观察分别记录。文案/样式改动跑对应回归，涉及合同和权限再补直接测试，不无差别重复 Solver 基准。
9. 完成一手再反馈、暂停恢复、弃牌/全下合法结束、手后定位节点并研究后返回均可操作；单点草图或单次动作不能代替整手验收。
10. 深度研究任务可以定位逐街路径/双方范围/具体组合、配置尺寸/混频、建立对照并保存结论；未开放能力如实说明，已开放能力不因界面精简而被删掉或藏到找不到。

本批仅新增/链接任务包并更新设计入口；没有改应用、没有更新上一版交互草图、没有声称 UI01–UI06 已完成。
