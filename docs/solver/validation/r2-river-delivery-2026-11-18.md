# R2 受限河牌真实闭环交付

日期：2026-11-18。承接 R1 提交 `0d91513`，工作分支 `codex/solver-real-r1-20261118`。本批完成受限模型中的 R2-A 应用合同、R2-B 产品接入和 R2-C 作业/恢复通路；一般河牌树与其他街道不因此完成。

## 1. 可以实际使用什么

```powershell
npm ci
npm run solver:build
npm run dev
```

打开 `http://127.0.0.1:5173/solver/real`，或从主导航「真实 HU 河牌」进入。更换运行时代码后需要重新启动业务服务，单独刷新浏览器不会加载新的 Node 代码。原 `/solver` 保留 S1 示例闭环，扑克数值仍标记合成，不能把它的六人/实验/教学页面算作真实引擎能力。

真实路线：配置公共牌、根底池/有效后手及双方组合权重→保存局面/范围版本→固定规格并原生预检→真实排队计算→打开固定解→Hero、169 手牌类与具体组合、行动路径→保存指定行动的派生范围→刷新或导出/恢复。

另一个入口可以用实际 MCP 工具查询和修订同一作品；界面轮询同一状态接手。并发变更返回版本冲突，保留本地草稿；恢复后若所选局面或解已不在当前索引，清除旧结果显示并保留输入草稿。输入变化后继续打开旧解时显示固定旧输入警告。

## 2. 支持矩阵

| 能力 | 真实状态 | 限制 |
|---|---|---|
| HU 翻前 | 不支持 | 未执行 R3-A |
| HU 翻后 | **受限河牌已接入并验证** | OOP check/一个显式下注；check 后 IP check，面对下注 IP fold/call；无 raise、抽水、bunching |
| 六人翻前 | 不支持 | 未执行 R3-B；示例数据不是计算范围 |
| 六人背景的单挑翻后 | 不支持真实交接 | 本批只有明确 HU 桌/两名活跃与求解玩家；未把示例六人来源包装为真实链路 |
| 多人翻后 | 不支持 | 未执行 R3-C |
| 一般河牌树、转牌、翻牌 | 尚未接入/独立验证 | 补充一般河牌树基准，再推进 R2-D/E |
| 固定用户策略评价、BR/锁定实验、比较 | 尚未产品接入 | R2-F；R1 锁定 API 测试不等于实验能力完成 |
| 真实证据教学反馈/新题生成 | 尚未打通完整旅程 | 本批统一信息暴露保护；消费与评价语义留待 R2-F/G |
| 花色同构预解库 | 未实现 | R2-I；未用近邻输入或最近结果代替计算 |

运行限制：每方最多 200 个正权重组合；输入组合仍可按完整 1,326 格编辑和查询。一次一个计算，未终结作业最多四个（含运行中）；最多 100,000 次迭代、120 秒内核时间预算，父进程另有启动/收尾超时。分配前按 256 MiB 引擎估算限额预检。**没有生产级硬 RSS 隔离**，不能把估算当作实际峰值保证。首验平台仍为 Windows x64/MSVC、Rust 1.85.1、单线程、不压缩。

## 4. 代码和数据边界

`runtime/service.ts` 仍是唯一 HTTP/MCP 应用入口，委托 `runtime/analysis/real-service.ts`；它们共享一个 DiskStore、修订号、幂等回执、内容寻址仓和暴露账本。`RuntimeState.real` 是该状态的可选版本化扩展索引，不是第二个工作区。范围仍由共同的 `RuntimeState.ranges` 管理；现有 `range_get/edit/undo/redo/fork` 可用，修改会推进关联真实局面版本。

局面保存玩家角色、根配置和范围引用；分析规格绑定固定局面/范围、原始输入字节哈希、树指纹、求解目的、无锁定约束、精确河牌终局模型、引擎/算法版本与质量目标。已有规格不追随范围编辑。每个新尝试使用独立目录与 jobId，重试绑定原规格。

Rust worker 不写业务状态。它保存原生二进制，重新加载原生解，再对本模型固定的六个节点分别产生文件；摘要只保留路径与摘要索引。Node 等待进程 close，校验身份、输入、格式、节点维度/概率和来源后，才用一次业务提交发布完整解引用。没有将整棵树塞入工作区快照或 Agent 上下文。

六节点投影是当前受限模型的明确实现，不宣称可以沿用到任意大树。将来扩树需要原生按需查询/独立游标，不能直接递归导出所有节点。

每份解分别保存 execution、coverage、availability、quality。达到迭代预算仍可有完整可用结果，但 quality 标记 `budget-exhausted`；不得自动写成质量成功。数值直接来自完整固定引擎，未调用 fixture 数值或相似局面缓存。

金额输入为整数 centibb（100 = 1 bb），界面按十进制文本无损解析。下注为根底池百分比，必须能无损表达为整数 centibb；不隐式合并尺度、追加/强制全下或静默缩树。根以下的新增投入、终局未跟注返还分开查询；原生终局 EV 包含未跟注返还，历史投入视为沉没，换算到根收益需减路径已投入。

EV/权益/策略按指定玩家视角查询，返回玩家标识、固定来源、单位和分布。条件组合比例采用双方兼容私牌权重在当前路径上归一化；自身路径权重、输入权重与该比例分开，不声称已经给出从根的真实到达概率。缺失、范围外、死牌、不可达及非行动玩家的策略分别处理，指标不填零。没有把频率差换成 EV 损失。

派生范围保留 solution/range/节点/行动来源，原始浮点计算值不降回整数编辑频率。编辑派生范围创建新假设；界面未修改范围文本时保持原引用，不因只改名称而量化数值。

## 5. MCP 和信息规则

新增工具全部经实际 SDK stdio 客户端验证：

| 业务 | 工具 |
|---|---|
| 能力与状态 | `real_capabilities`、`real_workspace_get` |
| 局面、范围版本 | `real_case_create`、`real_case_revise`；复用共同范围工具 |
| 固定规格与预检 | `real_spec_create`、`real_preflight` |
| 任务 | `real_analysis_start/get/cancel/retry` |
| 解、组合和汇总 | `real_solution_load/query`、`real_range_aggregate` |
| 派生范围 | `real_range_derive` |

公共旧协议保持原义，新增业务以独立合同标识协商；不把原生 worker 的 solve/cancel 控制帧直接注册成 MCP 业务工具。写操作 schema 明确要求 requestId/expectedRevision；读页最大 200 行，响应上限 120,000 bytes；错误包含稳定 code、原因与重试资格。

真实 manifest 资源、`artifact_inspect`、共同制品页和备份走同一权限。独立作答期间，界面、MCP 与资源读取都不能揭示策略；阅读真实证据登记到原权威暴露账本，后续相关作答记录辅助身份，历史首次作答不重写。原教学反馈没有被填入新的引擎数值或判分结论。

已实际验证的旅程：

1. 非 fixture 配置（12.34 bb、50% 下注）与范围保存→真实预检/求解→Hero、169 类矩阵、具体组合→按行动派生→刷新及原生制品备份。
2. UI 创建→MCP 读取并修订→UI 接手；UI 再修订→MCP 读取；并发修改保留草稿并拒绝覆盖新版本。
3. 不支持的重复公共牌保持原输入，不发出其他局面结果；独立模式阻止真实页面、工具和资源读取。
4. MCP 恢复同一工作区备份→移除索引中的旧局面/解不再继续显示→输入草稿保留。
5. 实际终止运行真实引擎的业务服务进程→日志恢复为 interrupted→原固定规格新 attempt→真实结果可查询。不是只关闭页面或模拟 worker 状态。
6. 篡改导入元数据、损坏 blob、输入和节点来源/维度错误均拒绝。旧 S1 备份没有 real 扩展时可读取/恢复，不补造真实结果；运行中的真实作业须先停止后才能替换工作区。

每方 200 组合的执行/分页与预算不足测试是资源和传输检查，**不是新增独立求解质量认证**。原 16 MiB MCP 制品测试仍为 storage-only，不计引擎性能。

### Windows 开发服务复验

中途浏览器回归暴露两个独立现象：生成的 Playwright HTML 引发 Vite 整页刷新；Windows Node 24 前端子进程另有 `0xC0000409` 退出。前者已通过忽略报告、数据和原生构建目录修复。后者的底层原因尚未证明，当前仅采用经过完整 48 旅程验证的局部兼容办法：`scripts/dev.mjs` 在 Windows/Node 24 的 **Vite 子进程**禁用 Sparkplug/Maglev/TurboFan 编译层，保留 Vite 所需 WebAssembly；后端、Rust 和浏览器不使用这些参数。可设置 `RIVERLINE_VITE_JIT=1` 还原默认作受控诊断，可能重新触发退出；兼容模式可能增加开发服务的 CPU/延迟成本，没有做跨平台或性能等价保证。`--jitless` 因禁用必要的 WebAssembly 已撤回，未采用。成功的完整日志是 `.artifacts/solver/r2/stable-full.log`。

复验独立教学身份时使用新 `RIVERLINE_DATA`；复用已经阅读过真实解的工作区会正确保留辅助暴露，不能靠清除账本让历史数据假装未接触答案。
