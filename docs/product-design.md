# Riverline Demo 产品设计 v0.1

日期：2026-11-12（Asia/Shanghai）。状态：整版设计基线；D01 已实现其首个交互子集，见 `d01-delivery.md`。本文中的“必须”是整版 Demo 目标，非全部已交付声明。

## 1. 目标与边界

构建一个可操作、可重播的德州扑克策略研究与训练 Demo：用户从局面出发，为整个范围构建策略，浏览模拟求解结果，评价与修订策略，通过理论和 AI 操作理解问题，再转成连续策略研究、练习和复测。

当前验证：产品逻辑、信息组织、完整旅程、模块契约和 AI 控制体验。当前不验证扑克计算正确性、求解速度、模型智能、实际教学有效性或商业生产能力。

“全功能展示”分为三个层次，三层都属于最终 Demo 范围：

- L1 深交互：局面、范围、策略、评价、AI 操作、修订、训练；输入与状态真实联动。
- L2 完整模拟：Solver 生命周期、连续节点、剥削实验、知识检索、复盘、能力报告；用完整脚本与制品串通流程。
- L3 产品预览：翻前、多路、MTT/ICM、团队与部署位置；展示配置、条件、报告形态和能力说明，不承诺实际计算或权限隔离。

首个开发闭环不代表删减 L2/L3；所有范围以功能矩阵及评审脚本追踪。

基于实际体验反馈，默认研究入口改为“Hero 手牌 → 当前行动与后续条件 → 全范围参考”。查看模拟策略不要求先完整提交。用户可选择只改局部、用参考辅助补全，或采用进阶的全手工范围构建。Hero 推演、辅助构建与独立范围作答必须保留不同身份，具体已实现流程见 `hero-feedback-delivery.md`。

## 2. 用户与工作对象

核心用户是理解规则与基本范围概念的学习者，也能够切换到研究者和内容作者视角。当前没有真实登录，多角色切换只是本地演示视角。

稳定工作对象：研究案例、局面修订、范围版本、策略草稿/提交版本、模拟求解制品、评价报告、实验分支、训练题、作答、理论条目、Agent 任务。

统一上下文条始终显示：案例名称 / 当前版本 / 决策节点 / 玩家视角 / 研究或训练模式 / 数据为示例。

## 3. 信息架构

导航按用户任务组织，不按后台服务名称组织。

| 页面 | 主要内容 | 跨模块出口 |
|---|---|---|
| `/` 工作台 | 最近案例、继续草稿、今日训练、演示旅程入口 | 打开案例、开始训练 |
| `/library` 局面库 | 位置、街道、牌面、底池类型、形式筛选；创建与导入 | 建立案例 |
| `/study/:caseId` 研究工作台 | 局面、范围、策略、节点树、求解、评价、实验标签页 | 训练、知识、报告 |
| `/practice` 训练中心 | 目标、题组、难度、独立/辅助模式 | 进入题目 |
| `/practice/:sessionId` 训练会话 | 作答、提示、提交、反馈、修订、迁移题 | 研究原节点 |
| `/review` 手牌复盘 | 示例导入、时间线、行动前视角、问题卡 | 提取研究节点、建练习 |
| `/knowledge` 理论库 | 概念、来源、适用条件、关联实验 | 应用到当前案例 |
| `/progress` 学习记录 | 维度、作答证据、独立与辅助区别、复测 | 开始推荐题组 |
| `/reports` 研究成果 | 策略比较、实验摘要、Agent 报告、导出 | 返回固定版本 |
| `/settings` 演示设置 | 场景、速度、失败注入、数据导入导出、重置 | 重播旅程 |

Agent 作为全局侧栏和可展开任务中心，不另外复制一份研究状态。Solver 队列、版本历史、来源详情为共享抽屉，保留当前工作区。

## 4. 核心工作台布局

- 左侧：案例导航、行动路径、研究分支；可收起。
- 中央：牌面/底池摘要、双方范围、当前策略矩阵、组合明细；焦点模式扩大编辑区。
- 右侧：Agent、理论证据、当前诊断；按任务切换标签。
- 下方或抽屉：求解任务、版本比较、分支覆盖。

策略矩阵有范围权重与行动频率两个明确模式。点击格子展开具体组合；批量编辑有锁定、选择范围和影响数量。提交前显示未完成项；“未填写”与“设置为零”区别展示。

参考、用户草稿和 AI 建议有各自标识。用户不能把参考矩阵误认为自己的作答。操作通过可撤销 patch 应用，批量改动显示预览。

## 6. 完整旅程

### J01 构建 → 求解 → 评价 → 修订

从局面库选择 BTN vs BB 示例 → 查看已知事实与范围假设 → 创建自己的草稿 → 编辑全范围并看整体频率 → 检查未完成项 → 提交版本 → 运行模拟求解 → 浏览节点 → 打开三种评价维度 → 定位问题组合 → 修订 → 保存第二版 → 对比两版 → 导出成果。

验收点：对象 ID 和版本连续，草稿操作有效，提交后修改不改变旧报告；求解与收益均标明示例。

### J02 连续策略

打开翻牌方案 → 选择对手回应 → 查看到达范围示意 → 选择不同转牌 → 编辑后续策略 → 查看已覆盖/未覆盖分支 → 修改翻牌方案 → 提示哪些下游节点需复核 → 保存新分支。预置分支之外的任意牌面保留草稿并标记无示例结果。

### J03 AI 委托研究

选择建议任务“分析当前范围结构并建立改进分支” → AI 展示计划和示例预算 → 读取当前案例 → 检索理论 → 生成 patch → 应用到独立分支 → 运行 mock 求解与评价 → 形成报告 → 用户查看修改并继续编辑。AI 的每一步都能定位真实制品。

另有“仅建议”“直接在新分支执行”两种策略。自定义自然语言只匹配明确支持的意图；未匹配时说明演示边界并给出可运行任务，不假装拥有开放式推理。

### J04 对手假设与实验

复制当前案例 → 设置“示例对手过度弃牌” → 显示这是人为假设 → 选择锁定范围和节点 → 运行预置实验 → 比较策略结构和示例数值 → 修改另一个假设形成第三分支 → 查看结论适用条件。

### J05 训练与迁移

选择范围构建题 → 答案隐藏 → 用户独立填写 → 提交 → 结构检查和参考差异反馈 → 打开一条理论解释 → 修订但不覆盖首次作答 → 转入另一张牌面的迁移题 → 学习记录显示两次证据。提示与 AI 辅助有独立标记。

### J06 复盘导向研究

导入内置手牌文本或受支持的 Demo JSON → 显示解析/缺失/待确认 → 确认 → 沿时间线选行动前节点 → 检查未来牌与对手私牌不可见 → 提取到研究案例 → 将问题生成训练题。未知文本只保存待整理草稿，不生成虚假解析。

### J07 理论到实验

检索“过牌范围保护” → 查看自写理论摘要、来源链接和条件 → 看相关案例 → 在当前案例建立一个对照分支 → 运行模拟 → 保存“观察/解释/尚未验证”的分层笔记。

### J08 任务异常恢复

开启失败注入 → 提交任务 → 失败信息 → 重试成功；再次提交后取消 → 不再生成完成报告；计算中修改输入 → 旧结果只能回到旧版本；刷新 → 已提交任务按恢复规则处理；关闭失败注入后回到理想流程。

### J09 预览扩展与成果恢复

打开翻前、多路、赛事示例 → 查看不同条件和示例报告 → 回到保存成果 → 从旧版本恢复为新草稿 → 导出/清空 Demo 数据/重新导入 → 恢复相同案例与成果引用。预览页仍需有可点击的配置与报告，而非“敬请期待”空页。

## 7. 信息与数值约定

- 全局有轻量“演示模式”标识；数值详情与导出有 `synthetic` 来源。避免大面积技术警告压过产品体验。
- 真实本地编辑结果显示“你的策略”；作者提供的数据标“示例参考”；AI 输出标“脚本化 Agent 演示”。
- 结构完整性和频率差异可在本地实际计算，但不叫真实扑克质量分；EV、权益、可利用性、置信度、学习预测均不计算真实业务值。
- 缺少匹配 fixture 时，输入和已编辑内容保留；示例报告只能在其自身条件下打开。
- 训练答案默认隐藏；揭示之后的提交标记为辅助/已揭示，不覆盖独立作答证据。

## 8. 视觉与交互方向

定位为清晰、可信的研究软件。中文优先，保留 BTN/BB、SRP、EV 等缩写并提供解释。

暂定深蓝灰中性色、青绿色主操作；扑克动作使用稳定分色，警告/质量使用独立图标与文字，不能只靠红绿。卡牌花色清晰，数字使用等宽对齐。

桌面 1440px 为主，1280px 完整可用；1024px 将右侧栏折叠；窄屏提供阅读与基础操作，不承诺手机上高效构建大矩阵。

矩阵支持键盘焦点、动作有可读标签、弹窗有焦点恢复、动画可减弱。优先使用原生文本/SVG/组件，不借用其他产品的图片、品牌或完整界面。

## 10. 完整产品补充需求：Hero 自定义尺度与混合频率

来源：2026-11-12 用户明确指出 Hero 当前行动只有预置尺度、没有频率选项，要求完整产品加入，并允许 Demo 阶段先跳过。

- Hero 当前节点应支持自定义下注/加注尺度，受合法行动、筹码和金额单位约束；预置尺度只是快捷模板。
- 同一 Hero 手牌应能在多个合法行动及尺寸之间分配频率，支持纯策略与混合策略；完整分配合计 100%。
- Hero 与全范围策略共用行动/尺度/频率语义，能够比较、保存、恢复与扩展，不能将单手入口永久限制为一次纯行动。
- 后续策略模型需表达动作类型、尺度参数和频率，不能永久写死为 X/B33/B75。规则合法与求解树是否支持分别判断；没有匹配结果时不伪造评价。

状态：完整产品已确认需求，尚未实现；用户明确允许当前 Demo 暂缓。Demo 的 Hero 推演继续采用预置尺度和单一行动。现有全范围编辑器中的混频能力保留，这次暂缓不意味着删除它，也不将此需求自动并入当前 Demo 开发任务。
