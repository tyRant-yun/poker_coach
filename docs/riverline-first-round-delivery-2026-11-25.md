# Riverline 统一产品第一轮开发

日期：2026-11-25（Asia/Shanghai）。执行授权：用户要求任务确认后开始开发，完成产品目标确认与第一轮开发。本轮承接 `c9d5482` 及开始时已有的一般河牌在途修改，未覆盖/回滚原工作。下列检查随实际完成更新；不将此前设计或远程仓库测试算作本批证据。

## 1. 已确认目标与本轮范围

产品目标：完整一手的连续练习发现问题 → 手后按行动前信息复盘 → 深入研究 → 回到练习。UI 与文字以用户任务取舍，减少重复信息；专业研究保留可发现的深度功能。真实能力按规则、对手模型、求解模型和评分资格分别声明。

第一轮交付范围：

- 真实规则的 HU/6-max 100BB 整手练习、合法终局、位置轮换、疑问记录、自动保存和恢复。
- 手后查看逐次 Hero 决策，按历史前缀重放，原选择与当前研究输入分开。
- 从原手派生研究来源/笔记；两名存活玩家的河牌可设定假设范围进入现有真实一般树分析；其他节点保存问题并说明暂不支持计算。
- 一般河牌多尺寸、加注/全下树的真实 UI/MCP/worker/原生分页链路，双方范围/组合、行动 EV 和真实策略矩阵。
- 新主导航“练习 / 复盘 / 研究”、界面/文字减法、桌面和窄屏操作；课程/旧 Demo 从“更多”或原地址进入。
- 本地构建后静态页面与 API 同端口运行，练习采用 SQLite，复用原 Node 服务和原生 Solver；不依赖 Vite 开发服务器进行日常使用验收。

这是一轮有明确能力边界的可用产品增量，不是所有 U00–U08 或完整商业 Solver 覆盖完成。

## 2. 实现与边界

| 模块 | 本轮实现 | 限制 |
|---|---|---|
| 规则 | Python helper 复用固定 PokerKit 0.7.8，重放明确发牌/行动，合法行动、账本、边池/返还、全下/摊牌均交由成熟规则实现 | 本机 Python 3.14；没有复制 newHoldem 规则或自行实现 CFR/牌型裁决 |
| 对手 | `bot-heuristic/1`，只用 actor 自己的牌、公开状态与合法动作，决定持久化可重放 | 有区分的启发式练习对手，不是六人 GTO 或强度评级 |
| 整手 | 默认六人，可选 HU；每手100BB、位置轮换、随机发牌、动作/疑问幂等保存；弃牌与全下可合法结束 | 当前为每手重置的训练桌，不提供持有筹码累计的现金会话或定向整手题库 |
| 信息边界 | 未完成整手期间经同一 Node 入口禁止研究、资源/备份和历史参考；历史决策只返回当时公开牌与 Hero 私牌 | 本轮采用先完成整手再研究，没有开放手中即时辅导与自动 GTO 评分 |
| 复盘 | 保存整手与逐次原始选择，节点前缀重放、标记疑问、研究后返回原手 | 不把输赢等同于策略评分；未计算节点不补零或拼接其他模型的损失 |
| 研究 | 接续一般树在途代码，真实进程、按需读取、分页、深层账本/返还、派生范围、固定版本、恢复和取消；矩阵显示兼容组合加权的真实策略/范围/权益/EV，Hero 各行动 EV | 当前仅 HU 河牌给定范围离散树，UI每方最多200个正权重组合，非任意大范围/全街道性能承诺 |
| 来源 | `game_research` 固定原手行动前快照及哈希，`game_study_link` 绑定真实案例版本；研究问题持久化 | 牌桌事实与人工范围假设分开；忽略弃牌私牌相关性，不称整手/六人均衡 |
| 存储 | 新练习/幂等/研究来源/笔记在同目录 `hands.sqlite`，WAL事务；研究仍沿用既有 journal/blob；均由一个 Node 服务拥有 | 未实施全部旧课程/研究到 SQLite 的迁移，旧浏览器课程仍保留原存储边界 |
| 备份 | 练习 JSON 单独导出/重放核验后事务导入；研究沿用原备份；数据损坏/来源伪造拒绝且无半导入 | 两种备份分别处理。练习备份含完整发牌，不作为未见题；研究案例绑定不随跨库导入猜测恢复；不同手牌同序号冲突需空工作区 |

## 3. UI 与文字独立交付记录

本轮主流程按 UI01–UI06 单独实施并验收；既有所有旧页面的完整专项仍未完成。上轮会话 HTML 草图保持历史样例，不作为应用实现。

| 调整 | 用途 / 删除理由 |
|---|---|
| 三个主入口，专项单点/课程归入更多 | 主旅程按整手行动、复盘、研究划分；保留旧功能地址与 `/legacy` 兼容入口 |
| 练习常态只留牌局、行动、疑问与行动记录 | 完成整手的操作直接可见；对手版本/重置规则收进设置详情 |
| 研究去掉重复工作台标题、默认长公告和“真实计算证据”徽章 | 真实来源/质量已有具体结果与详情；不重复自证 |
| 打开解后收起计算列表与原手笔记，矩阵前移 | 主区域服务当前读策略；执行过程、来源和笔记仍有明确展开入口 |
| 策略/范围占比/权益/EV 采用明确视图切换，Hero 行动 EV 单列 | 区分分母、数据类型与具体组合，不用范围热度冒充行动频率 |
| 原手来源保留“返回原手牌”，无解节点可保存问题 | 研究与练习连接明确，计算资格不足时仍保留用户成果 |
| 练习/研究备份分别命名 | 避免用户误以为一份旧研究备份已包含新 SQLite 手牌 |
| 同一明亮基础界面、清晰卡牌与聚焦、窄屏重排/组合表横向读取 | 提升真实操作区和文字可读性，未加入3D/无关动效 |

## 4. 复现与日常启动

```powershell
npm ci
npm run rules:setup
npm run solver:build
npm run build
npm start
```

打开 `http://127.0.0.1:5174/play`；`/hands` 复盘，`/solver/real` 研究。`npm start` 同端口提供构建后的页面/API。Python 环境为仓库忽略的 `.venv-rules`，也可通过 `RIVERLINE_PYTHON` 指定已有、确实安装固定依赖的解释器。初次安装必须能连接包源；本机曾遇无效代理，清除当次安装子进程的代理环境后成功，未改系统配置。

默认数据目录沿用 `.data/riverline-s1/local`，新练习库在其下。`RIVERLINE_DATA` / `RIVERLINE_WORKSPACE` / `RIVERLINE_PORT` 可用于独立工作区。不要在两个服务中同时打开同一数据目录。规则/MIT通知见 `engines/rules/THIRD_PARTY.md` 与 `engines/rules/licenses/pokerkit-MIT.txt`。Rust 保留既有固定工具链与来源，当前没有发布容器/安装包/远程服务。

## 5. 实际检查

已完成并观察通过：

- TypeScript、生产构建；现有状态/运行时 105 项；真实 Solver TS/CLI 13 项。
- 固定工具链 Rust fmt/clippy，10 项 Rust 测试。
- 6 个一般河牌独立 LP/终局/BR/账本/组合基准 + 5 个 oracle 自测；4 个原河牌独立基准 + 2 个 oracle 自测。原 `river-polar-pot` 达本批独立阈值但未达到更严引擎停止目标，继续保留 `iteration-limit`，未改写质量。
- 3 项整手/规则/SQLite 集成测试：确定重放、全下、短全下不重开、已知主/边池及返还、筹码守恒、权限、幂等、进程重启后恢复、历史前缀、备份和伪造快照原子拒绝；新手开始后，旧研究/终局行动/创建回执不能绕过当前信息边界，当前手的合法重复请求仍可恢复。
- 6 组真实 MCP 测试；新增13个整手工具逐个实际调用，列表共73工具，HTTP/UI与MCP同一服务/工作区。
- 构建后应用的全50条浏览器旅程通过（35旧课程/工作台、13分析、2整手，3.7分钟）；修复旧回执读取边界后，重新通过构建、3项整手集成、6组MCP与6条真实研究/整手浏览器主旅程（16.8秒）。
- 格式检查、`git diff --check`、本批文档相对路径检查通过；本地Python依赖检查通过。

扩大回归的首次运行复用了先前原生研究数据并将S1测试放在旧课程前，导致暴露身份相关旧断言失败；另发现旧首页入口和一个IndexedDB初始化时序假设。已保留旧入口、等待真实库初始化，并使整版测试使用新独立数据目录及“旧课程→分析→整手”的原有依赖顺序。整手刷新测试改为先等待保存回执再刷新，保留真正的恢复验证。第二次全量在UI撤销后立即MCP读取的旧测试中发现时序竞争，改为等待该撤销的真实HTTP回执后核对；随后全50条通过，没有降低权重/恢复断言。

Windows 前端/测试进程偶发退出仍未有确定根因。本轮日常运行和浏览器测试使用静态页面；曾观察一次测试启动异常、遗留本次自建的运行时，核对PID/命令后仅停止该实例。浏览器测试启动脚本保留 Windows Node24 局部编译层兼容参数，不能据此宣称上游根因或所有运行稳定性问题已经修复。
