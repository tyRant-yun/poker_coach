## 1. 出口、阶段和先决条件

目标：练习结束→无需填范围看到自动图表→理解合格决定的参考EV差和建议→在原决定深入研究→返回或练同类题。主流程不依赖AI服务。

第一组建议固定HU、100BB、50/100盲注、0 ante、无抽水，与当前练习匹配。六人翻前数据包列为下一组独立目标，不用HU成功替代。若最终用户选择有抽水游戏，需要先同步规则/模型与数据，不仅替换范围表。

M1与M2有实质数据/求解门：没有合格来源时可推进合同、UI、缓存和可行性研究，但不能用现有三档范围或Mock通过真实策略验收。已得到的数据样本不足以覆盖所有路径时按实际覆盖发布。

## 3. 拟定合同（尚未发布的领域草案）

### 3.1 StrategyPackManifest

- 身份：schemaVersion、packId/version、contentHash、sourceRef、producer/engine版本、原始文件校验和、导入器版本。
- 规则：variant、originTableSize、positions/button语义、每座stack、SB/BB/ante/straddle、原始金额单位、rake结构/封顶/时点、chipEV或ICM/其他收益模型。
- 模型：精确尺寸/树定义、后续街道模型/抽象、是否有多人/bunching、节点/牌类/组合索引与展开映射、可达支持集。
- 指标：策略精度、EV单位/原点/投入及退款语义、action-EV是否具备、采样/停止/质量依据；不同来源质量指标不强制换算成NashConv。
- 权限：取得方式、可本地使用/自动调用/再发行/服务化的依据、限制及失效处理；不由一个`licensed: true`省略实际条件。
- 覆盖：精确规则/路径/动作/街道、允许训练起点、支持的后续发牌与模型限制；缺失字段不从临近包猜出。

范围和策略/EV数组存为不可变分块制品，manifest/数据库只保存索引。公开DTO按需查节点/组合/摘要；不得把整棵树写入Zustand快照、每行journal、URL或Agent上下文。

### 3.2 RangeLineage

记录父范围/策略包/解引用、原公开事件哈希、动作和机会更新、联合兼容模型、生成器版本、输出范围摘要及哈希。状态分`exact-under-reference / declared-approximation / off-tree / zero-reach / unavailable`。

“exact”只修饰在声明参考模型和分布表示下的派生，不意味着对真实对手范围的准确推断。HU乘法更新、六人相关性、折叠牌条件等分别声明；不能将独立边缘近似标成精确联合分布。

### 3.3 DecisionEvaluation / Report v2

保留handHash/decisionSeq/行动前信息集、原金额、背景与活跃人数、牌面、player/combo、参考包/Spec/Solution/节点路径、收益原点/单位、动作EV/频率及原行动精确匹配。

新增能力维度：sourceMatch、historyMatch、actionCoverage、continuationCoverage、rangeStatus、numericQuality、comparisonStability。运行状态与可评分资格分开：计算完成不自动意味着可以评价原决定。

评价种类：`reference-comparable / partial-model / approximate-research / facts-only / unavailable`。EV差可空，空值必须带原因。建议有evidenceRefs、适用条件及下一步，不存在证据时不生成确定因果解释。

报告记录所有Hero决定分母、具备合格EV差的分子、待计算/未知/树外数量；图表可追溯单个决定。旧`auto-review/1`仍按原有限假设显示，不静默升级为新数据来源。

### 3.4 评价与数据所有权

Practice持有原手、独立作答和暴露账本；Research持有策略制品、固定求解、派生范围与研究结论；AutoReview持有可重建的评价投影与作业关联。Agent只消费获准的视图并通过同一业务命令申请研究分支，不拥有另一份权威报告。

`returnContext`至少固定handId/decisionSeq、原问题、viewTab、sourceRef；研究链接固定solution/player/path/combo及映射。输入变更建立新分支，不能改变旧报告绑定的解。版本冲突/原解缺失时解释并安全重算，不展示过期值当最新结果。

## 4. EV验收规则

同节点同参考下比较各行动`Q`；原行动不匹配、原组合不可达或候选缺失时不能给确定的全局“损失”。所有图表和建议引用同一数据投影，不让LLM重新计算或填数字。

1. 翻前频率正确但无行动EV的数据包，只能启用策略参考，不得给EV损失。
2. 混合策略中低频行动不因低频判错；小EV差与运行噪声区分；全局可利用性不冒充逐组合误差界。
3. 本手盈利仍可存在参考EV差，亏损也可能没有参考EV差；结算与决策评价分列。
4. 单街独立解的差值不能加成“真实整手损失”。若后续提供诊断合计，名称、共同协议、覆盖率和每项来源一并显示，不与真实反事实整手价值混同。
5. 原始数据的“相对fold”EV与现有当前节点沉没成本口径必须验证转换；不确定转换时拒绝拼接。
6. GTO参考与对固定Bot的最佳回应分开；后者需要独立策略分布和BR评价，当前不宣称已有。

## 5. 数值、数据与信息门

### 数据与翻前

- 对真实样本逐项复核根、HU BTN/SB首入、BB防守、limp/check、面对3-bet等**实际包含**的路径；缺少limp的包不能验收为覆盖上一轮试用的limp手牌。
- 原始频率和、合法动作、组合展开/花色映射、死牌和0权重；来源精度前后保持；不能用自写fixture冒充来源数据。
- 每种行动EV口径准备可独立计算的小树/全下/账本检查；若适用，独立来源精确匹配规则/树后对照，差异保留。
- 同一采样来源扩大预算/重复运行，观察行动价值和边界建议稳定性；不能把重复一致当成无抽象偏差证明。

### 翻牌与续街

- AF04先冻结独立oracle：小范围可枚举机会分支的checkdown/全下终局、带行动树的独立LP/BR或可审计参考；不仅比较适配器与自己输出相等。
- 检查未来牌机会概率、组合兼容、下注/未跟注退款、同构映射、两街与三街延续、同一节点不同游标隔离。
- 继续跑已有6转牌/10河牌数值门；新翻牌门不能用这些旧通过数量替代。
- 首组有利于验证的小树不等于真实全范围覆盖；实际目标范围必须独立跑通或发布明确资源拒绝。

### 信息权限

- 报告输入只用行动前可见事实；改变未知对手底牌/未来牌而保持可见前缀时，当时参考输入应保持不变。
- 用户开始下一手或独立题时，UI/HTTP/MCP和Agent均不能获得受限制答案；后台可继续算，但展示遵守现有暴露政策。
- Agent工具结果需同样检查当前权限/版本；缓存过的文本不能绕过新手答案门。研究分支结果不会成为Bot实时决策的隐藏答案。

## 6. 性能与持久化门（目标，未实测）

目标机器已读为i7-14700HX/约15.7GiB内存；当前固定原生单线程。以下是待验收目标，不是性能承诺：

| 场景 | 拟定目标/测量要求 |
|---|---|
| 已有参考命中 | 从结束到可交互摘要P95≤1秒，完整轻量图表P95≤2秒；至少30手，计时剔除用户停留但保留真实服务耗时 |
| 未命中后台 | 先显示事实、覆盖与队列状态；快档期望≤10秒有首个合格决定；超时保持待算/质量不足，不能降质量冒充达标 |
| 深度研究 | 独立配置60/180秒实验预算；报告实际完成比例和质量，不承诺全部完成；低预算未收敛允许明确失败 |
| 练习响应 | 后台启用与关闭各跑相同旅程；行动响应P95目标增幅≤100ms；Bot计算/播放延时分别记录 |
| 内存 | 建树先估算；实验先1/2/4GiB阶梯，总应用峰值预算初定≤6GiB且保留系统余量；记录实测RSS与可用内存，监控/终止子进程，不只相信估算 |
| 缓存/恢复 | 冷/热分别测，记录查表/求解/原生查询/序列化/UI分段、命中率、制品增长与恢复时间；报告压缩或索引优化不能丢可复核来源 |

实验矩阵至少包括：16/64/128组合已有尺度；真实数据包实际非零范围；单/多尺寸；checkdown与真实河牌下注；不同代表牌面；压缩配置若采用则单列。内存预检失败不默默砍成128组合，保留原输入并解释。

缓存保存同街同解，多个Hero决定复用按需查询；优先静态预解包和近期缓存。缓存键覆盖模型和来源；变更数据包/范围/树/引擎/质量目标应失效或保留为旧版本。

AF06先在隔离工作区验证存储/迁移，保留旧备份和回退路径，再按实际授权处理默认工作区。既有大journal债务要测冷恢复和写入增长，不以清空用户数据解决。

## 7. AI解释与Agent门

先提供版本化只读报告投影和结构化解释输出：claim、evidenceRefs、conditions、nextStep。数值在前端引用权威字段渲染；模型文本内出现新数值/不存在的节点引用时拒绝该段并回退模板。

若再开放工具循环，初始限单次最多3次工具调用、1个新研究分支、30秒墙钟预算，求解同时受既有资源队列限制；这只是拟定起点，需评测后调整。禁止改原报告/原解、读取隐藏牌、私自覆盖范围与无界开任务。解释、请求比较和生成新练习分别记可观察事件。

至少验证20个固定案例，覆盖来源不足、树外尺度、低频等EV、预算耗尽、上下文冲突、诱导编造、未来信息请求及模型不可用。数值引用与无越权要求全部满足；“有帮助”另做用户评估，不能只看JSON合法。新增LLM供应商/凭据/费用方案另行确定，未接入时保持完整离线主流程。

## 8. 视觉用户旅程与完成定义

- FJ01：标准HU练习结束，首屏已有图表/覆盖/原行动，下一手好找；无需先填范围。
- FJ02：同一合格手牌从翻前到四街各决定→同解研究→返回所选决定；无来源标题错配、错误根路径、滚动跳位。
- FJ03：复跑上一轮4♦6♠的limp手牌及两个原疑问；允许结果与旧假设不同，必须展示新来源；未覆盖就明确失败，不套旧答案。
- FJ04：自由整手出现树外尺寸/0到达/多人时，图表保留未知，不显示0损失或假完整评分；可创建明确假设的研究分支。
- FJ05：关闭/重启、取消/重试、新手期间禁止查看旧答案；服务恢复后固定引用与浏览位置可续接。
- FJ06：同主题再练区分已见与独立迁移，Agent不可用仍能完成主流程；六人只有独立数据和模型验收后才宣称覆盖。

应用实施后按变化跑类型检查/构建、关键状态/规则/数据/Solver检查、真实MCP和对应浏览器旅程；至少一次人工视觉从练习到复盘到研究再练，不用自动按钮通过替代体验结论。

最终交付须逐项列：取得哪些数据及权利、实际支持规则/路径/街道、数值依据、性能分布、UI与Agent实际能力、失败与未覆盖。**没有可靠数据或独立翻牌门时，不将AF-M2标为完成。**
