## 3. 第一段先交付的位置与 Bot 闭环

先M1-P01/M1-P02+M1-B01/M1-B02形成能看到的变化：

1. 创建新的HU或六人会话；Hero固定在易操作显示位置，按钮/扑克位置由规则映射确定。
2. HU选轮转或固定BTN/BB；六人可选UTG/HJ/CO/BTN/SB/BB或轮转。设置只在新手/新会话生效，进行中不换身份。
3. HU选择内建基线或固定版本实验候选；六人此批继续明确使用内建启发式，不把HU候选装进五个六人座位。
4. 打完至少两手，保存问题并在正确位置/行动前复盘；研究后回到同一原手。

适配候选初选为v2.2.2 final-r9的核心路径，用于本地集成测试，**不裁定它比已上传v1.8.4强**。工程开发须先核对manifest/源码包摘要与Bot项目当前工作约定，在新接入候选/发行目录实施，不能改冻结目录。当前`V2Runtime`返回ChipZen Action且仍接受SDK形状状态，需封装练习适配，不能把API名称“SDK-independent”当成已实现无SDK依赖。

先保持现有原子批次推进，限制Bot等待并记录批次响应；外部Bot连续行动导致明显等待时，P03的逐行动持久化为下一批前置，不在一条SQLite事务里await。播放只消费规则帧，不依赖Bot人为sleep来制造观感。

## 4. 第二段交付研究容量与上下文

当前转牌的16限制同时存在于Rust preflight/worker/reader、TS节点schema、Node校验、UI范围提示和查询缓存。必须统一消费新profile；不能只改一处常量。

M1-S01先冻结代表性输入：同花/两色/彩虹结构、非对称与重叠范围、至少两种有效深度和下注尺寸；原16小模型作哨兵，32/64/128/200作容量阶梯。至少两个128×128问题完成预设质量，其他profile如预算耗尽明确展示，不能全部用checkdown或0迭代样本代替研究性能。

沿用现有256MiB估算/120秒预算作为起点，不默认扩内存/时间。记录引擎估算、计算/查询进程实际峰值RSS、原生文件、冷/热查询及Node/UI开销。当前机会概率的逐私牌对×候选牌枚举可能成为瓶颈，先profile，再用独立加权概率/阻断样例证明任何优化等价。先单计算槽、合计两个查询槽，Bot负载同时采样。

原生侧采用新版本的节点元信息/范围聚合与组合页，保持有界传输、固定输入/原生身份和物理牌逆映射。Node不先拉完整大节点再假装分页；矩阵分母、缺失/不可达、动作频率/权益/EV仍由真实同解数据产生。旧schema3按原义读回，新能力用显式profile/reader版本，不冒充改变旧解输入。

M1-S03恢复绑定solutionRef+path+player+view。分支牌、Hero观察组合和根输入各自明确；草稿与固定解不同仍提示来源。支持切解、改草稿、迟到响应、恢复后路径失效、备份导入到新工作区。

## 7. 工程与交付方法

实际执行前只复核基线/适用AGENTS和选定Bot发行事实，不重新研究所有已交付代码。先闭环再抽共用；TS/Python/Rust合同与黄金样例同时更新。新接口的UI/MCP走同一权威，跨模块不直接双写。

每个高风险变更跑相应规则/金额/信息/并发/恢复检查，真实引擎扩容保留独立数值与资源报告，策略效果单列。阶段出口再做typecheck/build、状态/规则/Rust、真实MCP与完整浏览器回归；样式只做对应旅程。固定构建后跑浏览器，运行中不重建dist。

交付包含实际能力表、任务结果、版本/输入/发行包摘要、失败/未覆盖、启动/回退/备份说明。只本地提交，不推送、部署、上传平台、创建远程或移动历史标签。纯规划本次只校验文档与链接，不运行应用测试。
