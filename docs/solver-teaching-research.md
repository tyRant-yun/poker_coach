# Solver 产品逐项研究：对 Riverline 教学设计的启发

日期：2026-11-12（Asia/Shanghai）。状态：官方资料研究与产品分析已完成，本轮未修改应用。

本轮读取了[关联聊天](codex://threads/01a1cdfc-2ab0-7dd1-b60e-82b8c604606a)最近一次商业 Solver 研究，范围为 7 组产品。Simple Postflop 与 Simple GTO Trainer 分别分析，因此以下共 8 项。不是对上一轮 GitHub 工具列表的替代。

研究方式：查阅官方产品页、帮助文档与官方教程的文字目录；没有安装、购买、登录或观看完整视频，没有独立验证算法、精度、速度、商业套餐或学习效果。下文“资料支持”与“Riverline 建议”分开；未在文档中见到教学功能，不等于该产品一定没有。各版本和授权的能力不能视为相同。

证据索引见 [本轮来源记录](research/solver-teaching-sources.json)。可实施方向见 [教学产品调整方案](teaching-product-redesign.md)。原 D01–D08 交付状态及 mock 边界保持不变。

## 1. 先定义比较尺度

一个研究功能只有转化为学习者可完成的动作，才进入我们的教学设计。这里使用 8 个维度，不按功能数量排名：

| 维度 | 学习者应能做到 |
|---|---|
| 条件识别 | 说清位置、前序行动、筹码、范围、尺寸、价值目标与结果适用范围 |
| 策略阅读 | 区分组合、牌类、范围权重、行动频率和各种结果单位 |
| 范围理解 | 从一手牌推及同类、行动范围、双方范围及阻断/牌面因素 |
| 连续决策 | 解释前序行动如何筛选范围，及后续发牌怎样改变计划 |
| 反事实研究 | 先预测，再改变一个明确条件，检查结果和解释边界 |
| 练习反馈 | 单点、整街、行动线与范围构建各有训练目标和反馈时机 |
| 迁移复测 | 在新题、条件变化或延迟之后重新作答，区别提示后修正与独立表现 |
| 证据可信 | 所有结论能回到输入、节点、版本、质量、来源与适用条件 |

这些是本项目的分析尺度，不是对参考产品已证明教学效果的评价。

## 2. PioSOLVER：学习如何组织可检验的策略研究

**资料支持的功能。** 官方列出策略树浏览、组合级策略/EV/权益/行动范围、Range Explorer、后续牌纵向比较、聚合报告、内置训练、树与加权范围配置、节点锁定和脚本接口。[功能概览](https://site.piosolver.com/docs/feature_overview/)

其文档区分范围权重、行动策略与考虑双方组合相容性的真实频率；概念 FAQ 也说明混合动作 EV、范围构成与均衡条件的关系。[数字含义](https://site.piosolver.com/docs/viewer/numbers_in_piosolver/)、[概念 FAQ](https://piosolver.com/docs/faq/gto_concept/)

| 我们应学习的机制 | Riverline 的教学转化建议 |
|---|---|
| 同节点的多种结果投影 | 用户问“为什么这手牌这样打”，先定位同一节点的行动、范围与对手继续范围，避免 AI 离开当前条件泛讲理论 |
| 沿行动和后续牌比较 | 先让用户预测下一张牌的影响，再显式比较原节点与配对节点，并列出保持/改变的条件 |
| 聚合报告 | 用一组牌面检验用户归纳的规律，同时给出反例，不把一个翻牌的结论推广到所有牌面 |
| 锁定与重算 | 让用户写下对手假设，预测自己的调整，再查看带限制的实验结果 |
| 专业指标的明确语义 | 增加“输入范围权重/当前节点行动频率/条件到达频率”的教学提示，不用一个百分数承载三种含义 |

**对当前 Demo 的判断。** 已有节点、多视图、固定版本和假设实验底座；还缺预测记录、变化原因的证据链、跨牌面规律与反例、真实条件到达范围。现有静态节点样例不能被称为已完整传播的策略树。

**取舍。** 借鉴研究结构，保留专业模式；初学者先看到解决当前问题的视图。旧功能概览含 2015 年历史段落，本次不采纳其中性能、项目活跃度或版本时效主张。策略取整也不能自动等同于经过验证的低损失简化。

## 3. GTO+：学习紧凑的实验工作流

**资料支持的功能。** 官方教程目录涵盖建树/编辑、导航与结果分析、转河牌分支重算、范围比较、锁定/编辑策略、对抗解练习、数据库及聚合报告、范围预设和 FlopzillaPro 联动。[官方教程目录](https://www.gtoplus.com/videos2/)

| 我们应学习的机制 | Riverline 的教学转化建议 |
|---|---|
| 建树到分析的短路径 | 为每个学习问题提供可复用配置；配置摘要始终可见，不要求用户先学会全部求解设置 |
| 锁定、编辑、比较 | 保留原解，将用户假设与简化策略放入不同分支；比较前说明固定了谁、允许谁响应 |
| 多牌面数据库 | 将案例库组织成“同一学习目标的一组对照”，而非十个互不关联的入口 |
| 对抗固定解练习 | 区分“当前固定对手下的动作表现”与“整套策略面对可调整对手的表现” |
| 联动范围分析器 | 点击某个行动后看到其组成，再把组成中的边界组合送入练习 |

**对当前 Demo 的判断。** 已有实验与节点，尚缺面向学习目标的跨案例对照集。仅让 Agent 建立三份报告，不等于用户已经完成一次假设检验。

**取舍。** 我们应把“实验问题、预测、对照条件、观察和结论”保存成作品。官方教程中的 preflop menu 是范围输入/预设能力的证据，不能据此宣称 GTO+ 提供任意完整翻前求解。

## 4. GTO Wizard：学习研究、训练与复盘之间的产品衔接

**资料支持的功能。** Study 提供局面选择、策略与组合细节、动作 EV 比较、双方范围、构成及聚合报告；Practice 支持从翻前到河牌及指定决策练习。[研究模式](https://help.gtowizard.com/study-mode/)、[训练概览](https://help.gtowizard.com/practice-mode-overview/)

Trainer 文档区分整手、单街、单点，以及按行动/频率输入、动作分组和边界决策选择；Range Builder 提供分类构建、锁定、提示、提交与分类对照。[Trainer](https://help.gtowizard.com/how-to-use-the-trainer/)、[Range Builder](https://help.gtowizard.com/how-to-use-the-range-builder/)

表现文档区分其自身评分、EV 损失与频率指标；Analyze 文档描述牌谱分析、回放及匹配/不覆盖条件。[表现指标](https://help.gtowizard.com/measure-performance/)、[Analyze](https://help.gtowizard.com/analyze-mode-guide/)

| 我们应学习的机制 | Riverline 的教学转化建议 |
|---|---|
| 研究和作答是不同任务 | 自由研究可以先看参考；课程中的独立预测先隐藏参考。两种入口共用同一案例，保留暴露记录 |
| Hero、牌类、全范围联动 | 从一手具体牌开始，比较两三手有教学意义的近邻组合，再总结行动范围，不默认要求填写几百组合 |
| 单点/单街/整手与难度分组 | 学习动作类别、学习尺寸和学习连续计划分层；分组后的评分规则也必须明确改变 |
| Range Builder 的分类反馈 | 先练一个类别或一组关键组合，再练范围骨架，完整构建作为进阶专项 |
| 复盘定位问题 | 从原行动中提取学习问题，创建题组，而非把复盘结束于一张 EV 排名表 |
| 表现拆解 | 同时回答“这次动作损失如何”“一段样本的混频是否偏移”“是否能解释并迁移”，不照抄品牌总分 |

**对当前 Demo 的判断。** 页面出口已相连，但题组主要按四类题名生成，缺明确的技能依赖与围绕同一误解的教学步骤。建议将“训练计划”提升为可追溯的学习目标、内容、反馈和复测计划。

**取舍。** 不以多桌和刷题速度作为理解阶段默认目标；不把最高频动作当作唯一正确答案；不借用其品牌分数。Analyze 的近似匹配是该产品文档描述，我们的 Demo 继续坚持严格配对与未覆盖反馈，不悄悄切换为最近邻数值。该页面还含 Coming soon 内容，不能推断其已交付。

## 5. Simple Postflop：学习把求解规格保存为教学材料

**资料支持的功能。** 官方页介绍单挑翻前/翻后求解、树配置与编辑、策略/EV/权益显示、固定策略后的分析及批量牌面计算。[产品页](https://simplepoker.com/en/Solutions/Simple_Postflop)

| 我们应学习的机制 | Riverline 的教学转化建议 |
|---|---|
| 规格与解成套保存 | 每节课绑定一份可重复打开的案例输入和结果版本，不能随案例当前草稿漂移 |
| 翻前与翻后的条件联系 | 翻后起始范围必须来自对应前序行动，或明确声明为新研究假设 |
| 固定策略研究 | 把“发现基准策略”与“给定对手偏差后的响应”分开授课，结论附假设 |
| 批量材料 | 教学作者构造基础例、相似例和反例，不能只是增加样例数量 |

**对当前 Demo 的判断。** 版本与来源已有基础；内容尚缺教学作者可审阅的成套结构和发布状态。下一步无需实现真实求解，可先保存人工编写、审阅的教学包。

**取舍。** 官方页含历史系统需求和宣传文字，不能据此比较今天的计算速度、平台支持或教学效果。本项目不因此选定未来引擎。

## 6. Simple GTO Trainer：学习区分单点纠错与连续计划

**资料支持的功能。** 官方介绍预设/自定义训练及与求解结果联动；模式说明区分 Drill、Regular Train、Regular Play，且 Cloud/Custom 的支持矩阵不同。[介绍](https://simplepoker.com/en/Help/Intro_58)、[模式说明](https://simplepoker.com/en/Help/Training_Modes_62)

| 我们应学习的机制 | Riverline 的教学转化建议 |
|---|---|
| Drill 针对一个动作节点 | 用于澄清一个概念或某个边界，错误之后就地对照 |
| 连续行动线训练 | 用户必须对后续条件制定计划，不能每道题都从一个没有历史的新节点开始 |
| 不同反馈时机 | 教学模式可立即提示；独立测验先固定全段作答，再给反馈，避免中途答案改变后续表现 |
| 自定义求解成果转训练 | 题目必须引用明确的结果、输入、允许信息与评价规则，不只是跳转到某个案例 |

**对当前 Demo 的判断。** 已有固定会话和辅助身份，但“分支补全”仍以静态节点范围填写为主，不能代替整条行动线的实际决策训练。

**取舍。** 练习中的手牌输赢单独保留为结果，不能用一次盈利代替决策评价。不同训练模式应共享作品和版本，却各自定义何时显示答案。

## 7. HRC：学习先确认研究问题与结果可信边界

**资料支持的功能。** 官方文档涵盖翻前/翻后树、下注设置、频率锁定、采样/子树采样与收敛指标；另有 ICM/FGS/赏金模型说明。[树配置](https://www.holdemresources.net/docs/tree-config/)、[采样](https://www.holdemresources.net/docs/monte-carlo-sampling/)、[赏金模型历史说明](https://www.holdemresources.net/blog/hrc-1v4-update-knockout-bounty/)

频率锁定控制到达节点时的行动频率，与手工指定具体组合不同；翻后文档明确列出抽象和功能限制，并说明从翻前创建的独立翻后计算不会随原输入后来修改而更新。[频率锁定](https://www.holdemresources.net/docs/frequency-locks/)、[翻后说明](https://www.holdemresources.net/docs/postflop/)

| 我们应学习的机制 | Riverline 的教学转化建议 |
|---|---|
| 树定义会改变研究问题 | 引导用户先检查“允许哪些行动”，再讨论策略对错；未提供的动作不等于真实扑克中不可行 |
| 不同价值模型 | 现金局、chipEV 与赛事奖金效用各自有输入和单位，不能统一成一个跨模型总分 |
| 抽象与收敛信息 | 结果卡显示可解释粒度和质量，质量不足时允许观察但不做精细频率考核 |
| 频率锁定和组合锁定 | 前者是整体约束，后者是具体策略假设；即使都叫“锁定”，领域对象与解释也应不同 |
| 输入继承及独立快照 | 课程解释“这个翻后范围从哪里来”，上游修改后给复核提示，旧题仍引用旧输入 |

**对当前 Demo 的判断。** 当前只有组合式 Node Lock 示例；不能声称已经具备 HRC 式频率锁定求解。MTT 仍是预览，也没有真实采样。现有质量状态可作为教学信息边界的底座。

**取舍。** 不把 heuristic 收敛指标等同于严格误差界。HRC 的翻后模式不宜笼统理解为独立 HU Solver 的替代；也不能将其描述成仅支持 Push/Fold。暂不扩大我们的赛事实现范围。

## 8. MonkerSolver：学习分类视图，同时警惕过度泛化

**资料支持的功能。** 官方介绍 Hold’em/Omaha、多玩家、不同起始街道、自定义树及抽象；Views 可按类别汇总 EV、组合数和频率，分类有优先顺序。[产品页](https://www.monkerware.com/solver.html)、[抽象说明](https://www.monkerware.com/compare.html)、[Views](https://www.monkerware.com/views.html)

| 我们应学习的机制 | Riverline 的教学转化建议 |
|---|---|
| 将巨大组合空间归类 | 先比较有意义的类别，再下钻具体花色；分组规则与“其他”类可检查 |
| 多人研究条件明确 | 单挑结论进入多人场景前，要求重新核对玩家、范围和价值目标 |
| 抽象降低复杂度 | 区分“仅为显示合并类别”与“求解本身把手牌并桶”；二者对可解释性的影响不同 |
| 分类优先级 | 展示类别互斥还是重叠，不能把重叠类别直接相加，导致范围超过 100% |

**对当前 Demo 的判断。** 目前三人场景和示例构成只是预览，没有真实多人均衡或抽象实现。当前索引生成的牌类标签不能成为教学分类依据。

**取舍。** 借鉴可折叠的复杂度与分类工具；不为当前教学主线引入 Omaha 或任意多人求解。对抽象掉的花色信息，AI 不得给出精确阻断解释。

## 9. FlopzillaPro：学习从“范围中有什么”走向策略问题

**资料支持的功能。** 官方教程列出成牌/听牌统计、组合数/比例、加权过滤、类别重叠、单手/范围及多方权益、后续牌影响、范围预设和 GTO+ 联动。[官方教程文字目录](https://www.flopzilla.com/videos/)

| 我们应学习的机制 | Riverline 的教学转化建议 |
|---|---|
| 范围构成而非只有动作颜色 | 在看参考前，让用户判断双方哪些类别多、哪些类别少，并定位到实际组合 |
| 类别、组合数与权重联动 | 回答“这个类别怎样行动”和“这个行动由什么类别组成”两个不同问题 |
| 权益和后续牌 | 让用户先预测范围受什么牌面影响，再显示配对证据；不将权益直接翻译为应该下注 |
| 过滤和分组 | 让用户选出候选价值牌/诈唬牌，比较近邻组合，降低一次理解全范围的负担 |
| 分析器与 Solver 联动 | 用户提出结构假设后，才用行动参考检验；两者的数据来源与能力标签分别显示 |

**对当前 Demo 的判断。** UI 已有范围构成视图，但缺可信的分类资产、双向条件比例与围绕结构的预测题。增加图表而不设计学习动作，仍只是更多信息。

**取舍。** FlopzillaPro 是范围/权益分析工具，不能将其统计功能表述为自动给出均衡行动策略。其首页本轮超时，研究依据为成功读取的官方教程目录，未观看视频或运行计算。

## 10. 综合：我们应改变什么

以下均为本项目设计推论，不是参考产品的现成功能、竞争排名或已证明的教学效果。

| 参考中值得借鉴的部分 | Riverline 应新增或强化的学习动作 | 目前差距 |
|---|---|---|
| Pio 的树、节点与指标语义 | 用户预测范围如何到达下一节点，并验证 | 节点可看，范围传播与预测不足 |
| GTO+ 的实验与多牌面组织 | 写假设、做受控比较、找反例 | 有报告，缺结构化学习实验作品 |
| Wizard 的浏览/训练/复盘衔接 | 同一问题从 Hero 读参考到局部构建、独立迁移 | 有出口，缺学习目标与难度路线 |
| Simple Postflop 的规格/成果 | 教学内容固定输入、参考与解释依据 | 有快照，缺内容审核与发布流程 |
| Simple Trainer 的模式划分 | 单点纠错与连续测验使用不同反馈时机 | 分支填写还不是连续行动训练 |
| HRC 的模型/质量边界 | 学生能识别什么时候不能比较或不能评分 | 运行质量已有，教学资格未定义 |
| Monker 的分类/抽象边界 | 从类别归纳，再检查精确组合和反例 | 示例分类无教学可信度 |
| FlopzillaPro 的结构阅读 | 观察双方构成，解释而非仅记忆矩阵 | 范围构成还未成为学习过程 |

优先级建议：先建立教学内容与证据边界，再完成一条 Hero→范围→条件变化→独立迁移的教学旅程，同时承接已记录 PF01/PF02。之后扩展反例、连续行动线、实验和复盘驱动的复习；不以更多页面或更复杂求解参数作为下一轮目标。

## 11. 学习设计的证据与待验证部分

Butler（2010）的原始研究在文本学习实验中比较重复测试与重复阅读，观察了保持与推断题迁移。这支持我们研究“先尝试、反馈、再在新题检索”的设计方向，但不能推出同一方案已被证明能提高扑克水平。[研究论文](https://andymatuschak.org/files/papers/Butler%20-%202010%20-%20Repeated%20Testing%20Produces%20Superior%20Transfer%20of%20Learning%20Relative%20to%20Repeated.pdf)

Riverline 的课程顺序、间隔安排、解释评分、错误分类和推荐规则都仍是待体验验证的产品假设。Demo 可以真实保存作答和安排复测，但模拟数据下不能声称已经测得策略能力提升。
