# Stub/Mock 合同与场景目录 v0.1

状态：设计合同已由 D01–D08 的本地类型与命令实现承接。下列通用类型仍是设计表达，不宣称存在同名 API；实际实现与配对边界见第 10 节。

## 1. 模拟原则

stub 用来提供固定能力或结果；mock 用来模拟有状态交互和任务过程。本期共同目标是让真实 UI 操作产生一致、可追踪的演示成果。

| 能力 | 应真实执行 | 使用模拟 |
|---|---|---|
| 编辑与保存 | 选择、批量、混频、锁定、undo/redo、版本、本地导出 | 初始案例内容 |
| 范围显示 | 组合展开、过滤、死牌排除、权重汇总 | 示例输入范围；不推断真实对手范围 |
| 评价 | 未完成检查、概率检查、对合成参考的频率差异 | EV、权益、最佳回应、可利用性报告 |
| 规则/回放 | 表单校验、已定义时间线和信息投影 | 任意牌局裁决与未来状态 |
| Solver | 排队、进度、取消、错误、输入绑定 | 所有求解数值与策略结果 |
| Agent | 命令调用、patch、分支、制品登记、预算检查 | 意图匹配后的计划、推理、解释 |
| 知识 | 本地标签/关键词匹配与来源导航 | 自写精简示例知识库，不调用模型 |
| 学习记录 | 保存作答、提示、题组推进、历史引用 | 示例掌握度、学习预测和推荐理由 |

本地结构运算只表示操作一致性，不代表完成了完整扑克业务计算。

## 2. 标准结果信封

```typescript
type DemoResult<T> = {
  status: 'available' | 'uncovered' | 'unsupported' | 'failed';
  mechanism: 'local-state' | 'local-calculation' | 'scripted';
  dataKind: 'user-input' | 'synthetic';
  scenarioId: string;
  fixtureVersion: string;
  inputFingerprint: string;
  inputRefs: {
    caseRevisionId: string;
    nodeId?: string;
    rangeRevisionId?: string;
    treeRevisionId?: string;
    policyRevisionId?: string;
    assessmentSpecId?: string;
  };
  limitations: string[];
  payload?: T;
  reason?: string;
};
```

业务制品使用 ID，时间信息与运行序号另存。fingerprint 对规范化输入生成；不能仅以牌面、caseId 或文件名识别结果。

available 要求 payload 与输入适配；uncovered 表示模拟目录尚无对应数据；unsupported 表示声明的能力不支持；failed 表示预期支持但本次执行失败。三者不得互换。

## 3. 自定义输入与报告匹配

1. 任意表单输入均可保存为草稿；不保证任意输入有预制报告。
2. 用户修改策略时，结构与合成参考的频率差异可以实时重算，报告明确只表示差异。
3. EV/对抗性报告仅用于其预置的策略、范围和树快照，含可识别的版本或完整指纹。
4. 未匹配时，显示“当前自定义输入无模拟收益报告”，保留可用的结构和差异评价。
5. 可打开另一个“示例报告”，但其独立标题和上下文不可改成当前输入。
6. AI 剧本的预设改进分支有自己完整的输入与结果配对，用户继续编辑后按上述规则处理。
7. fixture 作者设定的趋势仅演示报告形态，不宣称扑克规律、因果关系或策略优劣已被验证。

## 5. 内容资产与最低数量

- 至少 10 个可打开的场景入口，对应 S01–S10；可共享组件，不共享不适配结果。
- S01 至少包含两个可编辑策略版本、两个对应报告和一个独立 Agent 分支。
- S02 至少包含三条有意义的延续分支，另有未覆盖分支状态。
- 至少 8 个自写理论条目：范围优势、坚果分布、极化、混合、阻断、过牌保护、尺度与后续、评价条件。
- 至少 4 类练习入口：构建、补全、诊断、比较；每类有一份完整样例。
- 至少 3 条 Agent 任务脚本：诊断并改进、对照实验、生成训练计划。
- 至少 1 份可导入复盘样例、1 份不完整样例、1 份错误 JSON 用于恢复演示。

数量用于保证展示覆盖，不作为产品学习效果指标。内容在实现时自行编写，不复制参考产品的付费策略或大段理论原文。

## 6. 故障配置

每次运行从 DemoContext 读取 outcome 和速度；每个 job 固定自己的配置快照，之后切换设置不回写旧任务。

| 配置 | 预期表现 |
|---|---|
| ideal | 完整理想状态机与可查看成果 |
| slow | 等待更明显，可跳过动画等待 |
| fail-once | 首次运行失败；显式重试成功 |
| resource-limit | 预检阶段返回示例资源限制；修改规格再提交 |
| incomplete-quality | 完成但目标未达，结果标记示例质量状态 |
| unsupported | 显示能力边界，其他编辑仍可用 |
| conflict | Agent patch 基于旧版本，显示对比/新分支 |
| interrupted | 刷新恢复后说明执行被中断，用户重播 |

cancelled 由用户操作触发，不在无用户操作时随机出现。输入变更由实际修订触发，结果继续绑定旧版本。

## 7. Agent 脚本约定

支持任务卡与明确意图短语，展示为“脚本化 Agent 演示”。每步包括 tool、输入版本、状态、简短观察、成果引用。

示例任务：读取 S01 → 查找两个理论条目 → 新建改进分支 → 给指定组合应用 patch → 提交策略 → 请求模拟求解与评价 → 生成带引用报告。

任务取消后不再执行下一命令。重试不重复创建既有成果。预算是可见的演示额度，不显示为真实计费。没有匹配意图时给出支持列表，不生成虚假工具轨迹。

## 8. 对导出和回放的要求

JSON 包含 schemaVersion、fixtureVersion、场景 ID、制品引用、用户覆盖层及来源标签。Markdown 报告保留研究条件、版本、评价口径、辅助状态与 synthetic 说明。

导入缺少匹配 fixture 时保留用户内容、标注引用缺失，不重新生成看似原有的数值。重播理想场景前固定 DemoContext，并避免覆盖已有用户案例；使用新 session 或显式重置。

## 9. D01/D02 阶段的交付与执行状态（历史）

场景、知识、Agent 脚本与题目分别在对应纵向任务中完成，不等到整版最后补内容。具体分配见 [第一版开发任务设计](demo-v1-task-design.md) 的内容资产表。

用户已授权第一轮 D01。当前 S01、MockSolverAdapter、基础频率评价和相应测试已实现；S02–S10、完整结果信封/故障配置与其他适配器仍为后续任务。当前求解/报告模型是完整合同的最小子集，不宣称整版模拟目录已经交付。

### D02 增量

`SolveInput` 现在同时固定双方输入权重；输入指纹包含规范化双方权重、局面与提交策略。S01 参考需要条件和双方权重同时匹配；修改任一方范围时返回 uncovered，不沿用原数值。历史求解始终使用该版本自己的范围。没有范围数据的旧版本按原 S01 权重解释。

局面库的“双版本示例”通过同一应用命令建立独立案例：V1 作者分配、V2 全过牌，各有固定版本、作业和合成报告，两版都带 example 辅助标记。创建该示例不覆盖用户已有案例。收益模板仍只对匹配输入与分配开放。

编辑语义：死牌不可选；输入权重 0 表示排除；行动概率 0 保留组合；未填写单独统计；部分概率允许保存草稿，提交要求每个活跃组合合计 100%。单节点尚无后续可达性模型，未覆盖不冒充不可达，实际连续节点与可达状态由 D04 完成。

## 10. 第一版完整实现与配对边界

D01/D02 记录保留历史语境；当前已完成 D03–D08。实际状态见 [整版交付](demo-v1-delivery.md)。所有输出都是本地作者合成资产，没有下载或复制参考产品求解数据。

- S01 保留原输入与参考；S02 有三条后续研究路径及未覆盖/不可达节点；S03 有独立迁移输入和参考；S04/S05 有自己的 3-bet/河牌行动集合。
- S06 基准、overfold、sticky 各自有完整输入与参考，锁定记录玩家、节点、组合/频率、剩余补全约定及固定基准版本；报告趋势人为设定。
- S07 完整/缺失样例支持行动前提取；未知手牌原文不自动解析。S08 翻前、S09 三人范围、S10 MTT/ICM 有各自可配置预览和报告，超出配对输入不返回定量示例。
- K01–K08 为自写知识，带背景来源和使用条件。AT01–AT03 为确定性脚本，运行实际应用命令。四类练习均有可完成作答、提交和反馈，S03 复测不借用旧场景数值。
- ideal、slow、fail-once、resource-limit、incomplete-quality、unsupported 以及 normal/fast 速度已连接设置和作业。Agent 预算是演示额度，无计费。

参考匹配要求语义输入完整一致，包括全部玩家范围和锁定假设；仅标题、随机范围 ID 或行动显示顺序变化不会误判。未覆盖、零范围、质量不足、失败分别表示，不用零 EV 代替未知。

结构校验与参考频率差异在本地计算；固定模型 EV/对抗数值只对明确配对的参考/被动策略模板开放。任意用户策略不会被套用这些模板数值；多路/ICM 不支持的对抗评价保持未知。各场景币值/效用单位独立，禁止混合汇总。

完整 JSON/Markdown 保留输入/固定版本/来源/辅助身份/作答和任务引用。导入进行 schema、引用及组合一致性校验，创建新副本；缺失 fixture 的既有数值封存为未验证证据。文件导入限制 20MB，大文本不强制灌入编辑框；原包保留。重播产生新对象，不替换旧历史。
