# Riverline 教学产品调整方案 v0.1

日期：2026-11-12（Asia/Shanghai）。状态：研究后的设计建议，待产品评审与后续任务细化，尚未实施。本次授权是分析各 Solver 并形成教学方向，不启动新一轮应用开发。

依据：[逐产品分析](solver-teaching-research.md)、[现有实现与边界](demo-v1-delivery.md)、[已记录翻前反馈](product-design.md)。原 D01–D08 合同与 `baseline/demo-v1.0` 保留，不把本方案写成已实现功能。Hero 自定义合法尺度与混合频率继续暂缓。

## 1. 调整的核心判断

建议将产品定位进一步明确为：**以 Solver 证据为基础，帮助学习者从具体手牌形成范围策略、解释适用条件，并在新局面独立决策的教学产品。**

专业研究工作台保留自由探索。教学入口围绕一个明确问题组织步骤，而不是把求解器各项功能平铺给学生。两种模式共享输入、节点和成果引用，答案显示规则不同。

用户完成一节课后，应留下的不只是一份“更接近参考”的策略，还应包括：原先的判断、关键证据、修正后的解释、一次独立迁移作答，以及哪些情形仍未掌握。这里的“应”是新设计目标，不是已有学习效果声明。

## 2. 当前 Demo 的真实教学缺口

| 已有基础 | 尚缺能力 | 为什么影响教学 |
|---|---|---|
| Solver、多视图、全范围参考 | 学习问题和阅读顺序 | 用户可能看了很多数字，却不知道本次需要学会什么 |
| Hero→同类→全范围入口 | 有目的的近邻组合对比与范围角色 | 仍可能只记住选中的手牌，而无法归纳 |
| 四种练习可完成 | 技能目标、分级负担、连续行动与策略推理题 | 题型名称不同不等于训练了不同策略能力 |
| 独立/辅助与首次 Attempt | 具体答案暴露记录、留出题和延迟复测 | 当前独立只说明本次没有调用辅助，不保证没见过题 |
| 固定输入和节点 | 由前序行动得到的到达范围及条件传播 | 有节点跳转仍可能误学“每个街道重新拿初始范围” |
| 实验分支与三份报告 | 预测、变量控制、反例和结论修订 | Agent 自动产出报告可能替代用户思考 |
| 8 条知识、Agent 脚本 | 逐条解释对应的证据及“无法解释”状态 | 一段相关理论不能证明它解释了当前组合 |
| 学习记录 | 按技能、题目覆盖、辅助与迁移拆解的证据 | 做了多少题不能代替学会了什么 |
| 翻前 S08 | 完整翻前学习流程与翻后衔接 | 翻前没有成为范围形成的起点，见 PF01/PF02 |

实现核对依据：`src/fixtures/scenarios.ts` 中的部分参考、权益/EV 和类别采用序号生成；`src/modules/product/learning.ts` 的诊断样例目前主要检查概率合计，比较样例主要检查“频率不等于 EV”。它们适合验证流程和概念边界，不能代表已具备完整策略诊断。

**最优先的内容问题：当前业务数据是演示资产，不是可信的真实 GTO 教材。** 不能在现有索引生成频率上加一层 AI 解释，就称作教学升级；也不能因为有官方背景链接，就宣称这些本地数字得到官方支持。

## 3. 内容先具备教学资格

提出三层身份，分别控制可以展示和评价什么：

| 内容身份 | 可以做什么 | 不可以做什么 |
|---|---|---|
| 流程合成示例 | 展示操作、任务、版本、评分形态，明确是虚构结果 | 将其频率、EV 或类别解释为真实扑克最优策略 |
| 人工编写并审阅的概念教学样例 | 讲清特定概念、展示自洽的对照/反例；保留作者和审核版本 | 宣称经过 Solver 数学验证，或把示意数值推广为普遍规则 |
| 未来合法来源且条件/质量核验过的真实解 | 在匹配范围内支持数值研究与评分，明确引擎/版本/质量/误差限制 | 脱离输入解释、混用单位、忽略抽象或将低质量结果精细评分 |

本 Demo 下一次仍使用前两层，**不接入第三层的真实业务**。人工审阅不使合成数据变成均衡解。找不到配对解释时，应显示“仅有策略示例，当前缺少解释证据”。

建议每个教学包固定：目标、先修概念、输入、节点、参考身份、动作定义、类别定义、解释主张、支持/反驳证据、对照条件、题目、允许信息、评价规则、反例、迁移题、审核记录。修改任一关键资产发布新版本，原作答不改写。

类别需要核对实际牌面与手牌，或明确声明为纯示意分组。展示“听牌/成牌”前逐项审核；本期无需真实规则引擎，可以使用自写并审阅的固定分类清单。重叠类别和互斥分区分别建模。

## 4. 两种入口，共用一套作品

| 入口 | 默认体验 | 参考与提示规则 |
|---|---|---|
| 自由研究 | 选局面→读参考→切视图→沿节点探索→实验→按需训练 | 可以先看答案；记录具体参考暴露，转测验时不宣称题目未见 |
| 引导学习 | 目标→先判断→查证据→修正→练习→迁移/复测 | 先固定预测；提示逐级提供，答案揭示影响辅助身份 |

首页建议突出“继续学习一个问题”和“自由研究”两个明确入口。教学阶段不强制全范围输入；专业用户仍可直接打开原工作台，不必完成课程才能读解。

## 5. 一条完整教学旅程

下面是一节课的建议形态，示例问题不预设具体手牌必须采取某个动作。所有数值和解释需来自对应内容包；没有证据则停在可解释边界。

```mermaid
flowchart LR
  A[明确问题与条件] --> B[Hero 预测与理由]
  B --> C[比较关键近邻组合]
  C --> D[联系行动范围和双方范围]
  D --> E[改变一个条件并先预测]
  E --> F[查看配对证据并修正]
  F --> G[完成局部策略作品]
  G --> H[独立迁移题]
  H --> I[证据记录与延迟复测]
```

| 步骤 | 用户做什么 | 产品展示和保存什么 | 避免的误区 |
|---|---|---|---|
| 目标 | 确认本次理解的是范围角色、后续牌还是翻前回应 | 一句话目标、适用条件与先修提示 | 一开始铺出所有 Solver 参数 |
| Hero 预测 | 选具体牌，给行动判断、简短理由和可选信心 | 先保存预测，允许“不确定” | 看完答案再补写原先的理由 |
| 近邻比较 | 比较同牌类不同花色或同结构的其他牌 | 同节点配对证据、相同/不同因素 | 看见花色不同就自动编造阻断原因 |
| 范围联系 | 选出若干同角色组合，给出行动范围骨架 | Hero 所在类别、行动组成、对手继续范围 | 将一手牌的行为当全范围规律 |
| 条件实验 | 预测改变位置/一张牌/对手假设会怎样 | 变量清单、冻结基准、配对比较 | 同时改变多项却声称找到唯一原因 |
| 修正 | 修改判断并写一句有条件的结论 | 原判断、修正、支持和反例并列 | AI 一键覆盖用户作品 |
| 局部构建 | 为关键组合或一个类别构建策略 | 明确评分范围，原未作答部分不算错误 | 为减少工作量偷偷将参考当用户作答 |
| 迁移 | 隐藏答案，在未暴露的新题独立作答 | 固定 Attempt、暴露身份、题目条件差异 | 原题重做被称作迁移 |
| 复测 | 后续再次回答同技能的新题或保持题 | 到期原因、原证据、独立/辅助历史 | 以一次修正后答对宣称掌握 |

## 6. 从 Hero 到全范围的低负担构建

建议采用递进深度，用户可选择需要的层级：

1. **具体手牌决策。** 选择动作，说明理由；未来完整产品再承接 Hero 频率和自定义尺度，不在本次扩大暂缓需求。
2. **关键组合小组。** 一次处理约 3–6 个经过作者选择的典型/边界组合，不按列表序号任意抽取。
3. **类别或范围骨架。** 为某个明确类别分配动作，或者选择哪些类别构成价值/诈唬/防守部分；分类可重叠时不相加当总量。
4. **局部补全。** 系统预填一部分并标“题目给定”，用户只补指定缺口；给定和用户填写分别保存，评分只计算要求部分。
5. **完整范围构建。** 保留为独立高级训练和研究作品，不作为每节课的门槛。

“参考补全”和“用户批量填写”是不同来源。范围构建任务应显示用户实际填写比例、参考辅助比例及题目给定比例，不能以补全后的完整度计算用户掌握度。

## 7. 范围解释应能回答的两个方向

用户点击一个类别时，回答“这类牌如何行动”；点击一个行动时，回答“这个行动由哪些牌构成”。两种比例的分母不同，界面上明确写出：

- 类别内行动比例：该类别选择这个动作的加权量 / 该类别总加权量。
- 行动内类别占比：该动作中属于这个类别的加权量 / 该动作总加权量。

分母为零时显示无数据；重叠类别不保证占比合计 100%。Demo 的组合权重统计明确标“按输入权重汇总”，不能冒充已考虑双方手牌相容性、移除效应和节点到达概率的真实频率。此区别在 Pio 的[数字文档](https://site.piosolver.com/docs/viewer/numbers_in_piosolver/)中有直接说明。

建议解释面板分三层：**观察**（本结果显示了什么）→**解释假说**（可能的概念与适用条件）→**验证**（配对对照是否支持、有什么反例）。不能把观察到的相关性直接命名为原因。用户能从每条解释跳到具体组合、固定节点和对照版本。

## 8. 评价不能再围绕一个“像不像参考”的总分

Pio 文档说明精确均衡中使用的混合动作具有相同 EV，而近似解存在差异；改变整套混合频率也可能改变对手可利用的空间。一次动作的条件 EV 与整套策略面对响应时的表现需要分开。[概念 FAQ](https://piosolver.com/docs/faq/gto_concept/)

建议新增以下评价契约，不照抄参考产品品牌分数或阈值：

| 评价对象 | 应显示 | 不能据此推断 |
|---|---|---|
| 输入/分配结构 | 覆盖、概率合计、死牌与范围一致性 | 概率合法就代表策略好 |
| 单次行动 | 匹配固定对手与后续策略下的动作 EV 差；没有配对数据就不显示 | 低频动作一定错，或最高频必然是唯一正确答案 |
| 同节点策略分布 | 各组合/类别的频率偏差、样本数和评价范围 | 频率差异等于可利用性或真实盈利损失 |
| 范围作品 | 关键类别组成、覆盖、参考辅助比例与来源 | 总下注频率接近就代表组合选择正确 |
| 理解与解释 | 条件是否识别、引用是否相关、有无反例；自由文本先保存待审阅 | 文本相似或语言流畅等于理解正确 |
| 连续行动 | 各节点作答与范围来源，哪些错误在上游 | 把嵌套节点的 EV 损失直接相加就是整手可利用性 |
| 学习迁移 | 未暴露题表现、延迟表现、辅助状态与样本覆盖 | 一次答对就已经掌握或真实胜率上升 |

频率误差可采用明确命名的分布距离，例如按固定组合权重对每组合行动分布的总变差距离做平均。其量纲是比例，不是 bb；只比较相同动作映射、输入和规定评分范围。不同近似解可能存在策略差异，不能用精确匹配某个解作为唯一目标。

动作 EV 差若使用 `max Q_ref(a) - Q_ref(userAction)`，必须说明 `Q_ref` 的对手/后续策略固定条件、单位、质量与来源。它不等于用户整套策略重算后的 EV，更不等于对抗可利用性；没有真实重算或完整配对 fixture 时禁止补出这些数值。小于结果可信分辨率的差异只标“难以区分”，不制造精确错题。

入门动作分组是教学评价投影，不是偷偷改求解树：组内频率可以相加，组内动作 EV 不自动做无依据平均。所有评分固定 `evaluationPolicyVersion`，修改规则生成新评价，不覆盖旧记录。

## 9. 翻前调整进入教学主线

承接用户已确认的 PF01/PF02，建议首先选有限条件的课程族，逐步实现，而非承诺任意位置和任意行动树：

| 课程族 | 要学会什么 | 与后续连接 |
|---|---|---|
| 位置与 RFI | 同一手牌在不同位置的范围角色，不把表格当无条件答案 | Open 后对手回应 |
| BB 面对 Open | 弃牌/跟注/3-bet 的范围分工 | 跟注进入匹配 SRP 翻牌 |
| 面对 3-bet | 继续范围、4-bet 与跟注的分工 | 匹配 3-bet 底池翻后 |
| 前序行动形成范围 | 解释为何某组合不在当前节点，区分初始范围和到达范围 | 后续牌比较与防守 |

第一包建议只深做一个翻前到翻后的预置树族，再扩展其他位置与 3-bet/4-bet 对照。每条边附固定输入与来源；无 fixture 不自动推导数值。修正库页面固定“翻牌 · 现金局”标签应随入口调整一并处理。

演示中可以使用一名玩家自身行动频率的逐步权重示意，但必须标出忽略项；不能将简单相乘称作包含全部移除效应的通用范围传播。转入独立翻后研究时，清楚说明继承的是哪一版本，而不是承诺原输入后续修改会联动全部旧题。

## 10. Agent 从“代做研究”增加“组织学习”职责

保留已有三个脚本和真实命令能力，增加教学意图时遵守以下阶段：

| 阶段 | Agent 可做 | 应保留给用户的行为 |
|---|---|---|
| 独立预测/测验 | 说明题目与输入含义；通过允许投影查询 | 作答、理由、信心；不运行可泄露答案的研究工具 |
| 引导提示 | 按提示级别指向条件、类别或对照，记录辅助 | 自己提出候选动作和解释 |
| 提交后解释 | 调用当前节点结果/类别/理论/对照，形成带引用的解释 | 决定是否修正作品，标注不理解的点 |
| 条件实验 | 固定基准、创建分支、核对改动、运行示例 | 运行前先预测，运行后判断支持程度 |
| 迁移与复习 | 根据明确错误候选和题库标签推荐题目并说明理由 | 在隐藏参考的新题独立回答 |

解释记录建议包含 `claim`、`evidenceRefs`、`conditions`、`counterexampleRefs`、`limitations` 与内容身份。无证据时可说明缺失、建议能做的对照，不能生成更具体的扑克结论。

完整产品未来的 LLM 也只调用领域工具，不拥有评分正确性或教学真值。Demo 采用确定性分支及自写解释模板；用户没有被提示到的错误原因，不应由系统臆测成心理缺陷。“错误概念”先标候选，结合新题验证。

## 11. DDD：将教学过程作为核心领域

以下是职责建议，不要求下一轮立刻重组物理目录或引入微服务。

| 上下文 | 拥有什么决定权 | 复用/调整 |
|---|---|---|
| 研究与策略作品 | 输入、节点、范围、版本、用户策略、实验 | 复用 Study/Strategy，补到达范围引用和受控比较规格 |
| 求解与结果 | 计算规格、任务、结果、来源/质量、能力限制 | 保留 SolverPort/mock；不拥有“学生已掌握”结论 |
| 教学内容 | 学习目标、概念关系、课程包、对照/反例、题目定义、审核发布 | 新增明确内容模型；Knowledge 继续维护知识主张/来源 |
| 学习过程 | 课程运行、阶段、提示、暴露、作答、复测计划、证据 | 扩展 Learning，防止仅按题型堆列表 |
| 评价 | 固定规则、可评分资格、频率/EV/解释反馈 | 从通用研究评价分出教学判定契约，允许“不足以判定” |
| 复盘 | 原始牌谱事实、行动前视角、提取和学习问题候选 | 复用 Review，不将推断写回原始事实 |
| Agent 编排 | 按目标调用命令、权限投影、工具轨迹与成本 | 不直接写内容真值、分数或 mastery |

建议对象与不变量：

- `LearningObjective`：可观察的技能目标、先修、适用条件与证据要求。目标不是一句宽泛的“掌握 GTO”。
- `LessonPackageVersion`：冻结教学步骤、输入/结果引用、解释、对照、反例、迁移池与规则；发布后不改写。
- `LessonRun`：引用内容版本，保存阶段和预测/修订引用；恢复后仍打开同一版本。
- `ExerciseDefinitionVersion`：规定实际评分范围、给定/用户部分、允许信息、难度投影和评分政策。
- `Attempt`：扩展现有不可变作答，保留最初判断、信心、辅助、题目版本和结果版本；修订产生新记录。
- `ExposureRecord`：记录看过哪份答案/组合/节点/提示及时间。它只能说明应用可观察的暴露，不能证明用户在外部未见过题。
- `EvaluationArtifact`：引用固定 Attempt、规则与证据，可包含 unknown/unsupported/low-quality；不是强制输出总分。
- `SkillEvidence` / `ReviewSchedule`：聚合作答引用和复测安排，展示样本与局限，不保存未经证据支持的确定掌握等级。
- `HypothesisExperiment`：冻结预测、变量与对照规格；观察和结论分开，原始输入与用户修订均保留。

命令建议：`startLesson`、`recordPrediction`、`requestHint`、`revealEvidence`、`submitAttempt`、`reviseAttempt`、`createContrastExperiment`、`recordConclusion`、`assignTransfer`、`scheduleReview`。复用同一命令层、expectedRevision/幂等标识、存储与导入契约；UI 和 Agent 不能各自维护课程状态。

可发布领域事件包括预测已记录、提示已使用、证据已揭示、作答已提交、评价已登记、迁移已分配。事件是边界内的状态事实，不表示需要引入消息系统。提示与答案揭示应在同一事务内更新暴露和辅助身份，避免查询间隙漏标。

## 12. 内容资产的最小完整单元

建议先制作两个可审阅教学包，而非扩充所有街道。具体数量是本方案的工作默认，后续任务可调整；当前均未制作。

| 教学包 | 内容和学习目标 | 最小资产建议 |
|---|---|---|
| A：翻前范围到翻后角色 | PF01 的一条预置树，识别 Hero 与到达范围，理解前序行动影响 | 1 个基础树族、2 个受控对照、1 个反例、3 道不提前揭示的迁移题、1 个后续复测候选 |
| B：同一类手牌为何不总同样行动 | 一个已有翻后案例，比较近邻组合、类别构成和一张后续牌变化 | 同样的对照/反例/迁移结构，条件与数据独立，不用不同标题重复同一题 |

包 A、B 都包含：动作/概率结构审核、公开信息和死牌核对、类别清单、解释可引用证据、明确未知项。若没有足够自洽的数值依据，可只教条件识别与推理流程，不能硬编精确 GTO 结论。

## 13. 后续开发建议顺序与验收

这些是新的候选工作包 TE01–TE08，均为设计建议、未实施；不重编号或追认原 D01–D08。以完整学习旅程为组织单位。

| 顺序 | 工作项 | 可观察验收 |
|---|---|---|
| TE01 | 教学内容资格、目标与包版本 | 明确示例/概念样例身份；解释逐条可定位证据；无依据的数值/原因不展示为真实结论 |
| TE02 | 引导学习与 Hero 局部构建 | 不必填全范围就可完成预测、近邻比较、类别作品与修正，给定/用户/参考分开 |
| TE03 | 翻前核心旅程及入口修正，承接 PF01/PF02 | 至少一条翻前→回应→匹配翻后的预置路径与专项练习；上游来源和未知分支清楚 |
| TE04 | 多维反馈与解释引用 | 合法性、频率、动作 EV 和解释分开；固定规则；不将低频动作一律判错 |
| TE05 | 迁移、答案暴露与复测 | 同技能的新题不泄露参考；暴露/辅助持续；原题重做、迁移、延迟复测分别记录 |
| TE06 | 条件实验、连续行动与聚合反例 | 用户先预测再运行，比较条件可核对；连续测验反馈不污染已声明独立部分 |
| TE07 | 教学 Agent 与复盘驱动计划 | Agent 不代填独立作答；从真实记录提出有证据的错误候选和对应题组 |
| TE08 | 内容工具、恢复与整体验证 | 内容/规则版本升级不改旧 Attempt，导入保留课程/暴露引用，原 D01–D08 回归可用 |

TE01–TE05 建议作为下一次升级的第一条完整教学闭环；TE06–TE08 按消费者前移必要底座，再扩展。实际开发仍遵守既有授权与新任务范围，本轮只提交研究和方案。

## 14. 如何判断教学方向是否更好

Demo 阶段先验证产品机制，而非宣称教学有效：

- 用户能否说清学习目标与当前条件，找到对应证据，而不依赖逐页口头引导。
- 能否从一手牌完成一个范围层面的判断，且不需要手填全部组合。
- 是否能区分自己的预测、题目给定、参考、Agent 建议和修正版本。
- 隐藏答案的新题能否实际作答、提交和追溯；unknown 不显示成零损失。
- 是否识别条件变化会使原结论不适用，能打开反例而不是只看正确模板。

未来有可靠内容和真实用户后，再评价同技能前后测、留出题迁移、延迟保持、重大错误率、信心与正确率是否匹配。独立/辅助、原题/新题、场景覆盖、样本数和规则版本分别展示；自适应题集难度变化时不能直接比较原始总分。

可用“仅浏览参考”与“预测→证据→迁移”的对照试验检验增益，控制内容、时间和先验水平；真实收益与长期胜率不能由一次 Demo 试用推出。建议的 1/3/7 天复测可作为待验证默认值，不称为扑克学习的最优间隔，也不在本次创建提醒或自动任务。

学习设计研究只提供方向：Butler（2010）在文本学习中观察到重复测试对保持和迁移的益处；它不是扑克教学效果证据。[原始论文](https://andymatuschak.org/files/papers/Butler%20-%202010%20-%20Repeated%20Testing%20Produces%20Superior%20Transfer%20of%20Learning%20Relative%20to%20Repeated.pdf)

本轮结果是产品设计建议。应用保持现状，原回滚标签不移动；进入下一轮开发时，应以一条可完成的教学旅程及以上明确边界细化任务。
