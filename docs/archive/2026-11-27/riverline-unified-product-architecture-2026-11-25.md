## 1. 产品目标与可检验结果

产品定位：面向已掌握德州扑克基本规则的学习者，把实战式练习中的不确定决策转为可研究、可复现、可再训练的学习材料。默认从本地单用户开始；连续 6-max 现金练习与专业 HU 研究共存，能力各自标明，互不冒充。

主旅程：连续练习 → 保存疑问/候选问题 → 行动前复盘 → 派生研究案例 → 核对范围/树/模型 → 加载或运行真实分析 → 条件对照 → 固定结论和题目 → 新题练习/复测 → 回看问题是否反复出现。

同日用户明确补充：**练习以完整一手牌为基本单位；研究承担更深入、高质量的分析能力。** 以下为正式目标修订，应用尚未实施。前述河牌单点闭环只是内部阶段验收，不代表完整练习体验已交付。

### 1.1 整手练习合同

- 默认从翻前开始，沿用户与对手实际选择推进至合法终局。Hero 弃牌即可结束其参与的本手，不强迫每手打到河牌；全下后按规则完成发牌/结算。不为让教学路线成立而偷偷改写用户动作。
- 专项训练优先选定整手的初始条件、位置、深度或对手类型，让目标问题在连续决策中出现；从翻后中途开始、单节点或范围构建题作为明确命名的补充练习，不能充当整手完成记录。
- 默认先完成整手再集中反馈；手中可标记疑问、保存理由或信心。辅导模式可即时提示，但记录提示发生节点和时间，此前已固定的独立决策保持原身份，其后的相关决策按实际暴露判定。
- 保存整手作答及每次行动前信息、原始选择、金额、提示和路径引用。中断/刷新可恢复未完成手牌；完成、放弃、暂停分别记录。复盘能从整手概览定位具体节点，并在研究后返回原手牌。
- 整手反馈区分牌局输赢、已评价决策、未覆盖决策及贯穿多街的待研究问题。有资格的同模型逐节点评价才给损失；缺失不当零分，不能把不同局部模型的 EV 直接相加成整手战略总分。重复问题统计保留样本与来源。
- 从研究返回练习时，可以重打该行动线或配置同目标整手变体。重打已看过参考的原手不算未见迁移，单纯换 ID/花色也不自动成为新题。

### 1.2 深度研究能力合同

研究是独立的专业工作区，能够提出、计算、比较和保存可复现问题。完成目标按以下能力逐项验收：

| 能力 | 用户应能完成 | 质量边界 |
|---|---|---|
| 整条行动线与逐街关联 | 从原手任一决策进入，查看前序事实、各街范围来源与后续分支，追溯上游变化 | 一组局部分析明确关联到同手；不能称作整手或六人全局均衡 |
| 双方范围与具体组合 | 同节点比较双方输入/到达范围、组合与牌类策略、行动 EV/权益、阻断及结构筛选 | 输入权重、策略频率、兼容组合加权统计分开；结构分类以实测分类器为准 |
| 树与自定义策略 | 配置多尺寸/加注/全下，编辑 Hero/全范围混频，保留合法与已建模边界 | 只有对应树/街道已验证时可计算；不借相近尺寸结果 |
| 条件实验与响应 | 改一项范围、筹码、牌面、尺寸或对手策略，固定策略求值、BR、锁定后再求解 | 各目的独立，比较条件和质量一致；假设不变成对手事实 |
| 多牌面/后续牌比较 | 比较不同 runout、牌面类别和策略变化，形成有依据的规律与反例 | 真正计算/加载相应兼容解；缺失保持缺失，禁止复用静态数值 |
| 版本与结论 | 保存基准/变体、差异、结果质量、解释与适用条件，回到原节点或生成整手训练 | 自由文本解释与求解证据分别记录，旧结果不随草稿漂移 |

研究深度由真实能力、数据粒度、比较方法与可复现性衡量。UI 专项删减冗余呈现，同时保留专业控制和分析视图的明确入口；依据当前研究任务展开必要深度。真实引擎逐街开放顺序仍为河牌→转牌→翻牌，翻前/多人独立验证。

“接近商业 Solver 体验”分为三种独立验收，不能用界面相似替代后两项：

| 目标 | 可见行为 | 不据此承诺的内容 |
|---|---|---|
| 工作流与可读性 | 节点导航、矩阵/组合联动、EV/权益/范围视图、树配置、版本比较、保存恢复、从复盘直达研究 | 商业产品的全套数据库、相同 UI 或品牌 |
| 数值可信与适用性 | 每个开放模型有独立基准、质量定义、金额口径、引擎版本和不可变输入 | 任意局面都能精确求解、与其他产品逐组合策略一致 |
| 内容覆盖与响应 | 常用规格有合法来源的预解；精确命中时快速查看；未命中可计算或说明边界 | 六人全街道 Nash、无限动作空间、所有自定义树即时返回 |

先以无前注、无抽水 NLHE cash 100BB 为连续训练基线，保留实际现金会话的筹码变化；“每手重置 100BB”是另一种明确模式，不在后台混用。后续 rake、短筹码与更多桌型按各自合同开放，不假定当前基准已覆盖。

## 2. 三份仓库的整合裁决

本仓库是后续开发的主底座。整合以职责、合同、测试资产与内容来源迁移为单位，不合并三套应用服务、不拼接数据库、不同时启用两套规则权威。

| 来源 | 值得承接 | 整合方式 | 目前证据与限制 |
|---|---|---|---|
| 本地 `poker_coach` | React 范围矩阵/具体组合、输入权重与策略混频、版本分支/比较、教学暴露/迁移概念、Node UI/MCP 入口、真实 Rust 河牌适配 | 保留并逐项迁到统一业务对象；旧课程数据只读导入 | HEAD `c9d5482`；一般树有内部独立基准，应用接入存在未提交改动，本次不验收它 |
| 旧 `riverline-poker-coach` | PokerKit 薄适配、连续牌局/事件、视角投影、幂等/恢复、逐决策复盘、规则及故障测试 | 优先将规则适配提为无业务存储的 Python helper；其余复用规范和测试后重接 Node 服务 | 固定审阅 `e449a35fb0b84dd13ab74d3dcde47034ac0cb294`；旧 FastAPI/Next 工作区不作为第二业务权威 |
| `newHoldem` | 牌桌行动反馈、连续开局节奏、结果到复盘的入口、统计观察、卡牌识别和 2D 布局经验 | 学习交互机制；若复制代码，逐项核对其来源和许可 | 固定审阅 `7744eb84999e1a53c0cc682d639cf3a86c9d448b`；不采用其固定质量数值、固定范围脚本和粗粒度缓存作为求解标准 |

本仓库当前也有新旧两类持久化边界：S1/real 通过 Node 服务，早期 Demo/教学仍含浏览器 IndexedDB 和曝光桥接。统一服务是目标，不把既有桥接误写成所有课程已经服务端化。

不引入：社交俱乐部、聊天/排行榜/装扮、3D 物理、真人多人房间、支付。它们没有解决本轮学习主旅程，未来另立产品范围。对手画像先作为有样本和来源的观察假设，不称作真实私牌分布或严格安全剥削保证。

## 3. 目标会冲突的地方与解决办法

| 潜在冲突 | 统一规则 |
|---|---|
| 自主练习需要隐藏答案，研究需要完整参考 | 共用数据和固定解，使用服务端查询投影；独立、辅导、研究三种会话模式分别规定揭示时机 |
| 六人牌局可玩，但真实 Solver 暂以 HU 河牌为主 | 规则覆盖、Bot 能力、策略数据覆盖、计算能力分别登记；多人节点可以保存问题，但不得显示借用的 HU 评分 |
| 任意合法尺寸与离散求解树不一致 | 牌桌执行合法行动；未建模尺寸保存原额并标未评分。进入研究时显式新增树分支或另建模型，不自动吸附相近尺寸 |
| 随机实战分布与高效专项训练不同 | 分开提供连续会话与定向训练；记录题目抽样方式，专项结果不代表自然牌局中的总体错误率 |
| 输赢、策略偏差和认知问题混在一起 | 输赢是事实；有同模型 EV 才计算动作损失；重复疑问、长思考、主观标记只是待复核线索 |
| 当前对手的剥削策略与均衡基准不同 | 比较时固定评价目的、对手模型、范围和单位，分别报告，不生成统一“打法分数” |
| 简洁牌桌与专业分析密度不同 | 同一上下文切换工作区，练习突出行动，研究突出矩阵/树/组合，详细来源按需展开 |

用户进入研究或查看答案后，保留其首次独立作答；后续修订与同答案事实的新作答记录已见/辅助。只换题名、牌色或对象 ID 不会自动创造未见迁移题。当前工作区无暴露记录也不等于用户在外部从未见过。

## 4. 统一对象与所有权

| 对象 | 所有权及不可变边界 |
|---|---|
| GameSession / HandRecord | Node 保存会话和有序手牌事实；规则是否合法只由 RulePort 的固定规则实现判定 |
| DecisionSnapshot | 引用 handId、行动前 eventSeq、actor/observer、局面哈希、规则版本与可见信息范围；历史后续牌不进入该快照 |
| IssueCandidate | 引用决策及标记来源：用户疑问、模型内动作损失、重复模式等；未经证据复核不升级为“已诊断错误” |
| StudyCase / StudyRevision | 从快照派生；范围来源、补充假设和对原局面的差异显式保存；修改生成新版本，不改写手牌事实 |
| RangeRevision / PolicyRevision | 输入范围权重与行动频率分别拥有版本；169 牌类仅是 1326 具体组合的显示聚合 |
| AnalysisSpec / JobAttempt / SolutionManifest | 固定模型、输入、资源和实际引擎；结果先校验后发布；原生大解保存在制品仓 |
| Finding | 保存观察、解释/假设、证据与适用条件；LLM 文本不能自行成为数值事实 |
| ExerciseDefinition / Attempt / Exposure | 固定题目、评分政策、答案事实、首次作答和提示；服务端事务保护暴露时序 |
| HandExercise / HandAttempt | 以一手为训练单元，拥有初始条件/终局目标和逐决策 Attempt 引用；保留原始路径、暂停恢复、整手完成和逐节点暴露，不用单点正确率代替整手表现 |

金额沿用 100 centibb = 1 bb 的整数研究合同。筹码桌记录 `chipUnit` 和固定盲注比例，以精确有理数换算；无法无损落入求解单位时返回不支持，不能静默舍入。行动明确区分 raise-to、当前街累计投入和本次增投。

## 5. 范围与计算的语义

范围来源至少区分：真实给定输入、公开行动下的估计、版本化策略派生、人工假设、示例内容。牌桌内知道 Bot 私牌和内部策略，不等于用户有权用它进行独立决策；训练 Bot 的精确内部范围不能伪装成由公开行动推断的范围。

计算类型分别声明：权益计算、启发式近似、固定策略求值、最佳响应、离散树均衡、受约束再求解。指标带单位、收益原点、评价分布与可用原因。MC 抽样区间只描述所声明模型中的抽样不确定性，不覆盖对手模型错设或证明接近均衡。

六人行动线进入两人翻后研究必须保存：原背景人数、当下活跃人数、求解人数、弃牌/已投入/返还账本、范围来源，以及是否忽略 folded-card/bunching 相关性。声明“给定范围的两人局部模型”，不声称重现整场六人均衡。

## 7. 整合顺序与完成口径

采用“本仓库为主、旧能力薄适配、逐条旅程替换”的渐进路线。先完成一个已有真解范围内的小闭环，再扩大连续牌局与街道覆盖；不能先铺一轮空模块和治理流程再等待用户体验。

初始真解闭环可以从受支持河牌开始，必须保留其起始范围是假设/导入的事实。它是阶段切片，不是完整六人翻前到河牌训练已完成。连续自由牌局随后接入，遇未覆盖节点可以继续合法打牌、标记疑问与保留研究，不输出假评分。

指标分别记录：完整旅程完成率、丢失上下文/串节点次数、可用模型覆盖率、预解精确命中率、响应分位数、首次独立作答保留率、相同问题的复测变化。学习效果是观察结果，样本不足时不承诺掌握或胜率提升。
