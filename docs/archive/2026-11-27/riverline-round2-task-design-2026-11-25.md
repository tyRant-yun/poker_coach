## 3. 牌桌：权威进度与播放进度分开

保留当前行动批次的原子提交。Node/PokerKit完成真实状态推进，再给客户端返回安全的表现帧；不把动画延时放入游戏写事务、规则进程或Node串行命令队列。以后若增加真人桌/按真实时间行动，再单独设计持久化调度器，本轮不引入。

```mermaid
flowchart LR
  A[提交Hero合法行动] --> B[PokerKit执行并产生规则操作]
  B --> C[Node投影公共帧并保存权威结果]
  C --> D[客户端逐帧呈现]
  D --> E[对手动作与筹码变化]
  E --> F[收池 发牌 或结算]
  F --> G[到达权威回合再开放操作]
```

### 3.1 计划合同

- `transition` 带 `handId/fromHandRevision/toHandRevision/batchId`；帧带稳定 `eventId/sequence`、类型、actor、规范金额和该帧安全观察。幂等重试返回同一批次，已消费帧不重复播放。
- 行动回复保留原 `HandView`，可选附批次引用；表现帧通过同一Node服务/MCP的 `game_transition_query` 按批次/游标读取，初始设计每页最多16帧、64KiB，游标绑定手牌/目标版本。提前预取下一页；跳过时直接同步权威视图，不把完整长手牌的快照数组塞进行动回复。Python协议仍有界，规则trace也需分段投影/重放，不直接扩大为无限JSON。
- 帧查询使用严格schema和同一信息边界；每次读取先检查当前工作区/独立状态，再使用缓存或旧回执。新手开始后不能重读上一手的亮牌帧。表现提前/延后不改变Node对当前事实的访问判定，帧中某时点尚未公开的内容不得提前渲染。
- 规则操作投影区分 `player-acted / bets-collected / board-dealt / cards-tabled / uncalled-returned / pot-awarded / hand-closed`。思考光标是表现状态，不伪装成真实计算耗时或牌局事实。
- 筹码显示来自规则操作当时的 stacks/bets/pot；跟注额、加注到与本次增投分开。只依据最终状态猜“飞了多少筹码”不通过。
- PokerKit当前会自动补街/结算，N00必须捕获真实操作边界。不能只对 `events` 加计时器，因为它没有独立发牌/收池/派奖事件。不得把包含所有私牌的原始 `operations` 直接送到前端。
- N00先证明自动规则操作能按边界生成真实观察；必要时调整helper的自动操作驱动方式，由PokerKit逐步执行，而非在前端/Node重写收池与派彩。未取得该证据前不开始用最终画面伪装逐步播放。
- 每个公共帧只显示该时刻公牌与已依法亮出的牌；Hero私牌按现有视角。完整deck/对手隐藏牌不进入任何表现帧。帧缓存有界，不能每次返回整手所有前缀快照；超限不得截断后谎称完整。
- `HandView`原有语义与旧客户端保留；新增表现数据需版本字段/可选适配，旧保存和备份仍能重放。若持久化帧缓存，导入必须从规则重新生成/核验，不能信任导入的视觉快照。

### 3.2 初始节奏与交互

以下为待体验调优的初始参数，不宣称已测得最佳时长：

| 阶段 | 舒适模式初始值 | 呈现目的 |
|---|---|---|
| 轮到对手 | 350–500ms | 让用户定位actor，不播放虚构思考理由 |
| 动作与投入 | 650–850ms；其中轻位移120–200ms | 读清弃牌/跟注/下注至多少，更新座位与投入 |
| 收池/换街 | 700–1000ms | 先收池，再显本街公共牌；翻牌成组，转/河分段 |
| 全下补牌 | 每街900–1200ms | 不一帧跳到五张公牌和赢家 |
| 结果 | 至少1200ms清晰停留，之后手动下一手 | 看清亮牌、返还/派彩和净变化；默认不自动开下一手 |

设置只保留舒适/快速/即时；播放中提供“跳过”。Hero操作在网络提交与未到达最终观察帧时禁用，轮到Hero后稳定开放，不增加玩家倒计时。减弱动态关闭位移/闪烁，保留可读动作标签和基本停留。隐藏页停止补播，恢复后同步最新安全回合与最近行动；刷新/换手不重发命令、不从第一步重放整手。视觉游标不决定牌局完成或研究权限，权限始终取Node事实状态。

## 4. 研究：默认图形操作，保留高级输入

### 4.1 选牌/范围

公共牌使用3–5个槽位组件，但真实可提交街道按能力开放：P2仅5张，P3通过后4张；不支持街道不显示伪结果。每个槽位能替换/清除，选牌器有花色图案、点数、禁用原因、键盘/ESC/焦点返回。`T`可显示为10，内部继续使用规范牌码。

Hero观察组合使用两个槽位，并可从组合列表直接选择。它只改变观察对象，不修改双方输入范围。原手事实保留只读来源；改变研究牌面属于假设分支，不覆盖原手。

OOP/IP范围使用同一个编辑器：选牌类→展开该类具体花色组合→设置0–100%输入权重；批量与逐组合编辑均保留未选组合。两方可以包含同一组合；公共牌才是共同死牌。高级文本导入/导出折叠保留，应用前做语义校验。冲突组合、空范围、没有兼容私牌对或超出资源限制都要指出可修正位置；禁止静默截断或换成默认范围。

### 4.2 从空工作区到真实结果

- 空状态保留“从复盘进入 / 新建研究 / 打开研究案例”三个有明确用途的选择。案例是公开的研究输入；可随包提供本项目实际生成、带规格/引擎/质量/摘要的真解，或明确点击后真实计算。没有制品时不拿基准JSON数值冒充已加载结果。
- 至少准备两个可复现河牌案例：一个多尺寸/加注，一个非对称权重/阻断。另准备有多个牌类/花色组合的正常展示范围，实际通过资源预检，不只用每方一两个组合填UI。案例输入、生成命令和真解出处可追溯。
- 一个“开始分析”主操作顺序调用已有真实业务命令：校验草稿→必要时保存版本→固定规格→原生预检→启动。各步骤仍由现有Node命令决定；不在UI复制扑克/质量计算。先复用现有工具，不为按钮缩减而直接绕过合同调用Rust。
- 步骤使用固定请求身份和明确失败阶段；部分失败保留已保存的case/spec与原草稿，不承诺SQLite和journal之间存在未实现的跨库原子事务。版本冲突先保留用户输入并定位差异，不能自动覆盖MCP的新版本。
- 作业完成后自动打开此次请求对应的固定解；刷新能恢复所跟随的作业/解。完成时用户已切换案例或修改草稿，不抢焦点、不把旧解覆盖新输入。质量未达目标仍显示真实指标及可操作状态，不伪装成功达标。

### 4.3 第一批必交图形与存在理由

| 图形 | 回答的问题 | 数据与约束 |
|---|---|---|
| 当前行动分布条及图例 | 这个范围整体怎么行动？ | `real_range_aggregate.frequencies`；只对行动方有策略；每种下注尺寸保留独立身份 |
| 169策略/范围/EV/权益视图 | 哪些牌类差异最大？ | 同节点兼容组合条件概率加权；EV以0为明确参照，权益色标0–100%；有色标/单位/空值状态 |
| 具体花色组合及频率条 | 同一牌类为何不同花色不同？ | 查询真实组合；点击矩阵联动；不可达/死牌/范围外分别说明，不填0或平均补齐 |

## 5. 真实转牌：明确超出UI改造的工程量

当前 `explicit.rs` 固定 `board.len()==5` 与 `BoardState::River`；合同、原生读取、节点schema和投影同样围绕河牌设计。旧adapter有turn字段或固定引擎支持多街，不足以直接开放本产品。

N06先建立独立基准：

1. 转牌check-down：独立枚举合法两手私牌与所有river，核验权益/终局价值。
2. 非对称输入权重与阻断：公牌层最多48个river候选，但给定不相交的双方私牌后只有44个合法river；实际概率随兼容私牌/路径条件化，不能均分所有候选。
3. 有转牌决策和河牌后续决策的微型树：用独立完整计划枚举或序列式LP/BR核验，转牌策略不得提前知道river。分别求每张river最优值再平均不能替代这个基准。
4. 全下、未跟注返还及跨街账本；节点EV收益原点一致，并核对原生存档重读。
5. 花色结构变化/逆映射、零概率分支与不可达组合；保持原河牌独立基准回归。

阈值先冻结：沿用R1/R2已声明的概率和EV/独立BR门槛，不为过关后改阈值。资源预算沿用现有限制做起点，以实测决定转牌开放范围；不默认继承“200组合/每方”的河牌性能承诺，不暗中提高内存/时间或舍弃河牌分支。

N07采用新版本模型/原生查询合同，兼容读旧河牌：

- 节点使用 `decision / chance / terminal` 判别联合，机会节点不是没有actor的普通决策节点。
- 新路径区分 `action(index)` 与 `deal(card)`；旧数字路径仅解释为旧河牌动作，不把发牌索引塞进去碰撞。
- 查询返回实际公共牌、可达发牌候选/概率、双方条件范围、节点/行动指标；分页游标绑定原生解/路径/玩家/模型版本。
- 继续原生按需读取、固定规格、单计算槽/有界查询、取消/中断/新attempt、原子发布与恢复。存档包含模型/输入身份，旧manifest和备份不改义。

N08只在N06/07通过后开放四张牌、机会节点选牌和后续河牌图表；同时扩展 `game_research/ResearchSource` 的转牌资格与根节点提取。完成手牌中的转牌决策进入研究时，只携带当时四张公共牌和前缀；原手实际river保留在手牌历史中，不固定进转牌求解输入或充当预测答案。旧河牌来源/笔记/绑定可恢复，未支持的翻牌/多人节点仍能保存研究问题，不借其他模型填数。
