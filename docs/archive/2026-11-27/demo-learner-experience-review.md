# Riverline Demo：扑克学习者体验评审

日期：2026-11-12（Asia/Shanghai）
评审源码：`39291a4`。本轮仅体验与记录，未修改应用实现。
方式：在本地运行中的 Demo 逐页操作，并实际查看页面截图；商业产品对照依据本轮重新查询的官方资料，未登录或实操其付费客户端。

## 1. 核心判断

Riverline 已能展示一个相当完整的研究与学习工作空间：编辑、版本、求解任务、实验、Agent 制品、训练、复盘和本地迁移能够形成真实操作链。尤其值得保留的是固定版本、行动前信息隔离、首次作答保存，以及不匹配输入不套用其他局面数值。

从学习者视角，目前更像“带教学入口的研究工作台”。我能完成操作、看到策略、保存作品，但还不容易回答：这次应该学会什么、为什么这样打、我的错误属于哪一类、换一个局面是否真的理解了。下一轮的主要价值应来自教学内容可信度、低负担学习路线和解释反馈。

不能拿本 Demo 的模拟结果与商业产品的求解精度、速度、策略质量直接排名。当前合成数据适合验证交互，不足以承担真实扑克策略教学。

以下区分实际操作和未穷举项目，不以旧自动化验收代替本轮体验。

|---|---|---|

| S09/S10 扩展 | 打开三人和 MTT 配置、检查第三方范围说明、筹码/奖金与效用模型；S09 读取任务完成 | 可用于讲边界，暂不足以承担多人或赛事课程；不应抢占基础课程优先级 |
| 求解与异常 | 实际触发首次失败并在任务详情重试成功；慢任务取消；资源限制；完成但质量不足；查看全局任务 | 状态机制丰富；英文状态、内部数值、旧结果与新任务状态的并置增加解释成本 |
| 保存与迁移 | 下载 JSON、损坏 schema 拒绝、加载约 4.7MB 备份预检、导入 12 个新副本、刷新验证；下载 Markdown | 可用性较好；导入后的案例管理与重复副本辨识有待加强 |
| 视觉偏好 | 实际切换四色牌面，检查常规与四色显示 | 牌面辨识度好；建议在首次使用提供轻量偏好入口 |

未操作的破坏性项目：全应用重置、实际损坏浏览器存储。未穷举：所有故障排列、Agent 并发冲突/额度耗尽/暂停时序、全部键盘与拖选路径、移动端和所有窄屏尺寸。没有验证真实扑克正确性、真实智能或教学效果。本轮未重新运行类型检查、构建及原有自动化套件，因为未修改应用实现。

体验产生的新案例、练习、实验和导入副本保留在本地，未覆盖原案例。结束时设置恢复为理想过程、正常速度、本地演示、学习者、双色牌面。未重置原有学习数据。

## 3. 最重要的教学问题

### P0：合成数据之间的关系不能被误学为扑克规律

实际例子：S02 起始节点、A♠7♦2♣、AhKh。

| 动作 | 参考频率 | 动作 EV 示例 |
|---|---:|---:|
| 过牌 | 53.0% | 0.57 bb |
| 下注 33% | 21.5% | 0.92 bb |
| 下注 75% | 25.5% | 1.27 bb |

页面已经明确写了合成示例，因此这不是“真实 Solver 算错”的证据。但如果学员把它当成均衡解，同一组合为何长期混合使用三个明显不同价值的动作，会形成错误理解。在相同信息集、相同 EV 定义及对手策略固定的均衡解释中，被混合采用的最优动作应在求解误差内近似无差异；当前示例并未满足这种教学语义。

源码核对也确认：`src/fixtures/scenarios.ts` 的频率、权益、动作 EV 和部分成牌/听牌标签采用独立的序号公式生成。它们是交互占位内容，不是牌力计算或审核过的扑克解释。

建议：

1. 明确“交互演示内容”“人工编写的概念练习”“有可追溯求解证据的策略内容”三种身份。
2. 没有资格的数值不能参与真实策略对错、精细混频或能力评价；可隐藏无教学意义的 EV/权益细节。
3. 保留 mock 边界，先制作少量自洽的教学案例；解释中的每个“因为”应指向案例条件、组合或明确的概念依据。
4. 成牌/听牌类别不能继续以组合序号作为教学分类依据。未具备可信分类时显示为演示分组，避免诱导用户据此分析阻断或坚果优势。

验收：学员能识别自己看到的是哪类证据；任何可评分题的答案、频率、EV、类别和解释不互相矛盾。人工审核不能被标为 Solver 验证。

### P1：先给学习目标，再给全范围

当前训练从“全范围构建/分支补全/诊断/比较”这些工具题型开始。第一次进入全范围练习就面对 569 个组合，分支补全也有 548 个组合。虽然提供整批填充，用户可能只是在完成表单覆盖。

建议第一课缩小到一个技能，例如“比较同牌类的具体花色如何影响候选行动”。流程为：选一手 Hero → 预测并写理由 → 对照两三手近邻 → 归纳一个类别 → 完成少量局部范围 → 在新条件下独立复测。完整范围编辑保留为自由研究和进阶专项。

验收：不填写整个范围也能完成一次有意义的学习闭环；每一步说明这次观察要解决哪个问题。

### P1：反馈应该指导修正，而不是只报告是否符合约定

诊断正确后，主要反馈是“判断符合本题的结构/评价约定”。之后出现一张完整策略矩阵，与本题的概率合计知识点联系较弱。局面比较主要考察“频率不能直接证明 EV 更高”，是有用的概念，但尚不是丰富的扑克局面比较。

建议反馈固定回答四件事：你做了什么 → 哪一处需要修正 → 依据是什么 → 下一步尝试什么。允许给出多种合理理由，不能把填写理由误当作理由已被理解或评分。

验收：一次反馈至少定位一个具体错误或一个可保留的判断，并提供与该题相关的下一步。没有真实 EV 时明确只评结构/概念，不伪造收益评分。

### P1：迁移要改变决策条件，而不是只改变题目的牌面装饰

本轮从诊断进入 S03，看到的核心任务仍是概率合计问题。它可以验证结构约定，但不能用于证明学员理解了牌面变化后的策略。

建议给同一技能配基础例、近似例和反例；分别记录原题修订、新题迁移、延迟复测。迁移题要求学员处理真正影响所学概念的变化，答案揭示与历史暴露单独保存。

### P1：翻前应是一条学习主线

S08 的 100bb、BTN/BB、F/C/R2.5 只是单节点预览，缺前序行动定义、位置顺序和对手回应。“平跟”在具体翻前序列中的意义必须依赖是否存在前序加注、盲位/straddle 等条件，不能只靠位置标题理解。

建议先做一条明确的预置路径：前序行动 → Hero 候选行动 → 对手回应 → 对应起始范围 → 匹配翻后场景 → 专项练习与迁移。继续遵守无真实规则引擎、无任意输入求解的 Demo 边界。

## 4. 视觉与交互反馈

本轮实际截图为约 1250×830 的桌面窗口；以下为视觉观察，未做色彩对比度仪器测量或移动端验收。

### 值得保留

- 深色底、薄边框与薄荷绿主操作统一，品牌气质稳定。
- 公共牌和具体组合用两张实体牌面表达，比内部字符串更易辨识；四色模式有实际帮助。
- 主要编辑区与右侧组合编辑器的空间关系直观。
- 独立/辅助、合成数据和固定版本说明并非只藏在介绍页，体现了结果边界意识。

### 应修正的问题

| 优先级 | 实际观察 | 建议与验收 |
|---|---|---|
| P1 | 研究页首屏中，案例头、局面摘要、标签、工作台说明、任务状态和警示占据较多高度；策略矩阵在下方 | 压缩上下文为一条紧凑固定栏；默认首屏出现完整或主要策略矩阵、Hero 细节与核心动作 |
| P1 | 从训练或设置切到学习记录/局面库时，有时保留旧滚动位置，页面标题已经在屏幕外；最后返回局面库也复现 | 新页面导航回顶部并聚焦主标题；只在明确返回原研究位置时恢复滚动 |
| P1 | 首页不同场景、三人和 MTT 都显示“S01 · 范围构建” | 标签来自真实场景与当前任务，导入副本和实验分支有独立标识；核对 `src/app/App.tsx` |
| P1 | 局面库搜索“翻前”后只剩 S08，但工具栏仍显示“翻牌 · 现金局”；S05 实际 F/C，卡片仍写“三种行动” | 筛选标签、行动数从场景数据生成；翻前独立入口可发现，不包装成完整能力 |
| P1 | 修改 S08 为 50bb 后，运行状态是绿色 completed/模拟完成，树仍标预置覆盖，但主内容是没有匹配结果 | 分开展示“任务执行完成”“当前数据未覆盖”；节点覆盖根据当前输入表达，不能让成功色代替可用结果 |
| P2 | 取消任务与完成任务的状态条视觉接近，都采用绿色基底；质量不足主要依赖文字 | 用中文状态、图标和不同语义样式共同区分完成、取消、失败、未覆盖、质量不足，不只依赖颜色 |
| P2 | 辅助说明、英文小标题、节点内文字与牌类小字偏小；暗灰文字与深色背景在长时间阅读下吃力 | 提高正文/关键数据字号和次要文本亮度，减少大写英文装饰标签；实际检查常用缩放和长文本 |
| P2 | 节点全部平铺成相似卡片，路径较长时当前节点不易与父子结构建立联系 | 使用缩进/连接线与可折叠兄弟分支；突出当前路径、行动者和累计下注，未覆盖节点给下一步出口 |
| P2 | Hero 组合选择器含五百多个内部字符串选项，精确寻找花色效率低 | 用点选两张牌、牌类过滤或可检索选择器；选项显示花色图案 |
| P2 | 提示消息固定悬浮在页面下方，截图中遮挡部分反馈或矩阵内容；导入错误未关闭时可跨页存在 | 成功提示更轻、错误就地定位；页面切换处理过期提示；给底部操作和反馈保留避让空间 |
| P2 | 任务详情出现 completed、fail-once、pot 1850/stack 9100 等内部表达，主页面对应 18.5/91 bb | 面向学员显示中文、bb 和明确单位；原始 ID/指纹/内部数值折叠到技术详情 |
| P2 | Agent 任务中心默认选择较早的案例，且只列当前所选案例的任务；刚完成的其他任务看起来消失 | 默认展示全局最近任务、状态计数和成果；案例筛选是显式操作，并保留当前选择 |

## 5. 与商业 Solver 和同类产品的对照

以下只比较官方资料支持的能力与学习方式；没有实测其求解速度、付费版本限制或教学效果，不把品牌宣传作为性能结论。

| 产品 | 官方资料可确认的长处 | Riverline 当前差距 | 应借鉴的具体机制 |
|---|---|---|---|
| PioSOLVER | 自定义树、策略修改/组合锁定、重新求解、聚合报告和内置训练器 | 目前是固定场景和合成结果，不能验证假设调整后的真实策略与 EV | 一个研究问题绑定完整规格；让学员先预测改变对手假设后哪一部分响应会变化，再核对成果。来源：[功能](https://piosolver.com/docs/feature_overview/)、[Node Lock](https://piosolver.com/docs/viewer/node_locking/) |
| GTO+ | 多尺度树编辑、求解树数据库与比较、分析图表、Play against solution | 有三份假设报告，但跨牌面规律、受控实验和连续决策练习较浅 | 把基准/变体、观察、结论存成一次实验；允许从自己的固定研究结果进入练习。来源：[产品](https://www.gtoplus.com/)、[训练器与版本说明](https://www.gtoplus.com/download/) |
| GTO Wizard | Study 的局面选择、策略/EV/权益/范围/构成/聚合；Practice 支持翻前到河牌、指定街道/决策及范围构建；表现统计区分自身评分与 EV 等指标 | 页面出口已连通，但课程路径、内容覆盖、错因诊断和反馈粒度仍有限 | 研究入口允许先看；学习入口先预测。训练按目标和粒度选择，回答后给可定位解释，而不是照抄品牌总分。来源：[Study](https://help.gtowizard.com/study-mode/)、[Practice](https://help.gtowizard.com/practice-mode-overview/)、[表现指标](https://help.gtowizard.com/measure-performance/) |

## 6. 下一轮建议顺序

建议沿用已存在但未实施的 TE01–TE08 设计，不再另开一套互相冲突的功能编号。

1. **先修可见错误与内容资格。** 修复场景标签、行动数、滚动和任务单位；分开任务状态/结果可用性；落实 TE01 的内容身份与一致性审阅。
2. **完成一节可独立体验的短课。** 结合 TE02、TE04、TE05，围绕一个技能实现 Hero 预测、近邻对照、局部范围、解释反馈与真正的新题迁移。以五到十分钟为产品设计目标，再通过试用验证，不能当作已测得时长。
3. **补一条翻前到翻后的预置主线。** 承接 TE03/PF01/PF02，保持当前纯 mock 范围；让上游行动与下游范围来源明确。
4. **再增强实验和 Agent。** TE06/TE07 先让学员写假设和判断，再由 Agent 组织实验、追踪证据和提出练习。不要默认替学员填完独立作答。
5. **最后扩大案例与进阶预览。** 先证明一套教学步骤能让目标用户理解并迁移，再扩大牌面、多人、ICM 或复杂求解参数。

不将 Hero 自定义尺度/混频自动并入这轮建议的必做项，继续尊重 Demo 已确认的暂缓约定。

## 7. 下一轮如何验收

功能验收继续保留，另加真实学习者试用：

- 首次用户无需口头带领，能找到一节适合自己的课，并说明当前目标。
- 学员能解释至少一组近邻组合的不同条件，且能点击查看解释依据。
- 完整范围无需手工填完也能完成核心学习旅程。
- 一次答错后，反馈使其知道具体改哪一处；“猜中选项”与“解释有依据”分开记录。
- 新题改变与技能相关的条件；原题重做、迁移和延迟复测分别展示。
- 学员能分清合成示例、内容审阅、真实求解及结果质量；不因绿色 completed 误以为有可用或高精度结果。
- 记录首次任务完成、求助/放弃位置、错误类型和后续表现；样本足够前，不宣称能力提升或胜率提升。

本报告是基于实际交互的产品评审，以上优先级与教学方案是待验证的设计判断，不是已经证明的教学效果。
