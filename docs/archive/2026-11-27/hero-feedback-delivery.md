# Hero 推演与全范围推荐改进

日期：2026-11-12。来源：用户实际体验后指出模拟结果没有展示全范围推荐，且完整手填范围负担过高；提出从 Hero 具体手牌出发，联系行动线与整个范围。

## 产品判断

原反馈只显示整体频率和差异，缺少组合级策略本体；同时把“填写完整范围”当作查看参考的前提，混淆了研究和完整作答。

当前默认路径调整为：Hero 手牌 → 当前行动与后续条件 → 整套参考 → 同牌类/局部范围 → 按需完整构建。

三种深度共用同一案例：

| 路径 | 用户工作量 | 成果与边界 |
|---|---|---|
| Hero 推演（默认） | 一手牌、一次行动、后续条件与理由 | 独立推演记录，不要求整范围完成，不生成虚假全范围评分 |
| 参考辅助构建 | 只修改关心的组合，剩余部分可辅助补全 | 保留手工决策、标记辅助来源，不能冒充独立范围作答 |
| 全范围构建（进阶） | 从空白或自己的方案逐组合组织 | 原有完整提交、比较与版本流程保持可用 |

## 实际修复与新增

- 已提交策略模拟后，反馈页显示 169 格全范围推荐矩阵；可选择牌类、具体组合和动作视图，查看完整行动频率及与用户提交的对照。
- Hero 默认先选具体组合，选择翻牌行动、对手后续假设、回应与转牌条件，单独保存到案例。
- 查看参考仅依赖局面与输入范围，不要求用户先提交完整策略；这类作业没有伪造的 policyRevisionId 或完整评分。
- Hero 被标为范围中的观察焦点；不会因知道 Hero 手牌就把整个自己的输入范围缩成一手，也不将 Hero 当作公共死牌改写研究条件。
- 用户明确操作后，才将 Hero 行动写入一个组合；扩展到同牌类需预览并确认，不自动假设同类花色策略等价。
- “用参考补全未填写组合”只补空白，保留已有 Hero/其他分配，固定版本继续保留 assistance 标记。
- 修改局面后，旧推演和结果保留在其原修订中，不套用到当前输入。
- 旧版 IndexedDB 快照缺少 heroPlans 时按空列表加载，原有提交和报告保留。

推荐策略仍是自行编写的合成 Mock 数据，不是真实 Solver 结论。后续行动线是用户的条件性研究计划，尚未计算多街策略或验证具体加注尺寸。

当前 S01 中 BB 已过牌，BTN 过牌后进入转牌，因此不会提供“同一翻牌轮 BB 再下注”的分支。这与 [德州扑克行动轮次说明](https://www.pokerstars.com/poker/games/texas-holdem/)一致。参考产品也分别提供 [单手训练与范围策略查看](https://help.gtowizard.com/how-to-use-the-trainer/)及[完整范围构建](https://help.gtowizard.com/how-to-use-the-range-builder/)；本项目把它们组织成递进的研究路径，非复制其数据或内部实现。

## 体验路线

1. 在局面库新建案例，默认进入“Hero 推演”。
2. 选择 AKs 中的 Ad/Kd，先决定行动，填写理由与后续条件并保存。
3. 查看范围草稿完成数，确认仅保存推演不会增加范围覆盖。
4. 可只把 Hero 行动写入草稿，此时仅覆盖一个组合。
5. 点击“查看全范围模拟策略”，无需填写其他组合；结果会滚动定位到 Hero 对照和全范围参考。
6. 点击矩阵中的其他牌类或花色组合，查看其频率与 Hero 的联系。
7. 如需完整方案，明确选择“用参考补全未填写组合”，然后进入全范围构建局部修订。
8. 提交版本会保留参考辅助标识；这不等于已经掌握完整范围。
