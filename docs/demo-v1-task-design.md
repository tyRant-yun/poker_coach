# 第一版 Demo 开发任务设计 v0.1

日期：2026-11-12（Asia/Shanghai）。状态：待用户审阅；D01–D08 全部未开始。本文是任务方案，不是已完成实现报告。

## 1. 审阅与执行边界

用户已确认 [技术栈](technology-selection.md)，并要求“设计完成后等我审阅再开始开发”。本轮只修改设计、任务和 Git 记录；不得创建脚手架、应用源码、package.json、应用 fixture 或测试实现，不安装依赖，不启动应用。

R0 为人工审阅门：只有用户明确允许开始开发，D01 才可执行。之后的里程碑检查属于质量验收，不默认增加逐任务用户确认；如用户另有审阅要求，以新指令为准。

## 2. 第一版整体交付

一个本地浏览器应用，能在同一套案例、策略和版本上下文中展示研究、训练、知识、复盘和 Agent 操作。所有外部业务能力均由 stub/mock 提供，不需要账号、密钥或外部服务。

第一版完成条件：F01–F18 全覆盖，J01–J09 全部可走通，S01–S10 具有适配的演示资产。L1/L2/L3 是交互深度差异，不是从第一版删除低优先功能；D01 或 M1 不等于整版完成。

必须真实工作的部分：局面与策略编辑、选择与批量操作、撤销重做、版本与分支、应用命令、任务状态、作答记录、IndexedDB 保存、JSON/Markdown 导出与导入。

使用合成内容的部分：Solver 输出、权益/EV/可利用性、对手反应、知识示例、Agent 计划与解释、能力预测。结构检查和对合成参考的频率差异可以本地计算，并单独命名。

## 5. 任务卡

### D01 — 首个可操作纵向闭环

目标：用户可从 S01 进入案例，编辑一份完整范围草稿、提交、运行 happy-path 模拟并修订；刷新后能继续。首批不以空导航壳作为交付。

依赖：R0。范围：F01/F02/F03/F05/F06/F14 的最小可用子集；J01 的首个片段。

拟涉及：app、study、strategy、solver、assessment、ports、fixtures、persistence、styles。只建立本批实际需要的目录和合同。

交付内容：

- 获准后创建 React/TypeScript/Vite 工程、React Router、Zustand、idb、Zod、CSS Modules；选择兼容版本并提交单一锁文件。
- 建立应用命令入口、纯领域校验、结果信封和规范化实体引用；UI 经命令修改状态。
- 首页、局面库和 S01 研究工作台；显示案例、节点、玩家、版本与演示状态。
- S01 包含双方合成范围、全体矩阵格、具体组合、可编辑的起始草稿、合成参考、匹配结果及不匹配分支。矩阵点击和基本混频可用。
- 建立 createCase、editPolicy、submitPolicy、requestSolve、requestAssessment、restoreAsDraft 的首批行为；提交快照固定。
- IndexedDB 中保存案例/草稿/版本及成果引用，保存成功后反馈；非持久化环境保留内存编辑并提示。
- 建立并核对 dev/typecheck/build/test/e2e 等实际脚本；浏览器检查采用本地运行应用。

验收：

1. 从空白会话打开 S01，编辑多个组合后整体频率变化；当前可选操作有即时反馈。
2. 未填完时显示遗漏并阻止完整提交；使用“填充剩余组合”也必须是明确可见操作。
3. 提交 V1，运行预置模拟，报告引用同一局面与策略版本；自定义策略未匹配时仅显示可用评价。
4. 继续编辑得到新草稿，V1 和旧报告保持不变；能返回 V1。
5. 刷新后案例、草稿和提交仍在；界面不显示伪保存成功。
6. typecheck/build 与本批机制检查通过，首个浏览器闭环可执行；所有业务输出为合成或实际本地操作。

验收材料：首闭环截图、实际命令结果、S01 输入/成果引用摘要、commit。D01 完成才可创建 M1 标签。

### D02 — 全范围编辑、版本与比较

目标：策略作品具备完整编辑能力，用户能控制组合构成，并检查、比较和恢复版本。

依赖：D01。覆盖：F02/F03/F14，扩展 J01，支撑 J02/J05/J09。

拟涉及：strategy、study、共享矩阵/组合组件、persistence；沿用 D01 命令和 ID 约定。

交付内容：

- 矩阵/具体组合切换，类别与花色过滤，多选、拖选、批量动作、混频输入、锁定、清空、焦点模式。
- 输入范围权重与策略行动频率分开编辑；显示死牌、不在范围、未填写、零和不可达的差异。
- 一次批量手势形成一个可撤销编辑动作；undo/redo 不写入不可变提交版本。
- 条件/范围修订、策略提交、从旧版本恢复为新草稿、分支命名与版本差异比较。
- 保存状态、未保存离开提示与修改冲突信息；补齐 S01 两个固定版本和对应报告数据绑定。

验收：

1. 锁定一组组合后批量编辑类别，锁定部分不变；撤销精确回到先前状态，重做恢复。
2. 调整单一行动频率可保留中间草稿；提交时按概率约定校验，不静默分配剩余概率。
3. 加入/排除组合后整体频率按当前范围权重更新；无可用组合时显示无数据，不除零。
4. 从 V1 恢复创建 V3 草稿，V1/V2 的内容和报告均不变。
5. 两版比较既显示总量，也能下钻到组合，不能只给一个差异分数。
6. 1440/1280px 完成核心编辑；键盘能定位组合、修改数值、关闭详情并恢复焦点。

验收材料：批量/锁定/撤销演示、版本前后快照与不可变性检查。状态历史和提交历史有不同显示。

### D03 — 模拟求解、多口径评价与作业恢复

目标：研究输入、模拟作业和评价形成可解释且不串版本的完整过程。

依赖：D02。覆盖：F05/F06/F16；J01 主体、J08 的作业部分；补入 S04/S05。

拟涉及：solver、assessment、mocks、共享任务抽屉和结果视图、demo runtime。

交付内容：

- Solver 配置摘要：范围、底池/筹码、树、目标和模拟预算；预检不静默改规格。
- queued/preflight/running/postprocessing/completed/failed/cancelled 状态、质量状态与执行记录。
- 支持 ideal、slow、fail-once、resource-limit、incomplete-quality、unsupported；支持跳过等待和实际取消。
- 节点结果与组合查询；S01/S04/S05 各有合成输入/结果配对。
- 结构完整性、参考频率差异、固定模型收益示例、对抗评价示例分开显示；后两者只对匹配的固定策略开放。
- 所有结果保留节点、输入引用与 fingerprint；刷新未完成任务显示 interrupted，可重试。

验收：

1. 运行中取消后等待原完成时刻，状态仍为 cancelled，不能登记迟到报告。
2. 失败一次后显式重试有新的执行记录；同次重复请求不重复创建成果。
3. 作业运行时修改范围，结果属于旧输入，当前草稿不被覆盖；能打开原版本。
4. 已完成但质量不足与任务失败分别显示；未知评价不记为零损失。
5. 当前自定义输入无 fixture 时保留草稿，不能把其他局面的 EV 或参考结果改名显示。
6. 切换 S01/S04/S05 后上下文、可用行动、结果及来源一起切换。

验收材料：取消/迟到、重试、输入变更和质量不足的检查记录，三类评价页面截图。D02/D03 完成才可创建 M2 标签。

### D04 — 连续策略、分支覆盖与对照实验

目标：用户能从单节点进入后续计划，并在受控假设变化下比较不同研究分支。

依赖：D03。覆盖：F04/F07/F08，J02/J04；准备 J07；场景 S02/S06。

拟涉及：study、strategy、solver、assessment、节点树/比较组件；不另建平行研究状态。

交付内容：

- 至少三条有意义的翻牌至后续分支，区分玩家、发牌和终局节点；可返回上游。
- 节点范围示意、用户/参考补全来源、已覆盖/未覆盖/不可达状态。
- 修改上游后定位受影响的下游节点，标记需复核；历史策略保持可查看。
- 新建对照分支、固定基准、记录唯一或多个受控改动；差异摘要说明比较条件。
- Node Lock 指定玩家、节点、组合/频率、锁定与未锁定部分、后续补全约定。
- S06 至少包含基准和两个对手假设变体，各自绑定合成报告；结论标明人为假设。

验收：

1. 三条预置延续可逐步打开且范围/策略不串节点；未预置分支保留为未覆盖。
2. 上游修改不会改写旧的下游版本；新工作区清楚显示复核范围。
3. 基准与变体可并排查看，知道改变了什么及哪些条件相同。
4. 不同锁定范围对应不同规格与成果引用，不能仅修改报告标题。
5. 继续编辑任意变体导致不匹配时，收益示例不再冒充当前评价。

验收材料：三条路径、受影响节点图、基准/两个变体及锁定说明的报告。

### D05 — 理论知识与 Agent 控制闭环

目标：AI 的展示计划能够通过真实本地命令生成可继续使用的成果，理论可定位到当前问题。

依赖：D03/D04。覆盖：F09/F10，J03/J07；J08 的 Agent 部分。

拟涉及：knowledge、agent、应用命令、共享侧栏与任务中心、报告模型。Agent 不直接写 store。

交付内容：

- 至少 8 个自写理论条目，有概念、条件、来源链接、相关案例与实验入口。
- 关键词/标签/当前局面匹配、来源详情、空结果和未匹配状态。
- AT01 诊断并建立改进分支：读案例→检索→patch→分支提交→模拟求解/评价→报告。
- AT02 建立对照实验：固定基准→应用假设→运行→比较→写出有条件结论。
- AT03 生成训练计划草稿：读当前问题/已有表现→生成任务草稿与理由；D06 负责将草稿转为题组，避免循环依赖。
- “仅建议”和“新分支执行”策略；可见预算、暂停/继续/取消、未识别意图反馈、成果跳转。
- patch 携带 expectedRevision；版本冲突时保留原草稿并给出比较或新分支选择。

验收：

1. AT01 在产品中确实出现新策略/分支/报告；点击轨迹能到对应对象。
2. AI 修改后用户可手工继续编辑和撤销；输出不只是一段聊天。
3. 用户在 Agent 读取后修改草稿，旧 patch 不得覆盖新修改。
4. 取消后下一工具不再执行；重试不重复已有副作用；暂停不冒充取消。
5. 无匹配意图只提供支持的任务，未执行工具不能显示为成功。
6. 理论摘要和精确数值有不同来源身份；任务预算为演示额度，不伪装真实计费。

验收材料：三条脚本及其成果、冲突/取消记录、8 条知识目录。AT03 的题组执行入口在 D06 完成后再标可用。

### D06 — 训练、迁移复测与能力证据

目标：将研究成果转成练习，在不同辅助条件下记录真实用户作答，并展示复测过程。

依赖：D02/D03/D05。覆盖：F11/F12，J05；S01/S03/S05 和四类题。

拟涉及：learning、strategy 的可复用编辑器、knowledge/agent 的受限上下文投影、progress。

交付内容：

- EX01 全范围构建、EX02 分支补全、EX03 策略诊断、EX04 局面比较，每类至少一份可完成题。
- 题目固定输入、作答要求、评价约定和揭示规则；支持独立/辅助模式。
- 作答保存为 Attempt，提示、答案揭示、AI 辅助及后续修订分别记录。
- S03 作为独立迁移局面，使用自己的输入、参考与反馈。
- 将 AT03 计划草稿转为可执行题组；学习记录能追溯到作答，推荐与掌握度预测标为示例。
- 从研究节点创建题目，从训练返回相应固定研究版本。

验收：

1. 四类题都能“进入→作答→提交→反馈→结束/下一题”，不能只有选择入口。
2. 训练中的界面与 Agent/知识上下文不包含未允许的参考、未来行动或私牌。
3. 看提示或答案后辅助标记保留；修订不会覆盖首次独立作答。
4. S01 到 S03 不沿用旧数值或旧策略对象，记录中可区分两次表现。
5. 能力展示能打开支持它的题目与 Attempt；不将合成预测显示为真实掌握度结论。
6. 页面刷新后进度与已提交作答保留；训练中断可继续，未完成作答不伪装提交。

验收材料：四类作答、独立/辅助对比、迁移与证据页面、训练投影检查记录。

### D07 — 手牌复盘与扩展能力预览

目标：展示从真实手牌入口到研究/训练的衔接，同时完成翻前、多路、赛事等整体产品视野。

依赖：D04/D06。覆盖：F13/F17/F18，J06、J09 的扩展部分；S07–S10。

拟涉及：review、study、learning、library、预览配置组件；多角色是演示视角，不是实际权限系统。

交付内容：

- S07 完整/不完整手牌样例、原文、脚本解析和待确认字段；未知文本保存待整理草稿。
- 行动前时间线、当前行动者与公开信息投影，切换全知复盘时明确模式。
- 提取节点到研究，保留来源引用；由该节点建题而不改写原始牌谱。
- S08 翻前、S09 三人底池、S10 MTT/ICM 各有配置、合成范围/报告和方法条件。
- 教练视角、预算与执行位置的产品预览；选择“云端”仅改变演示说明，不发起真实请求。

验收：

1. 完整手牌能重放到多个决策前节点；不完整样例显示待确认而非自动捏造字段。
2. 玩家视角不泄漏未来牌、后续行动或对手私牌；全知视角有明确标识。
3. 提取后研究修订不改变手牌原文和事实；可返回原决策。
4. S08/S09/S10 均可操作配置并查看匹配的示例报告；变化超出覆盖时按统一规则处理。
5. MTT 的价值目标/单位与现金局分开，不能直接混合汇总。
6. 预览不要求真实账号、模型或 Solver；所有预览入口有可完成交互而非空页。

## 9. 质量、检查与交付方式

每个任务完成时检查直接受影响的机制与旅程，报告实际命令、结果和截图。共享合同变化要检查至少一个实际消费者；不重复执行无关完整测试。

计划的机制检查：提交不可变、锁定/撤销、输入 fingerprint、取消拒绝迟到、重试幂等、Agent 冲突、训练投影、保存失败、导入引用。实现完成后才编写必要测试，不在任务设计阶段创建测试代码。

完整验收以 [评审脚本](demo-review.md) 为准；1440/1280px 为完整体验目标，1024px 折叠侧栏，窄屏保证阅读与基础操作。量化性能阈值在 D01 原型测量后设定，当前不编造运行数据。

候选任务状态：待审阅 → 未开始 → 进行中 → 待验收 → 已完成。只有 R0 通过才能进入开发；当前全部仍为待审阅。遇到问题记录事实和范围，不伪造完成。

任务记录仅保留：任务 ID、开始基线、实际改动、验证、遗留项、commit。遵循现有 Git 工作流，不引入重复台账和多层审查仪式。

## 11. 需要审阅的设计取舍

- 第一版包含 F01–F18，核心研究/训练深交互，扩展能力采用可操作预览。
