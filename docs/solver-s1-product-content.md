# S1 Solver 产品、内容与验收旅程 v0.3

日期：2026-11-12。状态：设计，资产未编写。与 [任务包](solver-s1-task-design.md)、[领域合同](solver-s1-contracts.md) 共同构成 S1 开发入口。

v0.3 按 [新增约束映射](solver-s1-constraint-mapping.md) 补充真实 MCP、双入口、长任务/大结果和完整教学消费；运行边界与工具合同见 [MCP/运行时](solver-s1-mcp-runtime.md)。原 SJ01–SJ15 保留，新增 SJ16–SJ21。

## 1. 用户界面

保留旧研究入口，新建/继续分析时进入 S1 工作台，不用新工作台阻止旧作品只读回看。列表可以按 HU/6-max、翻前/翻后、研究路径、覆盖身份筛选；旧局面条件不全标未知，不能猜成 HU。

工作台左侧为父子行动树/位置/历史，中间为局面账本与范围矩阵，右侧为组合、指标与来源；求解任务和版本历史沿用抽屉模式。主操作依次为“加载示例参考”“编辑我的范围/策略”“模拟分析”“建立对照”。默认无需完成全范围作答。

- 顶部持续显示桌型、活跃玩家、位置、筹码、抽水、公共牌与当前数据身份。
- 矩阵明确切换范围权重/行动概率，参考/草稿/假设有独立标识；零、空、死牌、不覆盖可辨别。
- 节点显示当前玩家、跟注增量、行动到总额、当前底池与剩余；Fold 进入终局，片段结束不假扮摊牌。
- 指标旁可查看定义、单位、玩家视角、范围模型与固定来源；无值不显示 0。
- 无覆盖/不支持时，仍可保存、编辑和返回上个覆盖节点；另开示例必须换到示例上下文。
- 对照页先记录预测/假设，再固定基准与变体，按有资格的指标显示差异，保存观察与有条件结论。
- 主要操作在 1440/1280/1024 宽度可用，键盘操作与抽屉焦点恢复保留。
- 顶部显示连接的本地 workspace 与保存 revision；MCP 修改可见地同步到当前作品。未提交草稿遇到冲突保留并提供重载/分支；服务失联不显示保存成功。
- 任务抽屉区分取消请求/已取消，页面关闭后作业仍可查询；界面重开获取同一 job。完整解只显示 manifest、当前页与依赖，不一次加载整树。
- 背景 HU/6-max、当前活跃人数、实际分析玩家、整体/局部模型分别展示；六人来源单挑结果不出现“整体六人均衡已解”。

## 2. 演示条件与账本

所有资产为作者合成，不是 GTO 表。公共默认：NLHE 现金、每人起始 100bb、SB=0.5bb/BB=1bb、无前注、无抽水、`100 units/bb`；没有遗漏扣费。只在双方投入相等且无待行动玩家时交接翻后。

| 路径/资产 | 明确行动历史 | 翻后底池 | 活跃玩家剩余 | 用途 |
|---|---|---|---|---|
| H-SRP | HU：SB/BTN raise-to 2.5，BB call | 5bb | 各 97.5bb | HU 第一闭环 |
| H-3BP | HU：SB/BTN raise-to 2.5，BB raise-to 10，BTN call | 20bb | 各 90bb | HU 第二线 |
| X-BB | 6-max：UTG/HJ/CO fold，BTN raise-to 2.5，SB fold，BB call | 5.5bb | BTN/BB 各 97.5bb | 六人背景的单挑 |
| X-3BP | 6-max：UTG/HJ fold，CO raise-to 2.5，BTN raise-to 8.5，SB/BB fold，CO call | 18.5bb | CO/BTN 各 91.5bb | 两个非盲位交接 |
| X-4BP | 6-max：UTG/HJ/CO fold，BTN raise-to 2.5，SB fold，BB raise-to 11，BTN raise-to 24，BB call | 48.5bb | BTN/BB 各 76bb | 4-bet 范围来源，仅翻前/交接预览 |
| X-SQ | 6-max：UTG raise-to 2.5，HJ fold，CO call，BTN raise-to 11，SB/BB/UTG fold，CO call | 26bb | CO/BTN 各 89bb | 冷跟/squeeze 来源，仅翻前/交接预览 |

call 金额是补齐到总投入，不重复扣整个 raise-to。弃牌投入保留底池：X-SQ 包含 UTG 2.5、CO 11、BTN 11、盲注 1.5。每条线还提供至少一条 Fold 终局并区分未跟注退还、最终争夺底池与净收益；不推断未知赢家。

上述尺度只是显式示例树，不宣称覆盖所有合法加注。用户输入其他尺寸可以保存；树/数据不支持应明确返回，不称其必然违反扑克规则。

## 3. 最低资产清单

| ID | 必需资产与深度 |
|---|---|
| AS-H01 | HU 两个根范围、完整根策略；2.5bb 开池后的 BB 回应；BB 3-bet 后 BTN 回应；两条声明线的完整路径范围 |
| AS-X01 | 六个位置的未开池示意策略，非盲位明确此前全弃；BB 为走牌到 SB 后 SB 弃牌的终局说明，不伪造 BB 未开池决策 |
| AS-X02 | X-BB/X-3BP/X-4BP/X-SQ 中所有决策点的节点策略、父子关系与来源；Fold 分支可操作，其余未展开行动显示片段结束/未覆盖 |
| AS-F01 | H-SRP 与 X-BB 各自独立的 A♠7♦2♣ 输入和结果；不能因牌面相同共用不匹配数值 |
| AS-F02 | X-3BP 的 K♣8♦3♠ 输入和结果；H-3BP 可只交接预览，未编写翻后参考时明确未覆盖 |
| AS-N01 | H-SRP 与 X-BB 各一条翻牌→转牌→河牌线；树内 OOP check、IP bet、OOP call，发牌前双方行动闭合；至少一条 check-through 变体；其他发牌未覆盖 |
| AS-E01 | X-BB 一个固定基准与两个固定对手假设（过度弃牌/偏多跟注），完整约束与配对结果；另一个自定义锁定未覆盖样例 |
| AS-V01 | 一个完整用户策略/一个修订策略及两份配对示例评价；一个仅频率差可算而 EV 不覆盖的编辑变体 |
| AS-M01 | 6-max 三人进入翻后配置（如 BTN open、SB/BB call）；可保存账本/范围，计算 unsupported，不给三人均衡结果 |
| AS-D01 | 首次失败、慢任务取消、质量不足、资源限制、无覆盖、资产缺失、损坏导入、旧库上传迁移中断及共享暴露事务中断各一可确定重放样例 |
| AS-T01 | 固定首次作答、按允许信息请求分析的证据需求、配对合成证据＋理论 refs、评价反馈、新题两版本（改变相关位置或公共牌条件）及答案暴露键；不宣称真实 GTO 错因 |
| AS-Q01 | 至少 16MiB 的确定性结构/分块存储测试资产及 manifest/丢块/损坏变体，明确不是扑克策略；另有双入口 requestId 重发、版本冲突、服务崩溃/重启脚本 |

每个可用参考决策节点都要求有效非零输入组合有完整分配。范围初值可由显式类别表展开到 1,326 组合，必须记录各类别权重与动作概率；任意未写项不得静默补成参考动作。编辑器始终支持完整 169 类/1,326 组合。

AS-X01 的“六个位置入口”不等于六个未开池决策：UTG/HJ/CO/BTN 可开池，SB 可弃/补盲/加注，前面含 SB 全弃时 BB 收盲终局。这一差异必须体现在入口文案和树中。

指标资产的声明目标组合至少含每个翻后参考节点的三类具体组合（如对子/非对子、不同花色），明确 metricsCoverage；其余组合策略可用但权益/EV 可缺失，不生成随机数补齐。若界面提供全范围 EV 聚合，必须该范围全部有效组合有同口径指标，否则显示未覆盖。

连续线使用显式命名动作与金额，翻后示例最多 check、33% pot bet、call、fold；bet 以行动前底池为基准，金额向最近最小单位取整，半单位向上，规则进入树版本。每节点保存精确账本，不能从 B33 文本反解析金额。HU 与 X-BB 即便动作相同也有不同金额。

内容发布前必须生成逐项 manifest：id/version/hash、输入条件、动作/范围/结果 refs、组合/指标覆盖、身份/限制与自检报告。AS-N01 的具体转河牌和每条频率表在 SO03 编写时落实为显式资产，先通过金额、牌面与引用检查，再允许发布；未完成 manifest 即 SO03 未完成。

## 4. 验收旅程

| ID | 用户过程 | 必须检查 |
|---|---|---|
| SJ01 | 新建 HU→加载参考→查看组合 | 无须提交自己的完整策略；来源明确合成 |
| SJ02 | 编辑双方范围/混频→撤销重做→提交→刷新 | 零/空/死牌、固定版本及组合统计正确 |
| SJ03 | 根节点→下注/加注分支→查看来源→返回 | 自身路径权重正确；分母明确；各节点草稿保留 |
| SJ04 | H-SRP 与 X-BB→发翻牌→转牌→河牌 | 历史、角色、账本、范围及结果同步；发牌顺序保留 |
| SJ05 | 6-max 六位置入口→筛选未开池与回应 | BB 收盲为终局；不复制 HU 表；未覆盖明确 |
| SJ06 | X-3BP/X-4BP/X-SQ→查看行动派生范围 | open/3-bet/4-bet/冷跟/squeeze 不混淆；固定来源可追溯 |
| SJ07 | 改抽水/筹码/尺寸→保存→模拟分析 | 输入保留、不套数值；unsupported 与 uncovered 区别 |
| SJ08 | 两人交接→三人配置→尝试分析 | 两人交接金额正确；三人不静默降为 HU |
| SJ09 | 固定旧解→改上游→看下游和历史 | 当前 stale；旧解仍可按旧输入打开，不能冒充新解 |
| SJ10 | 首次失败重试→慢任务取消→刷新中断→质量不足 | 重试旧规格，拒迟到结果，完成与质量不同 |
| SJ11 | 完整策略→频率距离→EV 缺失→修订 | 频率差不充当 EV loss；未提供值不是 0 |
| SJ12 | 写假设→基准→预置锁定→自定义锁定→对照 | 编辑保护不同于 Node Lock；未配对变体无伪收益 |
| SJ13 | 旧案例迁移两次→缺引用/损坏导入 | 幂等，旧库不变；未知身份不升级 |
| SJ14 | 研究关联题目→Agent/导出→中断→导入副本 | 同一暴露规则，无答案/未来泄漏；恢复固定引用 |
| SJ15 | Agent 建实验→打开真实成果→进入示例练习→回看 T1 | 共用命令，不制造另一份策略；T1 两课/知识/旧研究可继续 |

SJ04 需要 HU 和六人来源两种路径；SJ06 的三条路径不可只测一条后声称全部通过。SJ14 包括提交前拒绝答案与主动揭示后标辅助两种情况。

v0.3 更正 SJ10：浏览器刷新不等于本地任务中断，必须分别测刷新继续查询与运行时实际崩溃。AS-D01 的迁移/暴露中断不建立新旧双写。

| ID | 新增用户过程 | 必须检查/证据 |
|---|---|---|
| SJ16 | UI 创建局面/范围/固定策略→真实 MCP client 查询→批量编辑→UI 接手 | tools/list/call 的真实协议过程；同 workspace/ref，revision 递增，矩阵/来源相符；非直接调用应用函数 |
| SJ17 | MCP 创建局面/范围/规格→UI 浏览/修改→MCP 重查；关闭浏览器继续作业再打开 | 两方向都有新作品和固定版本；浏览器关闭不影响服务，重开同一持久 job/结果 |
| SJ18 | UI/MCP 同时改同 revision→重复 requestId→更换负载；独立题期间用工具和旧资源 URI 读答案 | 一次提交/一方冲突，无部分批量写；同键同负载重放、异负载拒绝；工具/资源统一拒绝或登记揭示，辅助身份一致 |
| SJ19 | MCP load manifest→分页查节点/组合/聚合→资源页→导出/损坏导入 | 实际 resources/list/read；每页项数/字节预算；16MiB 测试资产不进入工作区/Agent 全量上下文；丢块/缺依赖不激活 |
| SJ20 | 固定作答→请求分析证据→评价模块反馈→Agent 安排相关条件新题→首次再作答 | Attempt/输入/结果/规则/引用可追溯，改一个相关条件；Solver 不判理解，合成值不判真实 GTO；历史与辅助身份不改写 |
| SJ21 | 运行时任务→关页面/断 MCP→重连→取消请求/迟到→杀 worker/重启服务→显式重试→资源不足 | 页面关闭持续运行，取消请求与确认分开；实际中断才 interrupted，重试旧规格且幂等；不缩树、无全解快照；原件/任务状态保留 |

SJ16–SJ21 通过实际官方 SDK Client、stdio MCP server 代理、本地服务及 Playwright 浏览器联测。每个公开核心工具至少实际调用一次；不足覆盖的工具追加协议用例，不能以一条双入口旅程代表全工具通过。SJ20 的本地概念反馈必须与“数值未覆盖、暂不能判断真实行动”兼容。

## 5. 验证安排与交付证据

状态测试按领域不变量设计：组合/范围、规格/指纹、传播/账本、结果查询/比较、作业、导入/迁移/暴露。用有不同预期的输入验证，不编写只检查页面文字存在的测试替代机制。

浏览器/真实 MCP/运行时联测覆盖 SJ01–SJ21 及受影响的旧研究/编辑/训练/T1/恢复旅程；必要的变体单独列证据，不预先承诺最终测试数量。整轮类型检查、构建、状态、运行时持久化、协议与浏览器回归后更新交付记录。截图至少包含 HU 工作台、六人位置/回应、交接来源、结果口径、锁定对照、双入口接手、教学证据及恢复；另存脱敏协议过程/错误断言和字节/内存记录。

设计阶段仅检查文档链接、路径账本、任务/旅程追踪与差异；未执行应用测试。开发后生成 `solver-s1-delivery.md`，记录实际资产、通过项、未覆盖与偏差；此时不提前创建交付记录假装验收。

交付表逐项区分五类能力的设计/实现/协议实测/旅程通过、mock/真实来源、支持/未覆盖/不支持；提供每条 SJ 的输入/步骤/制品 refs/证据路径、实际测试结果、已知限制和整轮验证后的基线。R 交付另附固定引擎/算法/环境/采用方式、可复现输入输出、独立基准与阈值、质量、耗时/峰值内存；编译成功与单次试跑不能占“真实能力已验收”一栏。
