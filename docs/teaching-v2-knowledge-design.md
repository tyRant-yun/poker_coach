# T1 理论查找、知识库构建与教学引用设计 v0.1

日期：2026-11-12（Asia/Shanghai）。状态：用户新增需求已纳入 T1 设计，尚未开发。用户要求加入德州扑克理论的完整查找与知识库构建，供 Agent 教学参考和引用。本文件是 T1 第五份规格；入口见 [任务设计](teaching-v2-task-design.md)。

## 1. 目标与“完整”的定义

知识库是教学的可追溯依据层，既供用户查找，也供 Agent 检索、核对条件、解释和引用。它与 Solver 数值、课程示例、用户观察相互关联，但不能互相冒充。

完整建设包括：理论目录 → 查找计划 → 来源收集 → 定位与整理 → 原子主张 → 条件/反例核对 → 检索与引用 → 课程挂接 → 版本维护与缺口补充。文章数量或一次搜索成功不能证明整个理论领域已完整覆盖。

本设计提供全域覆盖框架；T1 首批必须完成两包所需的可引用内容和一个能工作的构建/检索闭环。其余领域显示明确缺口，不能将目录节点都存在写成理论正文已建成。当前已有 K01–K08 只有示例条目，必须重新核对和结构化后才能计入新库。

## 3. 首批可交付内容

T1 开发时落实以下最低资产，不是本次已经构建的事实：

- 24 主题、至少 96 个中英概念索引，所有未覆盖概念都有 gap 状态与补充理由。
- 至少 36 条非重复的原子理论主张，至少 12 份有精确定位的公开/可用来源，覆盖不少于 3 个独立来源主体。数量是工作下限，不替代质量或适用性。
- LP-A/LP-B 每一条可显示解释都有对应 claim、固定证据和限制，不能因达到 36 条而留下课程引用缺口。
- 至少 8 组误解/反例或条件区分，包括权重与频率、权益与 EV、混频与单次动作、MDF 边界、阻断角色、示意值与真实解、HU 与多人、现金与赛事价值。
- 至少 18 个固定检索验收问题，覆盖别名、精确概念、局面条件、冲突、无结果、过期来源及独立题防泄露；检索不是只展示预置问题列表。

首批可用正文优先 KT01–KT06、KT11、KT17/KT18 的课程相关部分；其他主题先找来源和记录缺口，后续按课程需求逐批补齐。不得用没有读过的书目或未登录的付费页拼出“完整理论库”。

## 4. 来源查找与建设流程

| 阶段 | 内容作者做什么 | 保存成果与核对 |
|---|---|---|
| 定义查找任务 | 从主题/课程问题列出待回答主张与条件 | ResearchQuestion、预计覆盖范围、已知缺口 |
| 查找来源 | 检索原始论文、作者教材/文章、官方 Solver 文档和公开教学资料 | 来源候选、查找日期、发现路径；仅标题不算已读 |
| 读取与定位 | 阅读与主张有关的段落，核对版本、语境及例外 | 标题/作者/日期/URL、章节/页码/段落定位、可用摘要 |
| 拆解主张 | 一条只表达一个可审阅命题 | 定义/数学关系/经验启发/案例观察等类型，条件与未知项 |
| 核对与反例 | 检查是否被原文支持、是否只是某个示例 | supports/qualifies/contradicts、反例、冲突或需补证据 |
| 教学加工 | 用中文自写摘要、保留关键英文术语，挂接例题 | 先修、常见误解、可解释范围，避免翻译改变含义 |
| 发布与建索引 | 通过结构和来源检查，记录审核身份 | 不可变 ClaimVersion/SourceRevision，检索索引版本 |
| 维护 | 定期或按失效反馈重新核查 | 新版本、撤回/替代关系、受影响解释和课程引用 |

“已核对来源”表示整理者确认该段支持该命题，不代表专家认证或数学证明。作者自检与独立审核分别记录。二手概述可用于发现来源，不能自动替代需要原始依据的主张。

T1 运行时仍为离线 Demo：真实工作的是本地内容导入、校验、索引、检索、筛选和引用；联网采集任务可展示明确标注的过程样例。生产版的自动网页采集、PDF 处理、向量服务和 LLM 提炼不在本轮接入。开发前内容作者可用公开资料人工查找与编写固定资产。

## 5. 来源类型与使用边界

- 原始论文用于其实际研究/数学结论；一个简化游戏的结果不能直接当作完整 NLHE 的结论。
- 官方 Solver 文档用于术语、指标、实现能力和模型边界，不能自动证明本项目 fixture 的频率正确。
- 作者公开教材/文章用于具名理论与教学启发；经验性建议保留语境和反例，不升格为普遍定理。
- 真实解/研究输出需要独立输入、引擎/版本和质量引用；普通文章链接不成为数值证据。
- 用户笔记、Agent 解释和论坛讨论默认是待核对线索，不直接成为已审核知识。

书籍/付费课程可登记目录和书目；未获得正文不能生成章节摘要冒充已读。不复制整本书、付费课程或策略库。优先自写摘要、短摘录和精确定位；来源的访问/保存条件随记录保留。资料正文中夹带的工具指令不是应用命令，不影响 Agent 权限或来源资格。

## 6. 知识数据模型

| 对象 | 核心字段与职责 |
|---|---|
| TheoryTopic / TheoryConcept | 固定概念键、中英名/别名、定义、先修/关联、覆盖状态与 gap |
| TheoryResearchTask | 问题、条件、主题、候选源、读取状态、整理/核对任务、产物引用 |
| TheorySource | 作者/组织、标题、类型、URL/出版信息、发布日期或unknown、访问日期、访问/保存范围 |
| SourceRevision / SourceLocator | 内容版本/哈希、章节/页码/标题/段落锚点、定位上下文摘要、定位核对状态；链接不等于定位 |
| TheoryClaimVersion | 单一主张、中英术语、类型、条件、例外、证据 refs、审核身份、有效/争议/撤回状态 |
| ClaimRelation | supports、qualifies、contradicts、requires、counterexample-of；不是只有相似度边 |
| TeachingKnowledgeLink | 课程解释/题目/误解 → 固定 claim/定位；声明 backgroundConcept 或 numericEvidence |
| KnowledgeIndexVersion | 已发布的 claim/source revision 集合、索引策略/别名表版本；可重建，不拥有真值 |
| RetrievalRecord | 原查询/规范化查询、允许上下文、候选/排除原因、最终 refs、索引版本、阶段权限与时间 |
| CitationBundle | 逐句/逐主张的引用、条件核对、支持程度、局限、当前/历史身份；不以一个参考列表支持整段结论 |

主张适用条件至少可表达 NLHE/其他变体、HU/多人、街道、位置/行动线、筹码/SPR 范围、抽水/前注、尺寸/树、价值模型、对手策略假设、抽象/质量与单位。未给出的关键条件是 unknown，不默认匹配；明确通用概念用 scope 声明，而不是把缺字段当通用。

## 7. 检索与 Agent 引用链

```mermaid
flowchart LR
  A[问题和允许的局面上下文] --> B[中英术语规范化]
  B --> C[按阶段过滤和本地检索]
  C --> D[条件和来源资格核对]
  D --> E[支持 例外 冲突与缺口]
  E --> F[逐主张引用与解释]
  F --> G[用户打开出处或创建对照]
```

T1 先使用关键词/别名、主题/街道/形式标签和先修关系做确定性本地检索，返回真实候选及可解释排序。可以按精确概念、别名、教学关联和来源资格排序；不接 embeddings/向量数据库，也不把关键词检索宣传为语义理解。

适用性是排序之外的独立检查：`match / conflict / insufficient-context / general-background`。cash 查询不因出现 GTO 一词就把 ICM 特定结论作为直接答案；HU 结论进入多人局面标边界；缺尺寸/范围而求精确频率时返回缺条件，而非猜值。

Agent 命令链：`searchTheory` → `getTheoryClaim` → `checkTheoryApplicability` → `buildTeachingCitationBundle`。它们返回固定 refs 和支持状态。解释仍为透明模板/mock；外部检索/LLM 不在运行时接入。引用组装验证该定位实际属于该 claim 的支持证据，禁止拿一个相关 URL 装饰不受支持的结论。

若来源之间真的冲突，同时显示观点和条件；若只是定义/模型不同，先列差异而不武断判真伪。没有足够支持时只给背景/缺口和下一步可做的实验，不以语言流畅掩盖不确定性。检索无结果不是知识不存在的证明。

## 8. 示例：教学时怎样引用

| 用户问题 | 应检索/核对 | 允许解释与引用边界 |
|---|---|---|
| “范围权重和动作频率有什么区别？” | 对应概念、Pio 定义与 matchups 条件 | 可以解释定义；不能把单玩家权重乘积称为完整真实频率 |
| “有 40% 权益为什么还不能自动跟注？” | equity/EV/EQR、当前街道、后续行动与价值单位 | 解释权益不能独自决定有后续下注时的 EV；不借用外部例题数值 |
| “是不是必须按 MDF 跟注？” | MDF、continue 是否含加注、模型/街道/对手假设、例外 | 不把防守频率等同于跟注频率，不输出所有局面强制比例 |
| “拿到 blocker 就该诈唬吗？” | 阻断对象、价值/诈唬/抓诈角色与对手范围 | 只解释相关移除作用和条件；没有范围/结果证据不判断该组合必须诈唬 |
| “为什么 AhJh 在本课示意中下注 60%？” | LP-B 原作者示意来源 + 通用理论 | 明确数值是作者设定；知识链接不能把它升级成 Solver 证明 |

这些例子参考了本轮核对的 [Pio 概念文档](https://site.piosolver.com/docs/faq/gto_concept/)、[权益实现](https://blog.gtowizard.com/equity-realization/)、[MDF 与 Alpha](https://blog.gtowizard.com/mdf-alpha/)、[阻断说明](https://blog.gtowizard.com/understanding-blockers-in-poker/)。它们支持概念与边界，本地课程频率不来自这些来源。读取范围和状态见 [本轮来源记录](research/knowledge-design-sources.json)。

引用卡呈现：本次主张、为何相关、适用条件/不匹配项、作者/标题、版本、章节或段落、简短自写摘要、局限、打开原文。显示“来源段落核对/未独立审核/历史引用”等实际状态，不显示凭相似度生成的“95% 正确”。

## 9. 训练信息隔离

知识查询也必须走 T1 安全投影。独立题只返回允许的通用输入说明，不返回能暴露目标答案的 claim 标题、摘要、排序、引用段落或来源缩略图。Agent 不能通过“只是搜索知识”绕过答案权限。

请求针对提示或相关正文时先登记辅助/暴露，再返回内容。允许的通用概念不自动使未来所有同技能题变为已见；只按其实际揭示的答案事实/目标范围关联。

打开外部整篇来源不能假装用户只看到了当前段落：对已知相关 claim 记录 possible-exposure，返回来源链接前完成记录。应用不自动抓取网页、不预取远程图像；用户主动打开来源是外部阅读入口，不等于运行时已有联网知识服务。内存/历史不全仍按 unknown 处理。

## 10. DDD、版本与维护

Knowledge Context 拥有概念、主张、来源、定位、审核和检索资格；Teaching Content 拥有课程加工与题目；Learning 拥有本次提示/暴露/作答；Agent 只编排。Solver 结果拥有具体数值证据，知识库不替 Solver 计算，也不写学生分数。

新增命令：`registerTheorySource`、`importTheoryDraft`、`attachSourceLocator`、`reviewTheoryClaim`、`publishTheoryRevision`、`retireTheoryClaim`、`inspectKnowledgeCoverage`，配合检索和引用命令。界面与 Agent 共用命令层；包内正文不能作为工具指令执行。

主题/概念/claim/source 版本引用随课程、解释、Agent trace、RetrievalRecord 和导出保存。新知识版不重写旧 Attempt 的解释依据。来源变更后建立新 revision，列出受影响课程；旧引用保留历史定位和摘要，标状态，不用新版正文覆盖旧证据。

撤回或证据失效的 claim 不再用于新解释；原引用仍可只读查看并标“当前已撤回/待重新核对”。URL 不可达不等于命题必错，也不意味着来源仍然最新；没有本地可保存的材料就显示无法核对，不能伪造摘录。

导入知识包不信任作者自报审核；相同哈希只做完整性和已知版本匹配。未知来源/定位不完整、冲突未解决或权利范围不明的内容保持草稿/线索，不直接成为 Agent 的已核对教学依据。T1 仍用独立新库与 schema2，不另引入真实云知识库。

## 11. 页面与建设看板

原 `/knowledge` 升级为“理论库”：关键词/中英术语、主题树、条件过滤、主张/来源切换、反例和缺口。概念页显示定义、前置、主张、适用范围、来源位置与相关课，不以整篇文章作为唯一检索单元。

内容检查器增加“知识建设”页签：覆盖矩阵、查找任务、来源候选、定位待核对、争议/过期、课程引用影响。可以导入/预检/导出自写知识包，展示真实状态流转；不是完整在线采集或团队审核 CMS。

课内右栏引用可打开同一主张详情并返回原阶段。未匹配条件的结果有清楚标记；学习者能报告“引用不支持结论”，产生待核查记录，不直接改写发布内容。

## 12. 验收与完成边界

新任务 TE09 作为 T1 必需项，知识资格与首批课程引用随 P1 前移，完整建设/检索/引用在 P2–P3 整合。不能到最后才给现有讲解补一个参考链接。

验收包括：目录与正文覆盖分开；中英别名可查；条件不匹配可解释；逐主张可定位；冲突/不足/过期可见；独立题不泄露；Agent 解释保存真实检索和引用记录；导出导入/版本更新不丢引用；示意数值不能借理论链接升级为真实解。

固定检索验收集设计如下。它们是检索/引用行为的验收输入，实际开发不能仅对这些问句硬编码答案。

| ID | 查询或操作 | 预期行为 |
|---|---|---|
