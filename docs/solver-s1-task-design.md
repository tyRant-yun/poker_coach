## 2. 能力与范围

| 能力 | S1 必须实现 | 后续真实计算目标 |
|---|---|---|
| HU 翻前 | SB/BTN 与 BB、行动路径、完整组合编辑、合成策略与范围来源 | 固定游戏模型下的翻前近似均衡求解，明确翻后价值模型 |
| HU 翻后 | 固定输入、节点策略/指标浏览、两条连续线及实验 | 双人翻后引擎，质量与资源验证 |
| 6-max 翻前 | UTG/HJ/CO/BTN/SB/BB、逐位置未开池入口、声明的回应分支、范围库 | 六人翻前引擎或有来源的固定解；不能用双人求解替代 |
| 6-max 单挑翻后 | 携带指定翻前路径的两方范围、底池与筹码创建分析 | 双人引擎；明确是否考虑弃牌玩家 bunching |
| 6-max 多人翻后 | 保存三人以上局面，明确不支持计算与可继续的配置 | 多人求解单独验证，包括边池及质量定义 |
| 任意条件/尺寸 | 保存、版本化、预检；无配对资产时未覆盖 | 由引擎能力决定，不隐式换成最近预置 |

S1 仅 NLHE 现金局，演示规格为 100bb、无前注、无抽水；这是减少演示变量的设计默认，不是推荐范围条件。抽水规格进入模型，非零抽水可保存但无配对结果。不同筹码、抽水、尺度不可套用原结果。

五类能力（HU 翻前、HU 翻后、六人翻前、六人背景单挑翻后、多人翻后）分别记录：设计状态、产品实现/协议实测/旅程通过状态、支持操作/范围模型、计算来源与质量证据。当前 S1 均未开发，真实计算均未通过验证；多人翻后本轮仅配置/明确 unsupported。六人背景交接后的双人局部结果不能标整体六人均衡。

不接真实 Solver/LLM/规则引擎/云服务，不添加 API Key。不把全文献研究、独立专家审核、完整六人 GTO 或完整合法动作裁决纳入已完成口径。Hero 任意尺度与混频表单继续按原要求暂缓；范围矩阵混频与有结构的树尺度配置在本轮范围内。

S1 新增本地业务运行时与真实 MCP server/client，均属本机产品基础设施；计算继续 Mock。范围编辑、版本、查询、任务、协议调用、持久化和恢复必须真实执行，不以同名函数或假 MCP 响应替代。

## 3. 执行方式

后续收到 S1 开发指令后，以同次尽量完成 P1→P2→P3 全部批次为默认目标。下列包是内部检查点，不要求逐包重复批准；必要校验、保存提交后继续。实际无法继续时记录已实现内容、失败证据与续接点。

| 连续工作包 | 用户闭环 | 主要任务 |
|---|---|---|
| P1 HU 研究闭环 | UI/MCP 连接同一本地服务→选 HU→编辑/保存范围→参考/行动范围→双入口接手 | SO01/02/03/04 首条 HU 线；SO08 权威存储/迁移、SO09 实际 MCP client 前移 |

| P3 实验与整合 | 固定策略评价→锁定对照→固定作答/证据反馈/相关新题→大结果/异常恢复 | SO07/08/09 与全部 SJ01–SJ21 旅程 |

持久化、信息隔离、资产检查随首个消费者交付，不能延迟到 P3 后补。保留现有 `/study/:caseId` 等入口，增量提取模块，不整体重写已验证应用。

v0.2 新增开发原则：理解现有数据流→固定版本→最小复现→薄适配→独立核验→受控升级。SO01/02/04/06/07 的合同设计必须对照复用方案；S1 只落实 DTO/索引/能力和 mock 合同，R1/R2 才运行和接入引擎。优先候选为 postflop-solver，产品桥参考 Desktop Postflop，TexasSolver 为第二候选。候选不是已通过选型，不让 mock 工作台形成未来必须重写的独立求解内核。

## 4. 详细任务

### SO01：能力、规格与独立分析入口

依赖：配套设计。产物：CapabilityDescriptor、AnalysisSpec、预检、唯一本地业务运行时、MCP server/实际 client 首条调用与界面入口。

- 显式区分加载已有参考、求近似均衡、固定策略评价和锁定后重新分析；S1 对后三者展示模拟执行身份。
- 读取参考/求均衡不要求填完用户策略；固定策略评价要求提交并固定策略。
- 预检分别返回 invalid、unsupported、uncovered；输入可保存，不为通过预检自动删尺寸或修改范围。
- 演示速度、故障和跳过等待与扑克输入分离；任务显示固定规格、时间线和结果入口。
- 落实共享 `riverline-analysis/1` schema 和所有权；声明桌型/背景/活跃人数/计算玩家及整体/局部/后续价值模型。
- 先建立 UI/MCP 共用服务和持久写入口，按运行时合同暴露 capability/spec/preflight/load/start/get/cancel/retry 工具；采用真实 SDK client 连接，不另建 MCP store。
- Mock worker 在业务进程管理下独立执行；取消请求/确认、资源限制、作业事件持久保存，页面关闭不丢任务。

验收：SJ01/07/10/16/21；真实 initialize/tools/list/call 的首条链可执行；自定义尺寸保留且没有误配 EV，多人请求在执行前明确能力限制。

### SO02：通用玩家、范围与策略版本

依赖：SO01 的规格定义。产物：PlayerId/位置映射、RangeVersion、PolicyVersion、统一矩阵查询与编辑。

- 取消新模型对 BTN/BB 的强制字段依赖；HU 明确 SB=BTN，6-max 明确六个位置及行动顺序。
- 1,326 组合为底层，169 格为聚合；范围权重与行动概率分开，零/未填写/死牌分开。
- 双方/多方范围编辑、批量、混频、编辑保护、撤销重做、提交、分支与恢复真实执行。
- 输入范围、行动派生范围、人工假设、导入数据具有独立来源；覆盖率只对声明有效范围计算。
- 继续使用固定精度整数保存用户输入，派生乘积不得逐步粗糙取整导致范围消失。
- range read/edit batch、policy edit/submit 及分支/撤销重做使用同一业务服务并通过 MCP 开放；批量原子校验、expectedRevision/幂等按运行时合同执行。派生范围修改另建假设，不覆盖来源解。

验收：SJ02/03/16/17/18；对子/同花/非同花映射 6/4/12 个组合，零权重不算漏填；两入口接手与批量失败无部分写入，旧编辑旅程不退化。

### SO03：显式内容资产与预检

依赖：SO01/02；与 SO04 的首条 HU 线一起交付。产物：资产 manifest、固定树/范围/策略/指标、内容检查结果。

- 按配套内容规格完成 HU 两线、6-max 六位置入口（BB 收盲为终局）和四类回应线。
- 每个发布的参考决策节点对其有效非零输入范围提供完整频率分配；不能用六个示例组合冒充完整范围。
- 频率可用自写显式手牌类别表展开，但不得按数组下标、哈希或牌名生成伪策略/EV。
- 输入范围不等于六人联合牌分布；局部范围传播限定为明确的简化结构计算。
- 检查卡牌、概率、金额、父子关系、角色、引用、动作支持、节点与结果输入匹配；未通过资产不可作为可用参考发布。
- 补全 AS-T01 固定作答/证据/反馈/相关条件新题链和 AS-Q01 大制品/分页测试 manifest；测试填充不标为新增扑克解。

验收：资产清单逐项可打开；人为损坏至少概率、账本、丢引用三种资产能定位并拒绝发布；明确“作者合成、自检、无战略正确性验证”。

### SO04：行动树与范围传播

依赖：SO02 与 SO03 首条资产。产物：父子树、历史路径、到达范围查询、失效关系。

- 区分决策、发牌、弃牌终局、摊牌占位和片段结束，不能平铺目录替代父子关系。
- 切换节点同步行动者、行动历史、底池、剩余筹码、双方范围与来源；返回保留各节点草稿。
- 本玩家行动派生权重可真实计算，明确这是自身路径权重，未完成卡牌相关的联合后验计算。
- 对手行动后的跨玩家牌移除推断与 bunching 不伪造；查询展示模型身份。
- 上游变化创建新分支/修订并标记后代 stale；旧结果可按旧输入查看，不自动成为当前节点参考。
- range_derive、situation revise 与节点历史通过 MCP 调用相同服务；真实条件到达概率无计算时明确 unavailable。

验收：SJ03/04/09；零到达分支不归一化、不展示有效策略；Fold 后不能发未来牌；转牌与河牌顺序固定。

### SO05：6-max 翻前范围库与研究

依赖：SO02/03/04。产物：六人位置入口、行动上下文筛选、固定范围集合与分支。

- 筛选 HU/6-max、位置、未开池/面对开池/3-bet/4-bet/squeeze、筹码、尺寸与抽水。
- 前面位置弃牌必须有历史；“BTN 对 BB”不能丢掉桌型与此前行动。
- 六个位置入口有配对示意策略或终局：UTG/HJ/CO/BTN/SB 提供声明的未开池决策，前面含 SB 全弃时 BB 为收盲终局；完整研究仅覆盖内容规格声明分支，其他显示未覆盖。
- 用户可以修改完整范围并保存版本；新输入不因动作名称相同沿用示例收益。
- MCP 可创建/查询同一六人路径和范围来源；同时展示背景六人/当前两人/分析两人/局部模型，不把连接翻后升级为六人整体解。

验收：SJ05/06；HU 与 6-max 同名位置查到不同规格；未覆盖位置/尺度组合不被范围库模糊搜索替代。

### SO06：翻前到翻后交接与结果浏览

依赖：SO04/05。产物：PostflopHandoff、固定 SolutionArtifact、节点/组合/聚合查询和浏览器。

- 从已完成的可交接路径携带范围、剩余筹码、底池、IP/OOP、抽水、弃牌历史和精确来源引用。
- 发牌与输入范围冲突检查后创建翻后规格；更换牌面创建新规格，不改写历史。
- 浏览策略、范围、权益/动作 EV 的合成示例；指标有玩家视角、单位、基准、条件与覆盖状态。
- 聚合严格区分范围质量、行动频率与到达概率；无数据返回缺失，不填零。
- 两名活跃玩家才允许本轮单挑分析；多人和不对称筹码引起的不支持独立显示，不静默转 HU。
- 实现 MCP solution/node/combo/aggregate/handoff 与受控 resources/read；每次检查允许信息与固定版本，旧 URI 不绕过策略。
- 完整解独立制品化，工作区仅 manifest/ref；组合/节点按需分页，响应字节预算及缺块校验真实工作，Agent 默认只收摘要/引用。

验收：SJ04/08/19/21；配套路径账本正确；缺来源/未覆盖上游不获得配对参考身份；16MiB 结构测试资产按页读取且不进入工作区快照/Agent 上下文。

### SO07：策略评价与 Node Lock 实验

依赖：SO01/02/06。产物：EvaluationSpec、ComparisonArtifact、固定基准/变体与 LockConstraint。

- 用户策略与参考分离；结构与频率距离可真实计算，EV/最佳响应/可利用性继续只展示精确配对合成数据。
- 非最高频不自动判错；频率差不转成 EV 损失，动作 EV 加权不冒充整棵树策略价值。
- 编辑保护不进入求解约束；Node Lock 指定玩家、节点、组合、动作频率及其余策略处理方式。
- 用户先记录假设，固定基准后建立变体；展示受控变量、派生变化、可比性与有条件结论。
- 未覆盖的自定义锁定可保存并模拟返回未覆盖；不得借用预置锁定的数值。
- policy_evaluate 与 experiment create/compare/conclude 在 MCP 可操作并返回固定制品；共同评价分布、收益原点/投入/抽水不明时禁止定量排序。

验收：SJ09/11/12；同一局面、不同用户策略的评价指纹不同；无指标时结论允许不足，不能自动宣传剥削收益。

### SO08：持久化、迁移与运行恢复

依赖：随 SO01/02 首个消费者前移。产物：唯一运行时持久存储、独立制品仓、旧模型只读导入桥、备份/故障恢复。

- 采用运行时合同的单一权威工作区/事务日志与制品仓，保留两个旧浏览器库只读迁移；不升级旧合成身份、不双写新旧活动状态。
- 中断恢复先查已登记成果，重试固定旧输入；取消后拒收迟到结果；跳过等待不越过结果校验。
- 导入先结构/语义/引用预检，再原子写入；ID 重映射处理所有关系，内容身份与暴露语义键不重置。
- 缺资产、损坏数据保留原件与只读状态；刷新不静默套当前 fixture。
- 浏览器断开不停止作业，运行器实际崩溃才 interrupted；操作结果持久幂等、取消确认前保持请求态。未验证 checkpoint 时重试明确是重跑。
- 教学/暴露状态迁移进同一权威服务；tools/resources/导出先持久登记后揭示，丢响应重试不制造新身份。

验收：SJ10/13/14/18/19/21；本应用重置仅影响声明数据；备份往返恢复固定依赖，缺块不激活，运行时重启与重复请求不重复成果。

### SO09：教学、Agent 与整轮交付

依赖：SO01–08；client 首条验证随 P1 前移。产物：全核心工具清单/schema、真实 MCP 协议测试、双向接手、教学证据链和交付记录。

- Agent 完成“读取范围→检查来源→建锁定分支→请求模拟分析→记录对照”脚本，保存真实制品引用；不新增自由 LLM。
- 研究结果进入教学前经过内容资格与暴露检查；用户主动打开研究答案也必须登记暴露。不能用新库绕过旧题身份。
- 保留 T1 两课、知识库、原训练与复盘，不趁本轮整体重组课程；新增一条从研究结果进入受控示例练习的证据闭环。

## 6. 真实 Solver 后续任务包（独立范围）

以下是具体候选工作，不包含在 S1 Demo 完成条件中，也尚未实施或选择引擎。无需逐个技术实验增加用户审批；只有从既定 mock 边界转入真实集成时需要新的范围指令。

| 包 | 前置与工作 | 必须产出/通过条件 |
|---|---|---|
| R1 引擎与模型验证 | 获真实计算范围指令；按复用方案 U2/U4 固定候选 commit、依赖/许可、机器资源、输入输出与质量口径；先编译原生示例再独立小树试算 | 候选矩阵、可复现命令/输入/输出、计算与内存记录、组合/金额一致性、与独立基准的差异说明；失败可结论不采用 |
| R2 双人翻后真实适配 | R1 候选通过；按 U3/U4 依赖原引擎并编写薄适配，河牌→转牌→翻牌，局部进程/服务边界，进度/取消/存档/查询 | 精确输入绑定、组合/动作映射、独立浏览游标、浮点保真；质量指标含定义/单位/范围；原生与适配调用一致，另有独立参考及预定阈值；不重写 CFR |
| R3 翻前与六人专项 | 分别验证 HU 翻前、六人翻前的下注抽象、翻后价值、抽水、卡牌相关、质量及资源需求 | 模型说明、范围生成来源、按位行动树、固定基准；不能用全下权益近似冒充深筹码完整解；多人翻后仍需独立通过才开放 |

不能用“迭代次数足够多”替代均衡质量。传统双人零和结论不自动适用于多人或含抽水模型；由候选算法与价值模型决定可声明的保证。读取外部已有解与实时计算为不同能力，来源、版本、许可和质量分别验证。

R1 必须额外记录运行环境（OS/架构/CPU/RAM、工具链、线程/压缩）、实际采用方式（依赖/fork/进程、补丁）、组合索引/金额/EV 口径、可复现输入输出、独立基准与预先声明误差阈值、质量定义、耗时/峰值内存。阅读源码、成功编译、运行一次或原生/适配同源一致，均只算中间证据。

R2 复用 S1 的唯一本地服务/MCP/制品仓，替换计算适配而不另建工作区；增加实际引擎取消延迟、进程异常、查询/存档/恢复和完整业务旅程证据。R3 将 HU 翻前、六人翻前、多人翻后逐项记录模型/基准/质量/资源/通过状态；其中一个通过不能替另外两项，六人背景下的两人局部结果不计六人整体均衡通过。
