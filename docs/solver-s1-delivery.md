# S1 Solver 与范围开发记录

日期：2026-11-13（Asia/Shanghai）。状态：**SO01–SO09 的本地 Mock 实现与自动验收完成**。用户已发出“开始开发任务”并要求“继续开发”，本轮连续完成 P1→P2→P3；R1–R3 真实引擎未执行。此记录是本地 Demo 的开发验收，不代表真实 GTO 能力或用户正式产品验收。

## 1. 已实现的本地闭环

- `/solver` 工作台与唯一本地 Node 运行时，stdio MCP 代理使用同一应用服务、磁盘状态、版本和暴露账本。浏览器断开不终止任务。
- 13 个显式路径入口，含 HU 两线、六个位置入口（BB 收盲终局）、6-max 的 SRP/3-bet/4-bet/squeeze 及多人不支持配置。自写类型化频率规则展开到 169 类/1,326 组合，不是求解得到的 GTO。
- 双方范围批量编辑、保护、撤销/重做、分支、策略混频与固定提交；参考/用户策略分开，已填写范围可见；来源链与固定版本查询。
- 精确配对参考/模拟作业、取消请求及确认、失败/重试/中断、质量不足和未覆盖；节点/组合/聚合按需查询。缺失不补零，自己的路径质量不称真实到达概率。
- 固定策略频率评价、有限的两策略配对合成收益示例、自定义锁定未覆盖、两个精确声明的锁定预置、比较资格与结论；Agent 调用同一业务命令建立真实实验/轨迹。
- 固定概念作答→引用分析/自写结构概念反馈→改变位置/前序行动的新题→实际首次迁移作答。只评价已声明结构概念，文本理由不自动判理解，合成结果不评价真实 GTO 对错。
- 内容清单/版本/树哈希及牌面、概率、账本、引用检查。固定结果独立保存，资源读取与工具/界面遵守同一允许信息规则。
- checksummed 磁盘日志、单写者锁、分块制品、1MiB 请求与有界查询、分块备份恢复、旧库只读封存/幂等导入、明确本应用索引重置。

金额输入保存为 1/100 bb 整数；动作 `to` 为加注至，节点账本保留投入/退还，派生权重保留浮点乘积。合成 EV 以当前节点、指定玩家为原点，不含已投入、无抽水；有抽水的自定义输入无配对指标。整体策略收益只对精确声明的两份固定合成策略提供示例，`evLoss` 仍缺失，不从频率差换算。执行、覆盖、可用性、演示质量分别记录。

## 4. 运行与 MCP

```powershell
npm ci
npm run dev
```

访问 [Solver 与范围](http://127.0.0.1:5173/solver)。启动器会先启动 5174 本机运行时，再启动 5173 页面。持久目录默认 `.data/riverline-s1/local`，已被 Git 忽略；旧浏览器两个数据库保持原件。可独立运行 `npm run runtime`；生产预览 `npm run preview` 也需要本机运行时。

MCP 启动器为 `scripts/mcp.mjs`，可从其他工作目录启动，连接已运行的本机服务，不自己创建第二工作区。一般 stdio 客户端配置示例（未自动修改用户客户端配置）：

```json
{
  "mcpServers": {
    "riverline-analysis": {
      "command": "node",
      "args": ["E:/poker_coach/scripts/mcp.mjs"]
    }
  }
}
```

工具参数中的 `workspaceId` 默认本机服务为 `local`。写操作需要唯一 `requestId` 与当前 `expectedRevision`；固定引用可用 `id@version` 查询，冲突不会静默覆盖。`npm run test:mcp` 启动临时独立运行时和实际 SDK 客户端，不能用函数测试代替。

## 5. 边界

真实 Solver/规则引擎/LLM 未接入；候选源码研究不记作验证复用。多人翻后仅配置，五类状态必须区分合成与真实；六人来源的双人局部分析不构成整体六人均衡。任意自定义输入保留但不保证有数值。

旧 T1/原训练的历史状态仍由原 Demo 浏览器库保存，本轮没有把旧业务全部重写成 MCP 命令。新 S1 的活动作品只在 Node 服务维护；旧数据迁移只读封存、不双写。进入旧页面也核对 S1 权威服务，独立题时阻断；已有 S1 研究/暴露时，后续旧版作答从权威状态投影为可能暴露/辅助，不建立另一份新的 S1 账本，也不倒改历史首次记录。该保守规则可能把无关旧题也标为已辅助。

当前备份恢复绑定同一 workspaceId，不自动合并不同工作区或重写原课程身份。旧库迁移保守登记可能暴露；旧首次作答、报告、源字段封存原意，不补造新引擎字段。重置索引保留磁盘孤立制品以避免误删，暂未做空间回收。权威存储采用完整元数据事务日志，未实现生产级压缩/归档；完整解不写入元数据日志。
