## 方法与实际操作

使用 computer-use 技能的 @oai/sky，在用户现有 Chrome 的本地5174页面直接点击、阅读截图、滚动、输入；后续为避免占用用户正在使用的窗口，改在独立 in-app browser 读取同一手牌。没有通过HTTP脚本、MCP业务命令、注入手牌或固定样例代替本次练习。未读取未知对手底牌或未来发牌。

在用户现有工作区实际新增第12手HU练习：Hero BB，4♦6♠。对手翻前补齐，Hero过牌。翻牌4♥6♦J♠，标记疑问后下注1bb（半池），对手跟注。转牌J♥，Hero过牌，面对2.60bb下注再次标记并跟注。河牌7♦，Hero过牌后结束，本手Hero +4.60bb，保存5次原始决策、2个疑问。

从结束按钮进入复盘，选择翻牌疑问，连续滚动寻找手后分析；报告显示真实局部分析3/5，翻牌只展示事实和未接入说明。实际点“研究此决策”，进入标题“河牌研究”的页面，来源却是第12手翻牌决定，并显示暂不支持真实求解。实际输入并保存试用问题：翻牌两对半池下注是否合适，转牌J配对如何调整价值下注和跟注范围；观察到“研究问题已保存”。

在同一手选择转牌跟注，看到真实局部报告，再点“图形深入研究”。已观察同一Hero 4♦6♠、同一转牌4♥6♦J♠J♥，报告和研究中的跟注EV相符。点击“返回原手牌”后，复盘回到整手结束视角，未保留所选转牌跟注决定。

## 实际读到的转牌数据及边界

- 行动前底池6.60bb，待跟注2.60bb，直接底池赔率28.3%。
- 参考范围下权益28.8%；弃牌EV 0，跟注EV约+0.046bb；显示跟注100.0%、假设内EV差0。
- 模型就地说明“转牌单尺寸、无再加注，后续河牌过牌摊牌”。它未评价所有合法行动，也没有覆盖真实后续下注的影响。
- 深入研究的根底池输入4bb、有效后手98bb，OOP/IP范围91/84组合；转牌下注2/2.6bb，双方河牌下注均0。
- 研究当前节点显示底池6.60bb、弃牌/跟注，但“研究行动路径”仅有“根节点”；缺少从4bb根经过过牌与对手下注2.6bb到当前决定的可读路径。

这些数字是局部假设内真实计算，不足以证明当时跟注在完整牌局里正确。未进行更换参考范围的敏感性计算，不能声称换范围后结论反转。

## 为什么研究没有贯穿全局

已交付应用只对一般HU河牌与受限HU转牌接入、验证了真实引擎；翻前策略来源、真实翻牌适配、多尺寸转牌、多人均衡和跨街条件范围仍未完成。AR1完成了有限模型的自动输入和报告，并没有补齐这些能力。

全局研究还需要把翻前策略、沿公开行动条件化的范围、各街下注树与可复核结果连起来。当前各街的有限默认范围并不构成这样的贯穿链。本次没有测量完整翻牌树或全局求解资源，不能以“性能不够”为已经证明的原因。

即使尚未完成全街求解，产品仍应完整保留四街原问题、事实、证据来源、能力状态和继续学习路径。局部求解边界不应变成用户旅程和研究对象的边界。

## 建议优先顺序

1. 先修复UX02/03/05/06/07的来源、布局、路径和返回上下文，按本次真实手牌复测完整问题路径。
2. 将范围/行动/后续街道覆盖变成结果的一部分，完善UX04的假设敏感性与解释，避免把模型内最优当成整手指南。
3. 独立推进翻牌薄适配与数值/性能门、受限转牌后续下注扩展，以及有来源的翻前策略与条件范围；HU与六人分别验收。
4. 把问题、结论与同目标再练连接起来。验收标准是用户能回答自己的原问题并知道下一手练什么，而不只检查按钮和矩阵是否出现。
