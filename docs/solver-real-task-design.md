## 1. 目标和首版范围

最终闭环是：配置局面和范围→预检→真实计算或加载固定解→浏览 Hero、全范围和行动路径→固定策略评价/锁定实验→保存可追溯结论→由评价与教学模块消费证据。

第一条真实交付线限定为现金局、两名决策玩家、无抽水、无 bunching、离散且显式的下注树。先河牌，再转牌，再翻牌。每街分别开放能力，不能编译一次就同时宣告支持。自定义合法尺寸属于真实树配置；无法精确表达时返回不支持，不靠旧 fixture 或合并尺寸补位。锁定和固定策略评价后置到基础求解、查询通过以后，但仍是本轮 R2 的独立交付项。

求得的策略只属于固定输入范围、下注树和后续价值模型定义的博弈，不宣称是无限动作空间下的完整扑克 GTO。给定翻后输入范围不能反推出唯一翻前均衡范围；真实翻前范围与行动必须由 R3 的相应模型求得，或导入有权使用且有固定来源的真实解。

| 能力 | 当前真实状态 | 计划 |
|---|---|---|
| HU 翻前 | 未验证、未接入 | R3-A；不由翻后引擎推定支持 |
| HU 翻后 | 受限河牌独立验证通过；产品未接入，一般树/扩街未验 | R1→R2 河牌→转牌→翻牌 |
| 六人翻前 | 未验证、未接入 | R3-B；单独候选、模型和质量定义 |
| 六人背景的单挑翻后 | 未验证、未接入 | R2-F；先声明给定范围的两人局部模型 |
| 多人翻后 | 未验证、未接入 | R3-C；没有合格候选时保持不支持 |
| 花色同构预解库 | 仅讨论与本次设计 | R2-I；在真实原解和查询验收后 |

R1 未通过时可以提交“候选不采用”的可复现结论；不能把失败包装成 R2 已完成。R3 可以先取得研究结论，完整六人均衡不设没有依据的工期承诺。

## 3. R1：引擎与模型验证

主候选仍为 b-inary/postflop-solver 固定提交 `9d1509fe5077d019825f833eed04b16d342dfda1`；TexasSolver 为备选。采用是待验证决定。源码来源与许可见 [代码库方案](solver-real-codebase-design.md)。

| 子任务 | 工作与交付 | 依赖 / 完成条件 |
|---|---|---|
| R1-A 环境和来源 | 固定提交、依赖锁、实际 Rust/MSVC 工具链；记录 feature、补丁、许可、OS/CPU/RAM/线程；构建原生示例 | 不改内核；成功编译仅通过本项，不通过 R1 |
| R1-B 河牌语义 | 原生驱动跑固定小树；记录完整输入、展开树、组合/动作索引、金额/EV 定义、范围和死牌；保存原始输出及哈希 | 组合双向映射和 ledger 对照通过；无抽水，关闭隐式合并/额外全下或显式取得预检确认 |
| R1-C 独立数值核验 | 独立枚举河牌终局 payoff，构造微型有限博弈并用独立 LP/枚举最佳响应核验策略；核验引擎质量指标的定义与换算 | 预先冻结测试输入、评价分布、阈值；核验代码不调用待测引擎的评估器/BR；同源一致另记 |
| R1-D 采用结论 | 确定支持边界，测试锁定/序列化/step 生命周期；记录耗时、峰值内存和取消观测；产出采用或拒绝报告 | A/B/C 证据齐备；不把未测特性列为已支持 |

R1-C 首版门槛：单线程、不压缩基准；概率非负且可达组合每列频率和误差≤1e-5；独立终局 EV 差≤1e-5 bb；微型河牌树独立 NashConv≤1e-3×根底池，且双方 EV 与独立解差≤1e-3×根底池。NashConv 是双方单边最佳响应增益之和，不与 exploitability 名称直接互换；存在不同最优混合策略时按价值和最佳响应检查，不要求逐组合策略一致。预先设置最多 100,000 次迭代、10 分钟、2 GiB 进程预算；达不到则记录失败，调整模型或阈值必须另版并保留原结果。四个受限河牌样本已按原门槛独立通过；一个样本未满足更严格的引擎停止目标，两项事实分别记录，不外推其他能力。

## 4. R2：薄适配与完整产品交付

| 子任务 | 工作与交付 | 完成条件 |
|---|---|---|
| R2-A 合同与边界 | 真实/Mock 判别联合类型、分析目的、支持矩阵、严格逐工具 schema、引擎 IPC v1；抽离现有 service 的引擎调度边界 | 旧解不改义；不支持输入有字段级原因；UI/MCP 调用同一预检 |
| R2-B 河牌最小闭环 | Rust sidecar 依赖完整引擎；映射范围/树、执行 step、投影查询；Node 发布固定解；UI/MCP 发起并浏览 | 非 fixture 自定义输入真实改变结果；原生/适配一致并另过 R1 独立基准；全范围、Hero、派生范围有真实来源 |
| R2-C 运行与恢复 | 资源预检、单计算槽、进度、取消确认、强制中断、幂等重试；原生解与索引原子发布 | 浏览器刷新不断算；进程崩溃不发布半解；未验证 checkpoint 不提供续算；重试保留新 attempt |
| R2-D 转牌 | 新增机会节点、全部合法 river、花色映射、独立小范围 runout 枚举；真实资源基线 | 机会概率和条件范围正确；新增独立基准；能力单独发布，河牌回归通过 |
| R2-E 翻牌 | 多街树、转牌与河牌路径、按需加载/查询、查询游标隔离 | 至少不同花色结构和不对称范围验证；完整制品不入快照；无预算依据不开放任意大树 |
| R2-F 策略与六人来源 | 固定双方策略评价；单方固定策略对另一方 BR；部分 nodelock 再求解；六人路径携带范围、账本和来源进入两人子游戏 | 三种分析目的分别声明；比较资格核对评价分布、树/单位和目标；弃牌相关信息缺失显式声明，不能声称整体六人均衡 |
| R2-G 集成交付 | 实跑六条真实旅程及异常；教学固定引用和暴露保护；提供能力表、报告、复现命令、限制和基线 | 每份证据含实际执行版本/输入哈希；所有开放能力通过对应测试，不以 Mock 旧证据替代 |
| R2-I 同构预解库 | 全问题花色规范化、不可变解目录、精确匹配、逆映射、质量筛选和预算预计算 | 在 B/C 后开始；转牌/翻牌按 D/E 逐级解锁；验证全部 24 置换、破坏对称的范围/锁定/死牌及失配拒绝 |

建议执行顺序：R1-A→B→C→D→R2-A→B→C→D→E→F→G。R2-I 从河牌真实解稳定后插入，不阻塞基础真实能力。各项是工程检查点，不是重复请求用户启动的审批节点。

第一条交付以 R1＋R2-A/B/C 为批次：用户可以用新输入真实求解河牌、双入口浏览/保存/恢复，并看到明确的计算质量。其后连续扩街，不把河牌完成写成 R2 整体完成。

## 5. R3：翻前与六人专项

| 子任务 | 必须回答的问题 | 可交付结论 |
|---|---|---|
| R3-A HU 翻前 | 完整引擎候选、开源许可、下注树、翻后终局/价值近似、抽水、资源、独立基准是什么？ | 限定模型的可复现真实解或不采用；不是把翻后引擎起始牌面设为空 |
| R3-B 六人翻前 | 多人策略求解算法和质量含义、按位树、联合发牌相关、弃牌条件、后续价值及误差如何定义？ | 输入范围可导出且有来源；整体解/局部解/近似分别标记；未验证模型不得发布 GTO 范围 |
| R3-C 多人翻后 | 是否有可复用完整实现及可检查的质量指标？取消和内存是否可控？ | 独立支持声明；没有合格依据则明确不支持，不延用两人零和保证 |

OpenSpiel 可研究小博弈/最佳响应验证；PokerKit 可研究账本和终局独立校验。两者均不预先认定为六人深筹码完整引擎。候选进入实验前同样固定版本与许可；本轮没有为这些项目新增“已验证复用”记录。

## 6. 必须实跑的真实旅程

1. HU：配置新的范围和树→真实求解/加载固定解→Hero 与全范围→沿行动浏览真实派生范围→保存后重新加载。
2. 六人背景：选择有固定来源的翻前路径→携带范围、账本、相关性模型→两人翻后求解；结果明确其局部性质。翻前若仍是 Mock 必须全程标注，不能成为“真实六人链路”证据。
3. 实验：固定用户策略→选择评价目的与分布→评价→新建锁定变体→检查比较资格→保存可追溯结论；不兼容比较明确拒绝。
4. UI→实际 MCP 客户端查询和修改→UI 接手；反向也成立。检查并发旧版本、重复请求及固定结果引用。
5. 教学：固定首次作答→请求真实分析证据→有来源反馈→改变相关条件的新题。数值由 Solver 提供，错因由评价模块决定，学习安排由教学 Agent 决定。
6. 异常：不支持输入、取消迟到、浏览器刷新、业务服务重启、worker 被终止、重复请求、损坏制品/导入、旧版迁移都有可复现结果。
