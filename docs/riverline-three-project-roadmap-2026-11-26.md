# 练习、研究与 Bot 三项目开发路线 v0.1

日期：2026-11-26（Asia/Shanghai）。状态：**规划完成，尚未实施本路线的新开发**。依据：用户希望按三个模块项目推进，并要求规划研究、练习位置及 Bot 能力的后续开发。当前应用基线为 `2a54c5c`；已交付内容见[第二轮交付](riverline-round2-delivery-2026-11-26.md)。

配套：[模块合同](riverline-three-project-contracts-2026-11-26.md)、[下一轮任务与验收](riverline-next-round-task-design-2026-11-26.md)。保留既有 U00–U08、R1–R3、N00–N08编号：本路线组织剩余工作，不重做已交付批次，也不把设计记成实现。三个研发项目不等于三个新页面、三个数据库写入口或三个立即部署的微服务。

## 1. 产品完成目标

面向学习者，完整完成：**连续整手练习 → 定位不确定决策 → 在明确假设下深入研究 → 保存证据和结论 → 配置同目标整手训练 → 检查问题是否重复出现**。

现有练习/复盘/研究三个主入口与明亮风格保留。研发归属改为：练习项目拥有复盘与学习会话，研究项目拥有 Solver 和研究证据，Bot 项目拥有策略与对手能力。Bot 选择是练习设置；Bot 实验室先作为开发工具，不新增一级产品入口。

用户提到的“练习的位置”同时按两层处理：产品定位是整手练习/复盘的承载者；实际牌桌则需要修正物理座位、按钮、扑克位置与 Hero 显示位置的建模和控制。

## 3. 三项目职责与工程形态

| 项目 | 负责与拥有的数据 | 不应承担 |
|---|---|---|
| Practice（练习/复盘） | 规则进程的调用、Session/HandRecord/DecisionSnapshot、位置和座位、动作/表现帧、Attempt/Exposure、练习计划执行 | 求解算法；把Bot理由当评分；自行重写规则或接受Bot直接改牌局 |
| Research（研究/Solver） | StudyCase、范围/树/策略版本、AnalysisSpec/Job/Solution、对照与Finding、训练定义中的研究依据 | 对在线练习掌握两套牌局真值；从未知范围推定整手GTO；隐式改写原手 |
| Bot（HU与六人策略） | BotManifest、版本化策略/风格、每个玩家的会话记忆、决策/预算、离线评测和候选发行包 | 发牌/结算、写用户练习库、获得其他玩家私牌、给自己策略颁发Solver真值 |

共用卡牌、整数金额、规则版本、座位映射、公开事件、来源引用与错误语义。共享内容优先是小型版本化合同和黄金样例，不先建设第四套大型“公共业务平台”。

初期工程形态：

- `E:\poker_coach`继续承载产品壳、练习与研究；先形成独立模块/应用服务入口和依赖边界，保持一个用户可运行产品。
- `E:\hu bot`继续独立演进策略。通过固定版本发行目录/包及适配器接入，不直接导入会变化的`.work`源码，不覆盖根`submission/`或冻结候选。
- 研究先在本仓库拆为独立应用边界和可测试消费者。固定来源、备份、鉴权/暴露与资源合同稳定后，再决定是否迁为单独仓库；本轮不预设新远程仓库。
- Node仍作产品协调入口；Python Bot/规则、Rust Solver通过受控进程运行。Bot快决策与Solver长作业使用独立资源队列，避免一个大解堵住练习。
- 产品事实各有唯一所有者；本地统一入口不要求把所有模块重新合成一个大类，也不要求所有模块直接访问同一个DB。

## 4. 目标可能冲突的地方

| 冲突 | 必须采用的规则 |
|---|---|
| 竞技Bot希望赢，教学希望暴露特定问题 | 分竞技策略与训练风格；训练对手有可测行为和来源，难度不等于GTO等级。脚本对手/定向样本清楚命名 |
| 研究可看完整结果，独立练习要保护答案 | Practice统一暴露/作答身份；查询研究前登记受影响答案事实。原独立作答不可覆盖，已见重打不算新题 |
| Solver策略是给定模型，Bot面对完整自由牌局 | 只在同规则/范围/节点/动作树匹配时评价；树外行动保存原额，不吸附到最近下注，不借局部EV给整手总分 |
| 六人牌局最后剩两人，HU接口刚好可用 | 背景人数、弃牌/死钱、位置与输入范围仍保留；HU原生策略或解只有显式支持六人来源局部模型后才能使用 |
| Bot估计对手范围，研究需要明确输入 | 估计带版本/观察/不确定度，作为假设导入；不因Bot知道自己私牌或使用人工表就当观测真值 |
| 三个项目进度不同 | 通过版本化发行和能力清单接入。练习可继续合法打牌，研究未覆盖仍保存问题；未接入的能力不出现假数值 |

## 5. 练习路线 P

### P01 位置、座位与会话（首批）

区分`playerId / physicalSeat / dealerSeat / ruleSeat / position / displaySlot`。Hero视觉位置固定；按钮和扑克位置随会话轮转，其他玩家身份稳定。规则helper若仍按固定盲注座位工作，由可逆映射连接，不能只换前端标签。

提供轮转、指定位置、随机位置三种练习设置；指定位置属于定向抽样，不冒充自然整场轮转。会话拥有自己的handIndex，跨HU/六人切换不再由全局手数决定位置。首批保持100BB重置模式，随后增加50/100/200BB与连续筹码模式，分别验证保存/规则/备份，不只新增下拉框。

HU验证BTN/SB翻前先行、翻后BB先行；六人验证UTG翻前、翻后按按钮方向跳过弃牌/全下者。牌桌采用清晰2D座位布局、D/SB/BB标志、当前动作和投入；手机提供可读紧凑布局，无3D前置。

### P02 问题账本与复盘（首批）

标记关联当时位置、行动线、对手/策略版本与行动前快照。可按位置/街道/底池类型筛选；先统计“疑问重复出现”，有研究证据后再升级为错误类别。不以输赢、思考时间或单次标记判断打错。

### P03 可恢复的逐行动运行（后续批）

接入较慢Bot后，不能在整批对手循环中等待数秒且只在末尾保存。Hero行动先提交，持久化`awaiting-opponent`，异步请求当前Bot，按同手/版本/token校验后提交一次动作，再安排下一个。每次变更都有可读取公共帧；任何事务不跨进程等待。

现有最新批次帧查询不能直接承受持续推进：需增加有限保留、固定事件区间的批次/游标，在当前手权限下按区间重放；新手开始后的旧亮牌限制保持。恢复时已提交动作不重算，未完成Bot请求按原配置新attempt，迟到结果不能覆盖新状态。

### P04 同目标整手训练与反馈（后续批）

研究可产出问题目标、已见重打与初始条件。整手仍从翻前合法进行，用户选择使目标节点未到达时记录“未到达”，不强制改变动作以制造教学路线。局部题作为明确补充模式。

首次独立作答、辅助后修订、已见复练和独立迁移分别记录。合法重放作为基础；自动战略评分只开放有同模型证据的节点。反馈同时显示评价覆盖，不能把缺失当零或把各街局部损失简单相加。

## 6. 研究路线 S（承接 U03/04/05、R2-D/E/F/G/I 与 R3）

### S01 正常范围容量与查询（最高优先）

先测真实范围/树/资源矩阵，再开放新能力profile。转牌16组合只是微型能力；下一轮以每方128个正组合的混权转牌输入作为拟验收目标，河牌保留并覆盖200组合。不是把16改为128就宣布完成。

必须同时处理当前reader全节点数组/16组合schema、128KiB传输限制、机会概率随组合数增长的计算、Node页/矩阵摘要、LRU和原生解大小。新增版本化分页reader与聚合，旧`native-turn/3`保持可读。完整输入不静默剪裁，不将部分范围归一化后标作原输入结果。

冻结至少16/32/64/128/200组合、重叠与非对称权重、不同深度/尺寸的采样矩阵。内存/耗时、取消、查询与练习负载一起测；未达到128目标就报告容量门未过，交付实际已验证profile，不能写“专业转牌完成”。全范围与任意大树继续单独验收。128不是长期产品上限：后续以有来源的常见实战范围（包括数百至上千合法组合的宽跟注范围）验证可计算profile或精确预解覆盖；达不到时保持未覆盖，不能为了凑入上限剪掉范围。M3/M4的深度研究验收须记录这些实际范围覆盖，而不只再演示微型案例。

### S02 研究操作与可读性（首批→第二批）

保存同一解最后浏览的类型化路径/玩家/牌类/观察组合；恢复先核对固定解与合法路径。输入与结果板面明确区分，选择river不改根输入。侧栏可收起，结果主区稳定。

常用树提供图形尺寸/行动编辑与明确预览，高级文本保留。转牌从当前单尺寸模型扩为显式多尺寸/加注须先完成数值门，不只修改编辑器。按同一输入比较后续牌的范围、策略和EV，显示条件概率与所处收益原点；不把不同条件范围的平均值当无条件效应。

### S03 固定策略、BR与对照（第二批优先从河牌）

分别提供固定双方策略求值、对指定固定对手的最佳响应、部分锁定后再求解。锁定模型的受约束质量与原博弈可利用性分列。基准/变体保存唯一变化项和无法保持相同的其他条件。

先做已验证河牌模型，给Bot离线审计提供可靠切片；无需等待完整翻牌。Bot完整策略若没有逐信息集/组合分布，单次采样行动不能伪装成完整固定策略。给定范围的局部动作价值也不自动成为赛事输赢证明。

### S04 Finding与训练交接（第二批）

研究结论固定：问题、事实/假设、输入/解、比较条件、观察、解释、适用条件及反例。支持“仍不确定”，保存文本不自动成为数值证据。从结论生成TrainingProposal，由Practice补齐并固定训练定义、创建计划/Attempt；研究不写练习库。

### S05 转牌多尺寸与翻牌（第三批）

沿用固定完整引擎和薄适配。先在微型博弈独立验证每个新增树语义，再资源profile与产品开放。翻牌跨两次发牌、条件范围与收益原点须单独核验；不能独立求每张后续牌再平均冒充前街策略。保留原河牌/转牌数值门。

### S06 预解、翻前与多人（第四批/长期）

先构建项目有权持有、可复现的小型真解库，按完整规格/质量精确命中；花色同构需变换整个问题并验证逆映射。HU翻前、六人翻前和多人翻后继续R3分别立证据门，不以Bot表或HU引擎填空。常用已验证任务可以快速加载，不承诺任意自定义输入即时返回。

## 7. Bot路线 B

### B01 可替换运行接口（首批）

抽出当前启发式作为`baseline-heuristic`固定版本。请求只含当前玩家私牌、公开历史/牌面/筹码、权威合法行动、规则与预算；不传deck/他人私牌/未来/答案。返回候选行动、版本、状态和可选只读诊断；Practice校验执行。

先适配固定HU候选，保留ChipZen适配器；练习适配器与平台适配器调用相同策略核心。候选按实验身份展示，不能因为版本新就默认更强或替换用户确认的平台版本。先单独验证当前合法动作/金额、完整手、超时/退出/重启/迟到和复现，随后再做策略增量。

### B02 HU高频策略质量（第二批）

参考Bot项目已冻结的范围与反例，一轮聚焦一个高到达率节点族，例如BTN首入及limp后iso防守、BB对常见open，或实际价格下的3-bet响应。记录深度/价格/输入范围/动作树/对手模型；对照正常、宽跟、被动、积极iso/3-bet以及反向画像。

先确定默认行为和合法可达性，再做在已验证模型内的条件行动价值及下行；保留未知/负结果。用冻结策略、相同发牌、换座成对对照，按独立session统计，避免把跨手学习当独立样本。工程通过、局部行为、局部价值、总体强度、打包和平台上传分开，不设无依据的胜率承诺。

### B03 六人独立基线（第二批）

至少支持UTG/HJ/CO/BTN/SB/BB首入、面对open、limp/iso、squeeze、3/4-bet、短全下重开、multiway与边池。早位/晚位、面对价格、活跃人数、是否闭合行动、SPR和行动线进入策略；不能继续只看私牌点数。

先提供合法、可解释、行为一致的6-max训练基线及版本化tight/passive/aggressive画像，标为启发式。HU与6-max共用进程/预算接口，分别使用策略与能力声明；六人剩两人不自动调用只支持原生HU的模型。多名Bot不共享隐藏牌或私有记忆；相同策略版本不意味着串通。

### B04 风格与难度（第三批）

风格按位置/节点机会的open、3-bet、面对下注继续/加注与尺寸分布验证，不以随机噪声充当难度。目标训练对手与竞技对手分开。预设里只展示有行为证据的差异；“高阶”必须带真实能力解释，不写假ELO/GTO百分比。
